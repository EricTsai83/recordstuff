## 目標

RecordStuff 會在有新版時告知使用者並帶他到下載頁，過程中沒有背景輪詢、遙測、靜默安裝，也不需要新的簽章身分。實際安裝仍是手動下載並替換，直到取得 Developer ID 才談自動安裝。

## 已做的決策（015 比較的結論）

| 選項 | 決策 | 理由 |
| --- | --- | --- |
| 只維持手動下載 | 不採用 | 使用者無從得知有新版；發布流程本來就會產出可供 App 讀取的已驗 metadata。 |
| 使用者主動檢查 ＋ 啟動時檢查，並連到下載頁 | **採用** | 只用一次對靜態檔的 HTTPS 請求就拿到全部價值（知道有新版）。不引入 updater 相依、不改安裝方式、不在 `/Applications` 內製造新的失敗模式。 |
| 完整自動更新器（下載、安裝、重啟） | 延後，未排程 | 透過 `electron-updater` 的 Squirrel.Mac 需要 Developer ID 簽章並公證。RecordStuff 使用固定自簽身分，Apple 認證維持範圍外（[發布](../docs/zh-TW/system-design/releases.md)）；自動安裝的版本重啟時會被 Gatekeeper 擋下，還可能在 `/Applications` 留下壞掉的 App。取得 Developer ID 後再以另一份計畫處理。 |

## 階段 1. 版本 feed

1. 由網站建置輸出穩定的 feed 路徑 `/{site}/release.json`，內容來自已驗證的 `website/release-manifest.json`，包含版本、tag、DMG 檔名、大小、SHA-256、發布日期、release 頁與網站下載頁連結。不新增後端，就是隨網站部署的靜態檔。
2. feed 的快取時間要短，且絕不能宣告 manifest 未對已發布產物驗證過的版本（現有 manifest 規則已強制這點）。
3. 網站無法連線時的備援：改查 GitHub releases API。檢查失敗必須視為「未知」，不得當成「已是最新」。
4. 網站測試：建置輸出含 `release.json`，且版本與 manifest 一致。

## 階段 2. App 內的檢查

1. Tray 選單項目 **Check for updates…**（雙語，沿用既有選單字串）：執行一次請求、自行回報結果，檢查進行中時停用。
2. 啟動時檢查，每 24 小時最多一次，並提供可關閉的偏好設定（`Check for updates on launch`）。執行期間不做計時輪詢，不送任何識別資訊或可辨識安裝來源的查詢參數。
3. 錄影安全：錄影進行中不啟動檢查、不跳對話框、不改 tray 標題，延到下次機會再處理。
4. 比較規則：以語意化版本與 `app.getVersion()` 比較；忽略相同或較舊版本、預覽版，以及平台／架構不符的項目。
5. 失敗處理：啟動檢查失敗只寫日誌不打擾使用者；手動檢查則明確說明失敗並提供 releases 頁。逾時有上限，且關閉 App 時可取消。

## 階段 3. 使用者看到什麼

1. 選單狀態：閒置（`Check for updates…`）、檢查中、已是最新（顯示上次成功檢查的本機時間）、`Update available: X.Y.Z`（點擊以瀏覽器開啟下載頁）。
2. 除非維護者另有要求，不新增通知類型：入口就是 tray 選單。更新項目不得把錄影控制項擠離選單最上方。
3. 隨此功能一起要改的文案：移除網站說明頁、雙語 README 與雙語安裝指南中「不會檢查更新」的敘述，並更新目前斷言發行說明含 `no automatic updater` 的 `scripts/release.test.ts`。

## 階段 4. 驗證

1. 單元測試：版本比較（較新、相同、較舊、預覽版、格式錯誤）、feed 缺欄位、HTTP 錯誤、逾時、架構不符、偏好關閉、錄影中、檢查途中關閉 App。
2. 已安裝版本的本機驗收：舊版對上提供新版的 feed 時顯示更新項目並開啟正確下載頁；同一流程在錄影中不出現任何更新 UI，直到錄影結束；離線時選單不變並寫入日誌。
3. 在[驗證紀錄](../docs/zh-TW/verification/README.md)寫下實際測到什麼、以及沒測到什麼：真實使用者從已發布舊版升級到新版，要等到真的有新版發布才算證明。

## 邊界

不引入 `electron-updater` 或其他 updater 相依、不自動下載 DMG、不靜默安裝、不做背景輪詢、不加遙測、不申請新簽章身分，也不改變安裝方式。本計畫不授權由 App 自行替換已安裝的程式。

## 完成條件

Tray 具備可用的手動檢查與可選的啟動檢查、對上已發布的 feed；測試涵蓋失敗路徑；本機驗收結果寫入驗證紀錄；文件不再宣稱 App 無法檢查更新。之後移除本計畫及其翻譯。
