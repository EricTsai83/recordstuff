# 099 — 分享錄影：預設給對的檔案，其他版本要刻意選

[English](099-share-recordings.md) | [繁體中文](099-share-recordings.zh-TW.md)

狀態：已規劃，尚未開始；決定 D1–D8 已於 2026-10-28 回答。建立：2026-10-28，依維護者要求；同日依維護者的檢視改寫為以使用體驗為主。硬性相依：無未完成項目。建立在已結案的 085（剪輯錄影、匯出與發布）、087 與 098（可編輯錄影與其音軌）以及 071（錄影分頁）之上。依[計畫索引](README.zh-TW.md)的順序執行。本任務只寫計畫，以下內容都尚未實作、量測或決定。

維護者的要求（2026-10-28）：設計最好的體驗，不追求改動最小；使用者不知道什麼是音軌，只會把錄好的東西直接拖給別人；也有人需要素材、成品，或兩者都要；要想清楚一段錄影的各種版本怎麼分享、怎麼管理、畫面上怎麼呈現。把所有錄影都改成可編輯錄影不在範圍內（維護者，2026-10-28）。

## 現在的問題

錄影離開 RecordStuff 的每條路都交出**原始檔**：從錄影分頁把卡片拖出去（[main](../src/main/index.ts) 的 `startDrag`）、「在 Finder 中顯示」，以及會打開 Finder 的存檔通知。沒剪過的一般錄影這樣是對的；其他情況都沒有任何提醒，使用者不知道自己給出去的是什麼：

| 分享的是 | 對方拿到的 | 風險 |
| --- | --- | --- |
| 剪過的一般錄影（085） | 全部片段，包括移除的：剪輯存在 `userData` 的剪輯紀錄，從不寫進檔案 | **高**：隱私，使用者以為已經刪掉 |
| 編輯過的可編輯錄影 | 錄影當時的樣子：移除的片段、靜音的區段、隱藏的相機都還在 | **高**：隱私 |
| 沒編輯的可編輯錄影 | 沒有相機泡泡的螢幕畫面（相機是停用的軌） | 高：不是使用者想給的 |
| 任何可編輯錄影 | 用 VLC 或 ffmpeg 就能抽出麥克風與完整相機畫面 | 中 |
| 任何可編輯錄影 | 一般錄影的兩倍大；剪輯不會跟著過去 | 低，但令人意外 |

這些情況下，匯出檔 `<name> (edited).mp4` 才是對的檔案，但它是「獨立的一段錄影，沒有連回來源」（[剪輯](../docs/zh-TW/system-design/editing.md)）：使用者得知道要選另一張卡片，而它也可能比最新的剪輯舊。

## 一段錄影是什麼（本計畫採用的模型）

一段錄影只有三樣東西，其中只有兩樣是檔案：

| | 是什麼 | 檔案 |
| --- | --- | --- |
| **原始檔** | 錄影當時的樣子，從不寫入（085 的規則） | 一個 |
| **編輯** | 一種狀態：剪輯紀錄（剪掉哪裡、泡泡位置、音量、時段）。app 顯示的「編輯後」是照它即時播放出來的 | 沒有 |
| **儲存的副本** | 使用者要求時，照原始檔＋編輯、以選定的形式算出的檔案 | 零到多個 |

使用者拖出或分享的是一個**版本**：在那一刻從原始檔＋編輯產生的東西。版本不是 app 保存、管理的檔案，而是在離開時才在 app 自己的快取裡做成檔案。所以沒有任何衍生物需要和原始檔保持連結，也不會過期，使用者從來不用管理衍生檔案。

兩種錄影存放輸入的方式不同，所以版本也不同：

| | 一般錄影 | 可編輯錄影 |
| --- | --- | --- |
| 相機 | 錄影當下合成進螢幕畫面，之後拿不出來 | 另存一條軌；螢幕畫面裡沒有泡泡 |
| 麥克風 | 錄影當下和系統聲音混成一條 | 兩者的混音（自 098 起，就是播放器播放的那條），另外每個輸入各一條 |
| 一般播放器看到的 | 有泡泡的螢幕、兩個聲音 | 沒有泡泡的螢幕、兩個聲音 |

## 業界的做法

沒有單一標準，但大家熟悉的 app 收斂成五種模式，本計畫照著做。

1. **非破壞性編輯：原始檔加一份做法，輸出時才算繪。** 「照片」保留原始檔，編輯存成修改紀錄；看到的是修改後的版本，「匯出未修改的原始檔」才給匯入時的檔案（[Macworld](https://www.macworld.com/article/232763/how-to-get-the-best-image-export-from-photos-in-macos.html)）。Screen Studio、Camtasia 與 Final Cut 也都保留錄影或專案，匯出時再算繪（[Screen Studio，匯出](https://www.screen.studio/guide/exporting-the-video)）。
2. **分享預設給你看到的；原始檔是刻意的第二選擇。** 「照片」的「匯出 N 張照片」會套用編輯，未修改的原始檔是另一個指令。
3. **擷取後立刻出現的快速操作區**，不用打開任何東西就能拖、拷貝或儲存：macOS 的截圖縮圖、CleanShot X 的 Quick Access Overlay（可儲存、拷貝或把擷取拖進其他 app，[CleanShot](https://cleanshot.com/features)），以及 Screen Studio 錄完後的 Quick Share widget（分享、儲存、拷貝、編輯，[Screen Studio，Quick Share](https://www.screen.studio/guide/quick-share-widget-)）。
4. **輸出依用途命名，而不是技術選項。** Screen Studio 的「匯出成檔案」與「拷貝到剪貼簿」及其 preset，Final Cut 的分享目的地；技術設定放在下一層。
5. **來源和成品分得出來。** 專案型 app 讓來源有自己的文件類型（Screen Studio 專案、Camtasia 的 `.tscproj`），不會被誤當成要寄的東西。RecordStuff 的可編輯原始檔仍是任何播放器都能開的 MP4，這是它們都沒有的優點，所以這裡用檔名來區分（D3）。

## 設計原則

1. **預設離開的，就是使用者在 app 裡看到的。** 剪輯已套用、相機已合成、聲音已混好。
2. **剪掉的東西，沒要求就不會離開。** 隱私是預設。
3. **版本依用途命名。** 介面不出現「音軌」、「alternate」、「stem」，這些字留給文件。
4. **原始檔與素材只差一個刻意的步驟**，從不阻擋。
5. **沒剪過的一般錄影，行為和現在完全一樣。**
6. **每個拖曳都有點擊與鍵盤的替代方式**，並有 VoiceOver 名稱。
7. **使用者管理的是錄影，不是衍生檔案。** 衍生檔案在離開時產生，由 app 清理。

## 版本

| 版本 | 內容 | 提供給 | 離開時的檔名 |
| --- | --- | --- | --- |
| **影片**（預設，標示建議） | app 顯示的樣子：套用剪輯、相機在顯示的地方合成、一條畫面一條聲音 | 所有錄影 | `會議.mp4`（沒剪過的一般錄影就是原始檔本身） |
| **只有聲音** | 影片的聲音，已混好 | 所有錄影 | `會議.m4a` |
| **不含相機的影片** | 影片，但不放相機 | 有相機的可編輯錄影 | `會議（僅螢幕）.mp4` |
| **原始檔** | 錄影當時的檔案，含所有軌 | 編輯過或可編輯的錄影 | 可編輯：`會議.recordstuff.mp4`（D3）；一般：`會議（原始）.mp4` |
| **素材**（放在「更多」） | 每條軌各自一個檔案，不重新編碼，給 Premiere、Final Cut、DaVinci | 可編輯錄影 | 資料夾 `會議 素材/`，內含 `會議 - 螢幕.mp4`、`- 相機.mp4`、`- 系統聲音.m4a`、`- 麥克風.m4a`（只有錄影實際有的） |

**只有原始檔做標記；離開的東西都以成品命名。** 專案型的錄影與剪輯軟體都這樣命名：Screen Studio 與 Camtasia 讓來源有自己的文件類型，匯出檔以專案命名；Shotcut 等開源剪輯軟體也以專案名稱匯出（[Shotcut 論壇](https://forum.shotcut.org/t/batch-export-multiple-projects-automatically/11740)）；「照片」匯出編輯後的照片時用原本的名稱，未修改的原始檔是另一個指令。收到的人在乎檔案裝什麼，不在乎有沒有剪過，「已編輯」反而讓人問改了什麼。所以：

- 版本以錄影命名，跟隨 app 的語言（英文為 `Meeting.mp4`），只有和預設形式不同時才加內容標示：`（僅螢幕）`，聲音則用 `.m4a`。
- 可編輯原始檔叫 `會議.recordstuff.mp4`，從存檔起就是這個名稱，離開時也一樣（D3）。剪過的一般錄影，刻意交出原始檔時叫 `會議（原始）.mp4`；它在磁碟上的名稱不變。
- **儲存在自己來源旁邊**的副本會和來源同名。只有這時才標示「已編輯」，就像 iPhone 把編輯過的照片和原始檔一起傳出時命名為 `IMG_E…`（[MacRumors](https://forums.macrumors.com/threads/question-on-iphone-16-pro-max-camera-image-files.2478196/)）：存進一般錄影 `會議.mp4` 所在資料夾的副本叫 `會議（已編輯）.mp4`，卡片也依檔案內的來源資訊顯示「從『會議』儲存」（D8）。可編輯錄影不會遇到這種情況，因為它的來源是 `會議.recordstuff.mp4`。
- 落點已有其他同名檔案時加數字（`會議 2.mp4`）。不使用 V1、V2 這類版本號：收到 V2 的人會問 V1 在哪、差在哪。在 app 裡，錄影改以時間與形式列出它的副本（D4）。

使用者只需要記住一條規則：**有標記的是原始檔，其他都可以直接給人。**

「不含相機的影片」只出現在可編輯錄影，因為只有它的相機能拿掉；一般錄影的相機已經是畫面的一部分。

## 畫面上怎麼分享

### 1. 拖卡片（大多數人走的路）

**拖出去的是「影片」：卡片播放的樣子就是離開的樣子。** 按住 ⌥ 拖曳則是「原始檔」。沒剪過的一般錄影，影片就是原始檔，所以什麼都沒變。

拖曳開始的那一刻檔案就必須存在（macOS 的限制），而編輯過或可編輯錄影的影片必須算繪（參考機約即時的 6.3 倍：10 分鐘的錄影約 1.5 分鐘）。所以影片要**事先準備**進快取（D2）：剪輯畫面關閉時，以及可編輯錄影存檔時。還沒好之前，卡片畫面上顯示「正在準備影片… 40%」，拖曳不會開始，並說明原因及按住 ⌥ 可拖原始檔（D1）。macOS 原生的 file promise（先開始拖，放下時才寫檔）可以省掉等待，但需要原生模組，而瀏覽器裡的 Slack、Gmail 等網頁 app 不接受；它是之後的選項，不在本計畫內。

### 2. 分享…（刻意選擇任何版本）

「**分享…**」放在卡片選單、卡片的滑過動作與剪輯畫面的工具列。按下後，一層 overlay 覆蓋卡片畫面，上面每個方塊是上表的一個版本（維護者的方向）：

- 每個方塊顯示版本名稱與將產生的檔名；**拖出去**就是給那個檔案，**點擊**則有「拷貝」、「存到…」與「分享」（macOS 分享選單：AirDrop、訊息、郵件）。
- 第一個方塊「影片」標示建議。「素材」放在「**更多**」裡。
- 還沒好的方塊顯示進度；打開「分享」是明確的意圖，所以會開始準備所有還沒好的版本。
- 同時拖多個方塊可一次給多個檔案（`startDrag` 支援 `files`），涵蓋「成品＋原始檔或素材一起給」。
- Esc、✕ 或點外面關閉。Tab 在方塊間移動，Return 開啟方塊的動作。
- 格狀版面的卡片至少 272 px 寬（畫面約 272 × 153），放得下三個方塊加「更多」。清單版面的畫面太小，同樣的方塊改為從卡片彈出的 popover。

### 3. 錄完立刻出現的快速縮圖（D6）

錄影存好時，螢幕角落出現縮圖幾秒，就像 macOS 截圖縮圖與 CleanShot 的 overlay：拖它就是給「影片」，點它在錄影分頁打開這段錄影，滑過時有「分享…」、「編輯」與「在 Finder 中顯示」。一般錄影本來就是一條合成好的畫面加一條混好的聲音，所以縮圖可以立刻拖。可編輯錄影的影片在存檔的那一刻就開始算繪（D2），參考機約即時的 6.3 倍（1 分鐘的錄影約 10 秒，10 分鐘約 1.5 分鐘）：縮圖顯示進度，算繪期間與完成後幾秒都會留著，也可以關掉；完成前拖曳會和卡片一樣等待（D1）。它取代存檔通知「帶到檔案」的角色；關掉縮圖的人、螢幕正在分享或錄影時，仍保留通知。

### 4. 剪輯畫面

工具列的「**匯出**」改為「**分享…**」（同樣的方塊，針對目前的剪輯）與「**儲存副本…**」，詢問位置與形式：畫面（螢幕＋相機、只有螢幕、不要畫面）與聲音（混音），命名同上。選擇只影響新檔案：副本不放相機，不會刪掉原始檔的任何東西，原始檔的相機軌仍在，下一份副本還能用。

### 5. 卡片說明它是什麼

- 「**可編輯**」標記保留，tooltip 用白話：「畫面、相機和聲音分開保存，之後還能調整。要寄給別人，直接拖或用『分享』。」
- 「**已編輯**」標記保留。
- 影片準備中：畫面上的進度。拖曳給的是對的檔案時，不跳任何警告。

## 管理離開的東西

- **版本不需要管理。** 它們以「錄影、剪輯 revision、版本」為 key 做進快取，剪輯沒變就重複使用；剪輯改了，下次就重做。快取有容量上限（D5），先清最舊的，錄影不見了就清掉它的版本。拖出的檔案在磁碟允許時是快取檔案的硬連結，換上要送出的檔名，不用複製。
- **儲存的副本是使用者放的普通檔案。** RecordStuff 在每份副本中寫入它的來源（來源名稱與剪輯 revision，放在 `udta`，就像 `rsed` 描述可編輯檔），所以副本存進錄影資料夾時，即使在 Finder 改了名，錄影分頁仍能顯示「從『會議』儲存」。檔案以外不存任何連結，所以沒有要同步的東西。
- **錄影列出它在錄影資料夾中的副本**（D4）：錄影分頁依每個檔案內的來源資訊找到它們，錄影的選單依時間與形式列出，並提供「在 Finder 中顯示」。移出 RecordStuff 監看的資料夾或被刪掉的副本就不列出；不另外保存紀錄。
- **可編輯原始檔用檔名區分**：`會議.recordstuff.mp4`（D3），仍是任何播放器都能開的 MP4，但不會被當成要寄的影片。

## 不採用的做法

- **每次拖曳編輯過的錄影就跳警告：** 使用者會習慣按掉，而且會打斷拖曳。
- **把副本以儲存的連結歸在錄影卡片底下：** 每次改名、搬移、刪除都要同步，在 Finder 改名就斷掉。把來源寫在檔案裡就能有同樣的「從…儲存」，而沒有這些問題。
- **可編輯原始檔改用 `.recordstuff` 套件格式：** 放棄 087「任何播放器都能打開」。
- **檔名用版本號（V1、V2）：** 對收到的人說明不了內容。
- **每個離開的版本都加「已編輯」：** 標記的是成品而不是來源；收到的人不需要，還會引起疑問。只保留在副本和自己的來源放在一起時。
- **讓可編輯檔啟用的畫面改成合成畫面：** 錄影時要多一個編碼器，而且仍然沒有套用剪輯。
- **把剪輯寫回原始檔：** 違反 085 不寫入來源的規則。

## 決定（維護者 2026-10-28 回答）

- **D1 — 影片還沒好時拖卡片：等待。** 拖曳給的是「影片」，也就是卡片播放的樣子：沒剪過的一般錄影立刻給原始檔；剪過的一般錄影的剪輯結果，以及任何可編輯錄影套用剪輯與音量、合成相機的畫面，要算繪完成後才給。完成前不開始拖曳，卡片顯示進度，並說明按住 ⌥ 可拖原始檔。
- **D2 — 在剪輯畫面關閉時與可編輯錄影存檔時準備影片。**
- **D3 — 可編輯原始檔在存檔時命名為 `<name>.recordstuff.mp4`。** 用全名而不用 `rs`：多數人看不懂 `.rs`，開發者還會當成 Rust 程式檔，而 `recordstuff` 說明了用哪個 app 能再打開；副檔名仍是 `.mp4`，任何播放器都能開。
- **D4 — 錄影列出它在錄影資料夾中的副本**，依每個檔案內的來源資訊找到。移出監看資料夾或被刪掉的副本不列出；不另外保存紀錄。副本是「儲存副本…」（即現在的「匯出」）產生的檔案；編輯本身不產生檔案。
- **D5 — 快取最多佔 10 GB 與可用空間 10% 取較小者。**
- **D6 — 做快速縮圖並預設開啟**，可在設定中關閉；一般錄影的縮圖可以立刻拖，可編輯錄影的縮圖從存檔那一刻起顯示影片的算繪進度。
- **D7 — 素材是一個資料夾，音軌不重新編碼**（聲音為 AAC 的 `.m4a`）。
- **D8 — 存在一般錄影來源旁的副本叫 `<name>（已編輯）.mp4`**，即上面的命名規則。

## 步驟

- [ ] **0. 開始。** 檢查目前的程式、085 的發布與命名、087 與 098 的音軌、錄影分頁的卡片、拖曳、選單與通知，以及剪輯紀錄。D1–D8 已於 2026-10-28 回答。第一個桌面回合前依 [AGENTS.md](../AGENTS.md) 啟動 `caffeinate -d -i -t 5400`。
- [ ] **1. 版本與快取。** 把版本做成 shared 的模型（每段錄影提供哪些、兩種語言的檔名、撞名）；以錄影、剪輯 revision 與版本為 key 的快取、上限與清理；經由匯出 worker 算繪版本但不發布在錄影旁；以硬連結換上送出的檔名。在儲存的副本中寫入來源。每種錄影與剪輯狀態、檔名、快取的重用、過期與上限都有單元測試。
- [ ] **2. 卡片。** 拖曳給影片、⌥ 拖曳給原始檔、準備中的狀態（D1、D2）、tooltip；D3 對新可編輯錄影的命名。背景 UI 測試涵蓋各狀態、兩種語言與主題，只斷言行為與無障礙。
- [ ] **3. 分享…。** Overlay（格狀）與 popover（清單）、顯示名稱與檔名的方塊、拷貝、存到…與分享選單、「更多」、一次多個檔案、準備與取消、鍵盤與 VoiceOver。剪輯畫面的「分享…」與附形式選擇的「儲存副本…」；錄影的副本列表（D4）。
- [ ] **4. 快速縮圖**（D6）、它的時機，以及它和存檔通知如何分工。
- [ ] **5. 桌面回合。** 收到「好了」後，在全新的簽章 bundle 上：把每個版本拖到 Finder 視窗以及郵件草稿或聊天中，檢查收到的檔案（影片一條畫面一條聲音、套用剪輯、相機在顯示的地方；只有聲音能解碼；原始檔逐位元組相同；素材和錄影的軌一致）；各狀態下拖卡片與 ⌥ 拖曳；分享選單；縮圖；1、10、30 分鐘錄影的準備時間；快取上限。還原設定、關閉 app 並確認程序已結束。
- [ ] **6. 易用性檢查。** 以[剪輯畫面易用性 skill](../.agents/skills/edit-view-usability/SKILL.md) 的方法套用到分享：請第一次使用的人把錄影寄給同事，再把素材交給剪輯師，以 Computer Use 觀察；發現的問題修正或記錄。
- [ ] **7. 文件與結案。** [剪輯](../docs/zh-TW/system-design/editing.md)（版本、快取、來源）、[桌面](../docs/zh-TW/system-design/desktop.md)（卡片、分享…、縮圖）、[設計決策](../docs/zh-TW/system-design/decisions.md)（模型、拖曳規則、命名、不採用的做法）、README 對分享的說明、驗證紀錄、翻譯、移除本計畫並更新索引。

## 驗證

- 步驟 1–4：開發時以 `pnpm test:scope` 跑 library 與 editing 範圍；步驟 5 之前跑 `pnpm check`，因為匯出 worker、錄影分頁與 main 的發布都會改變。
- 步驟 5–6：以[原生驗收 skill](../.agents/skills/native-acceptance/SKILL.md) 跑桌面回合；拖曳會移動真正的游標，每輪都需要交接。共用 `out/` 與 `dist/` 的工作要排隊。
- 分開回報：自動化結果、拖了什麼到哪裡、收到什麼檔案、易用性回合看到什麼，以及沒驗證到的部分（Windows 沒有可編輯錄影，一般錄影的分享只由 CI 檢查；回合中沒有實際拖入的服務）。
