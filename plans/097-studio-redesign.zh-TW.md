# 097 — 重新設計錄影工作室：選擇在預覽上方，即時控制在下方

[English](097-studio-redesign.md) | [繁體中文](097-studio-redesign.zh-TW.md)

狀態：已規劃，尚未開始。建立：2026-10-27，依維護者要求。硬性相依：無未完成的項目。本計畫調整由已結案的 075（工作室、相機、即時預覽）、090（錄影中的相機狀態）、092（預覽速率與畫面）、094（相機畫面）與 095（工具列）建立的工作室，錄影分頁裡 074 與 079 的裝置列（麥克風裝置與輸入音量），以及可編輯錄影（087）在錄影中錄下的內容。依[計畫索引](README.zh-TW.md)的順序執行。本任務只撰寫計畫，下文所述內容都尚未實作或驗證。

## 目標與現況

維護者覺得工作室不好理解（2026-10-27）。起因是一張截圖：在「只看螢幕」畫面裡，相機已從錄影中隱藏，畫面上卻還有相機泡泡的虛線框，看起來像相機還在。

現況（[desktop：錄影工作室](../docs/zh-TW/system-design/desktop.md#錄影工作室)）：

- **相機有兩個開關，意思幾乎一樣。** 工作室相機面板的相機開關（`studioCamera`，跟錄影設定和托盤的 `camera` 是同一個設定）在錄影中會鎖住。工具列的人像按鈕（`cameraShown`，075 的 D13）只在錄影合成相機時出現。對使用者來說，兩個都在回答「成品裡有沒有相機」。
- **預覽有三種畫面，其中一種很特別。** 錄影畫面、只看螢幕、只看相機（[studio-port.ts](../src/shared/studio-port.ts) 的 `STUDIO_VIEWS`）。「只看螢幕」把泡泡畫成可拖動的虛線框（[ui.css](../src/renderer/ui.css) 的 `[data-view="screen"]`），相機隱藏時也照畫，因為 [camera.ts](../src/main/settings/model/camera.ts) 的 `composed` 只看這場錄影有沒有相機。
- **泡泡有五種樣子。** 毛玻璃泡泡、虛線框、看不見但拖得動（相機隱藏時的錄影畫面）、不顯示、放大版（相機畫面）。使用者猜不出每一種代表什麼。
- **裝置選擇在別的頁面。** 螢幕、相機裝置、麥克風裝置只在錄影設定裡。工作室刻意不放（「每個控制只放一個地方」），所以使用者在工作室看到畫面不對、聽不到聲音時，得離開工作室才能修。
- **問題同時出現在好幾個地方。** 相機狀態是舞台上方的一行字（090）；麥克風或顯示器不見是錄影設定裡的列診斷；沒聲音則從來不會說：錄影之間音量條是靜止的，也沒有任何東西在注意麥克風是否完全沒收到聲音。
- **沒打開任何介面就開始錄。** 托盤和快捷鍵可以在工作室關著的時候開始錄影。這時除了托盤「錄影包含」的勾選，沒有任何地方說相機或麥克風是否正常。
- **錄影類型在別的地方選，工作室也不會跟著變。** 可編輯錄影（087，macOS，預設關閉）是錄影設定裡的開關；在 Windows 上這個開關顯示為無法使用，並寫著「可編輯錄影只支援 macOS。」托盤另有「開始可編輯錄影」可單次使用。工作室對兩種類型長得一樣，但在可編輯錄影裡，靜音、音量推桿和隱藏相機都會永久改到錄下的音軌（靜音的輸入在它的音軌裡是無聲、音量已套用在各音軌、隱藏時相機軌是黑畫面），而剪輯畫面其實可以事後設定這三項（[editing](../docs/zh-TW/system-design/editing.md)）。
- **靜音被誤會成監聽靜音。** 按鈕寫「Mute」，而靜音中輸入的音量條還會繼續跳（變灰，因為顯示的是靜音之前的音量）。使用者講話時看到音量條在動，可能以為有錄進去，其實沒有。

目標：一個工作室版面，把「要錄什麼」和「錄得怎麼樣」分開，而且各自一目了然；錄影中的控制符合錄影類型；泡泡只在成品看得到相機的地方出現；問題只說一次，就說在能修的地方；錄影分頁保留為檢查與測試裝置的地方。

## 需求（維護者，2026-10-27）

1. 工作室是使用者在錄影前和錄影中確認「錄的東西是對的」的地方。它顯示螢幕、相機、麥克風的狀態，錄到一半出問題也能立刻知道。
2. 保留大預覽。不需要靠展開或收合來騰出空間。
3. 選擇（哪個螢幕、哪台相機、哪支麥克風）放在預覽上方。即時、可調整或監控用的控制（音量條、音量、靜音、相機顯示或隱藏）放在預覽下方。
4. 錄影分頁保留螢幕、相機、麥克風的選擇，當作裝置檢查站：選裝置、看有沒有連上、測試能不能用。
5. 不用綠點、黃點。一切正常時控制項保持安靜；有問題時，由控制項本身說出問題。
6. 從托盤或快捷鍵開始錄影、工作室沒開時，使用者仍然會知道有問題，並被帶到工作室查看。
7. 工作室提供錄影類型的選擇（一般錄影或可編輯錄影），即時控制跟著類型變：一般錄影有靜音；可編輯錄影不需要。
8. 無法使用可編輯錄影的地方（Windows），使用者在選擇時就看得到，也知道原因，而不是發現選項不見了。

## 設計

2026-10-27 檢視過的樣稿在這裡用文字描述。最後的間距和樣式以正式的元件和設計 token 為準，不以樣稿為準。

### 每一列一個規則

| 列 | 放什麼 | 錄影中 |
| --- | --- | --- |
| **標題列** | 標題；預覽畫面選單；即時預覽；⋯ 裡的預覽速率 | 不變：這些只影響使用者看到什麼，不影響檔案 |
| **選擇列**（預覽上方） | 錄影按鈕；錄影類型；螢幕、相機、麥克風選擇器 | 類型、螢幕和相機鎖住並顯示鎖頭。麥克風照 079 的既有行為，仍可切換 |
| **預覽** | 畫面，泡泡直接在上面拖 | 不變 |
| **即時列**（預覽下方） | 依錄影類型而定（見下） | 顯示的項目全部仍可調整 |

移除：舞台下方的相機面板、預覽面板、音訊面板，以及工具列的人像按鈕。它們的控制移到上面幾列。側欄收合按鈕不變。

### 選擇器

- **螢幕**：照錄影設定的方式列出顯示器，加上「隱藏選單列和 Dock」。
- **相機**：選單最上面是開關，接著是裝置，再來是泡泡外觀（寬、高、圓角）和鏡像。外觀在錄影前決定，跟著選擇器一起鎖住。泡泡位置仍在預覽裡拖。
- **麥克風**：開關，接著是輸入裝置，包括系統預設和已選但未連接的裝置（074 的規則不變）。

裝置正常時，選擇器只顯示裝置名稱，沒有其他標示。

### 錄影類型，以及各自的即時列

選擇列最前面、錄影按鈕旁邊有一個選擇器：

- **一般錄影**：「錄完就能分享。」
- **可編輯錄影**：「錄完可以在剪輯中移動相機、調整音量。分享前要先匯出；檔案約兩倍大。」

它跟錄影設定的開關是同一個 `editableRecording` 設定，錄影中鎖住。用托盤「開始可編輯錄影」開始的那一場，工作室在該場錄影中顯示可編輯錄影的介面，設定本身不變。

| 即時列 | 一般錄影 | 可編輯錄影 |
| --- | --- | --- |
| 相機 | 顯示或隱藏 | 不提供 |
| 麥克風 | 不錄（開關）、音量條、推桿 | 只有音量條 |
| 系統聲音 | 不錄（開關）、音量條、推桿 | 只有音量條 |
| 即時列下方 | — | 一行字：「錄完可在剪輯中調整音量、隱藏相機」 |

**可編輯錄影一律原樣錄製。** 不靜音、不管推桿設多少都以 100% 錄製、相機軌從不隱藏，這些都留到剪輯畫面再設定；剪輯畫面已經有音量、分段音量和隱藏時段（[editing](../docs/zh-TW/system-design/editing.md)）。推桿存好的數值保留，一般錄影時照樣套用。音量條保留，讓使用者仍看得到每個輸入有收到聲音，「沒有收到聲音」也照常運作。做法是讓可編輯錄影不再經過靜音、推桿和隱藏，而不是把它們改成可還原。

**一般錄影的靜音要說清楚會發生什麼。** 按鈕在輸入名稱旁寫「不錄」，不寫「Mute」。開啟時整組換成警告樣式，並寫「麥克風未錄製」（或「系統聲音未錄製」），而不只是把音量條變灰。有輸入未錄製時，托盤多一行提示，工作室沒開也看得到。

**無法使用可編輯錄影的地方**（Windows，引擎會拒絕：[session.rs](../native/capture/src/win/session.rs)），類型選擇器照樣顯示，可編輯錄影列在選項中但無法選擇，下方寫出原因：「可編輯錄影只支援 macOS。」維持選取一般錄影。這跟錄影設定目前在 Windows 上的做法一致，兩邊說法相同。托盤在 Windows 上照舊不顯示「開始可編輯錄影」。

### 問題：沒事就安靜，有事由選擇器說出來

輸入裝置有問題時，它的選擇器會改變：換成警告底色和邊框、圖示換成斜線版本、名稱換成問題本身，例如「找不到 FaceTime HD」「麥克風沒有收到聲音」。按下去還是同一個選單，可以直接換裝置。沒有燈號，工具列也沒有另外的狀態列。

| 輸入 | 由選擇器說出的問題 |
| --- | --- |
| 螢幕 | 選擇的顯示器無法使用；沒有螢幕錄製權限 |
| 相機 | 沒有權限；選擇的裝置未連接；等待中、尚未就緒或斷線（090 的狀態，從舞台上方的那行字移過來） |
| 麥克風 | 沒有權限；選擇的輸入未連接；蓋子闔上（既有文字）；沒有收到聲音（新增，見下） |

**沒有收到聲音**是新功能。在工作階段進行中（即時預覽或錄影中），麥克風音量持續低於某個下限一段時間，就算是沒有聲音；靜音或推桿在 0% 時不算。下限和時間長度見 D3。錄影之間沒有音量資料，所以只有開著即時預覽或錄影中才知道有沒有聲音。

即時列的音量條照舊顯示音量，不再另外顯示警告。

### 相機：一個開關，泡泡只在看得到的地方

| 時機 | 相機選擇器的開關 | 即時列的顯示／隱藏（僅一般錄影） |
| --- | --- | --- |
| 錄影前 | 這次錄影要不要帶相機 | 不能用：還沒有在錄 |
| 錄影中，有相機 | 鎖住 | 立即在檔案中顯示或隱藏相機（075 的 D13） |
| 錄影中，沒有相機 | 鎖住 | 不能用，並說明相機會從下一次錄影開始加入（既有文字） |

可編輯錄影的相機在剪輯中事後隱藏，所以即時列沒有顯示／隱藏。

泡泡只遵守一個規則：**預覽裡看得到相機，才拖得動。**

| 狀態 | 預覽裡 |
| --- | --- |
| 相機開著，畫面已顯示 | 相機畫面本身，可以拖 |
| 相機開著，還沒有畫面（即時預覽關著，或相機啟動中） | 毛玻璃泡泡，可以拖（目前的佔位樣式） |
| 相機關著，或已從錄影中隱藏 | 什麼都沒有，也不能拖 |

虛線框和看不見的拖動區域都移除。

### 兩種畫面

預覽畫面選單只有**錄影畫面**（預設）和**檢查相機**（目前的「只看相機」，改名以說明用途）。移除「只看螢幕」：它唯一的用途是看相機擋住了什麼，改成直接隱藏相機就好。已儲存的 `screen` 畫面一律當成 `composed`。

### 錄影分頁成為裝置檢查站

螢幕、相機、麥克風這幾列留在錄影設定，跟工作室的選擇器改的是同一個設定。每一列另外提供裝置正常運作的即時證據：

- **麥克風**：目前的輸入音量列（079）保留在裝置旁邊。
- **相機**：在裝置列旁邊顯示所選相機的小型即時畫面（何時開啟由 D4 決定）。
- **螢幕**：沿用目前的顯示器排列圖，這裡不即時擷取螢幕。

裝置問題的用字跟工作室的選擇器一致。「在錄影工作室中調整…」保留。

### 工作室以外

- **托盤。** 「錄影包含」底下，每個輸入都附上裝置名稱，例如「麥克風 — MacBook Pro 麥克風」。已知的問題在下面多一行（例如「找不到相機」），點下去打開工作室。
- **倒數。** 開始錄影時如果已知有問題（裝置不見、沒有權限、顯示器無法使用；不包括沒有收到聲音，因為那需要工作階段），倒數畫面多一行說明，使用者還來得及取消。沒有問題就什麼都不加。
- **錄影中、工作室沒開時。** 錄到一半才發生的問題（相機斷線、麥克風沒有聲音）由托盤提示（D5）。

## 決策

- **D1 — 版面。** 2026-10-27 採用：選擇在上、即時控制在下，不做展開的狀態列、側欄或浮在畫面上的狀態。記錄下來，條件沒變就不再重議。
- **D2 — 狀態呈現。** 2026-10-27 採用：不用燈號；沒事就安靜；由選擇器說出問題。即時證據（縮圖、音量）放在錄影分頁的裝置檢查站，不放在工作室的選擇器，因為預覽和即時列已經顯示這些內容。
- **D3 — 沒有收到聲音的判斷規則。** 提案：工作階段中峰值低於 −60 dBFS 持續 10 秒，靜音或 0% 時不算，音量一回升就解除。用步驟 1 的資料檢查：安靜房間裡正常運作的麥克風絕不能觸發。
- **D4 — 錄影分頁的相機畫面。** 打開相機會亮起相機燈，也會耗 CPU。提案：一顆「測試相機」按鈕，按下後顯示畫面，再按一次或離開分頁就關閉；單純進入分頁不會打開相機。另一個選擇是分頁在畫面上時就一直打開。在步驟 5 之前決定。
- **D5 — 錄影中、工作室沒開時發生的問題。** 提案：只用托盤（狀態行和提示文字）。通知比較吵，也可能蓋住正在錄的畫面。在步驟 6 之前決定。
- **D6 — 工作室裡的錄影類型。** 2026-10-27 採用：錄影類型在工作室和錄影設定都能選，即時列跟著類型變。可編輯錄影以 100%、不靜音、相機軌不隱藏的方式錄下每個輸入，這些都在剪輯中事後設定。一般錄影保留靜音、推桿和顯示／隱藏，靜音改名為說明該輸入不會被錄到。無法使用可編輯錄影的地方，選項顯示為無法使用並寫出原因，絕不隱藏。

## 步驟

- [ ] **0. 開始。** 檢查目前的程式碼和上面提到的已結案計畫。第一次桌面測試前，依 [AGENTS.md](../AGENTS.md) 啟動 `caffeinate -d -i -t 5400`。
- [ ] **1. 模型。** 在 main 的設定模型裡：把每個輸入（螢幕、相機、麥克風）的問題狀態集中在一處，供工作室、錄影分頁、托盤和倒數共用；根據音量資料判斷沒有收到聲音（D3），測試要包含安靜房間和靜音的情況；`composed` 和可拖動與否遵守泡泡規則；畫面清單只留 `composed` 和 `camera`，已儲存的 `screen` 讀成 `composed`；相機開關和顯示／隱藏的可用狀態照上面的表格；工作室的錄影類型（同一個設定，非 macOS 時顯示為無法使用並附原因），以及每種類型提供哪些即時控制，包括從托盤以可編輯錄影開始的那一場。先寫單元測試。
- [ ] **2. 工作室版面。** [studio.tsx](../src/renderer/settings/tabs/studio.tsx)：標題列、選擇列（類型選擇器、三個裝置選擇器和錄影按鈕）、兩種類型各自的即時列，移除舊面板和人像按鈕。選擇器沿用現有的 Select 和開關元件。錄影中的鎖定狀態。一般錄影的「不錄」開關和未錄製的樣式。
- [ ] **2b. 可編輯錄影原樣錄製。** 在 [recorder](../src/main/recording/recorder.ts) 和相關動作裡：可編輯錄影的工作階段一律送出 100% 音量而非存好的音量，拒絕靜音和隱藏相機的要求（托盤也一樣：可編輯錄影不提供隱藏相機），一般錄影照舊使用存好的音量。兩種類型都要有測試。引擎的檔案格式不變。
- [ ] **3. 預覽。** [camera-preview.tsx](../src/renderer/settings/tabs/camera-preview.tsx) 和 [ui.css](../src/renderer/ui.css)：泡泡規則；移除虛線框和看不見的拖動區域；相機狀態從舞台上方那行字移到相機選擇器。「檢查相機」保留目前的放大相機和它的狀態。
- [ ] **4. 問題呈現。** 選擇器的問題樣式和用字；錄影分頁各列使用相同用字；每個新字串都要翻譯。
- [ ] **5. 錄影分頁的裝置檢查站。** 先決定 D4。依 D4 加入相機即時畫面；麥克風輸入音量列保留在裝置旁；問題用字與步驟 4 共用。
- [ ] **6. 托盤和倒數。** 先決定 D5。托盤的裝置名稱、問題行和開啟工作室的動作；輸入未錄製時的提示行；倒數畫面的問題行。
- [ ] **7. 桌面測試。** 取得「好了」的交接後，在新建的 `pnpm start:app` 套件上，用[原生驗收 skill](../.agents/skills/native-acceptance/SKILL.md)：錄影前和錄影中的工作室，相機開著、隱藏、關著三種情況；拔掉相機或拒絕相機權限；開著即時預覽時麥克風沒有聲音；相機不見時用快捷鍵開始錄影（倒數的那一行）；托盤的提示行。一般錄影中讓某個輸入有一段不錄；可編輯錄影在麥克風推桿存為 50% 時錄一段：一般錄影的檔案那段是無聲，可編輯錄影的麥克風軌是原本收到的音量（以媒體驗證確認），且即時列沒有靜音、推桿或隱藏。還原設定、關閉 app，並確認它的程序都已結束。
- [ ] **8. 寫文件並結案。** 改寫 [desktop：錄影工作室](../docs/zh-TW/system-design/desktop.md#錄影工作室)（裡面寫裝置選擇不放在工作室，這點已推翻）、[recording](../docs/zh-TW/system-design/recording.md) 和 [editing](../docs/zh-TW/system-design/editing.md)（可編輯錄影在錄影中不套用音量、靜音和隱藏相機）、[設計決策](../docs/zh-TW/system-design/decisions.md)（D1、D2、D6 和移除「只看螢幕」）、函式參考、翻譯、提到工作室的說明和 README、驗證紀錄和計畫索引。

## 驗證

每個步驟完成時，依[測試政策](../docs/zh-TW/testing.md)選擇：

- 步驟 1–4：`pnpm test:scope -- studio recording-settings tray countdown`（工作室、錄影分頁控制項、托盤模型、倒數畫面）；共用元件有改時加上 `layout`。新增的行為測試：各狀態下的泡泡規則、畫面設定的轉換、沒有收到聲音的判斷、鎖定狀態、每個選擇器的問題狀態。UI 測試只檢查行為和無障礙，不檢查設計數值。
- 步驟 2b：`pnpm test:scope -- recording`，檢查 recorder 依類型處理音量、靜音和隱藏。
- `pnpm check`，因為設定模型、recorder、托盤和倒數會一起改。
- 如果沒有收到聲音的判斷或相機測試加了計時器、或讓擷取一直開著，就跑 `pnpm measure:cpu`（測試政策的 CPU 那一列）。
- 步驟 7 的桌面測試如上。步驟 2b 改了可編輯錄影錄下的內容，所以適用測試政策的錄影那一列：兩種類型各做一輪錄影冒煙測試（開始、停止、存檔、媒體驗證、播放），涵蓋上面的情境。擷取、編碼和檔案格式沒有改，所以不跑錄影矩陣。
- 分開回報：自動化結果、桌面測試觀察到的結果、仍未驗證的項目（Windows 只有 CI 檢查；外接相機和 USB 麥克風只在有接的時候測）。
