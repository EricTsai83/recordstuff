## Local acceptance before tagging

`pnpm start:app` built, signed, verified and opened `dist/mac-arm64/RecordStuff.app` on macOS 26.6.2 (25G83), Apple M1 Pro, arm64, 32 GB, Electron 44.3.0. Two user-authorized `pnpm acceptance` runs recorded through the global shortcut: 20.3 s and 30.3 s, with approximately 82 s idle between runs in the same App process. Both integrity-tier checks passed, including full decoding, 1920×1080 output and non-silent 48 kHz stereo audio (per-channel RMS approximately −27.2 and −27.1 dBFS). These are script recording results, not tray UI results.

Native Computer Use verified sequential Standard → High → Economy → Standard changes, English/Traditional Chinese UI switching, Chinese persistence after normal quit and reopening the same artifact, and restoration of the original English settings. Both files played in QuickTime with advancing video and successful seeking. The user opened Settings from the tray because the tool could not operate the tray itself. Original settings were restored and both recordings saved; the App remains open and idle.

Case totals: **9 pass, 0 fail, 3 blocked, 4 not run**. Blocked cases: native tray start/stop and menu states; recording-time settings locking/language switching; notification or Show last recording navigation to Finder. Fullscreen recording prevented reliable native settings interaction. These are tool limitations, not demonstrated App failures.

[Detailed local report and evidence](../measurements/2026-09-21T0220-computer-use/report.md) are gitignored and available only on the acceptance machine. AX and playback screenshots were observed in the tool conversation; no screenshot files were saved. One inactive test-material browser tab remains because Browser Use rejected its file URL during cleanup.
