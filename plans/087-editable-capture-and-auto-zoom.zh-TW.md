# 087 — 可選分離素材錄影：錄完再決定相機位置與音量

[English](087-editable-capture-and-auto-zoom.md) | [繁體中文](087-editable-capture-and-auto-zoom.zh-TW.md)

狀態：第一步已於 2026-10-24 完成（[紀錄](../docs/zh-TW/verification/history-2026-10.md#plan-087-第一步可編輯錄影的成本--2026-10-24)）；同日已決定 D1（見下方）：繼續，但不做滑鼠事件與自動縮放。下一步：可編輯選項與畫面模型。檔名維持不變以免連結失效；自動縮放已不在本計畫內。建立：2026-10-22，原編號 088；2026-10-23 改編號為 087。同日維護者把 086（樣式與渲染匯出）從佇列移除，所以本計畫現在承接 086 中它少不了的兩部分：純畫面模型與渲染匯出。硬性相依：085 已實作並在使用中（它的編輯畫面、編輯狀態、匯出 worker 與發布），以及下方的 D1；084 的預覽上限，以及經 090–092 重量後的[管線 baseline](../docs/zh-TW/system-design/tooling.md#管線-baseline)。佇列第八個，也是最後一個。依[計畫索引](README.zh-TW.md)與[系列契約](README.zh-TW.md#glide-參考演進083087)執行。除第一步外，以下實作及效能目標尚未驗證。

## 目標與產品門檻

讓未來的錄影在錄完後可以編輯，一般的直接 MP4 仍為預設：錄完後再決定相機小框放在哪、多大，並分別設定系統聲音與麥克風的音量，然後匯出成一般的 MP4。舊的扁平錄影無法還原相機或乾淨的螢幕畫面，也不承諾還原。

**D1 — 是否要做、範圍多大：維護者已於 2026-10-24 決定**，依第一步的數據（引擎多 3.33 個百分點，App 估算為直接模式 CPU 的 1.27 倍，記憶體 +1.3 MiB，磁碟 1.33 倍）。繼續，但只做這個範圍：錄完後的相機位置與大小，以及兩個音量。滑鼠事件與自動縮放不做：游標維持現在的方式，直接畫在螢幕畫面裡。螢幕畫面的樣式美化（背景、留白、圓角、陰影、其他輸出比例）隨 086 移除，仍不在範圍內，維護者不需要。相機小框本身的樣式（大小、圓角、鏡像）是既有的相機版面設定，維持不變。

## 步驟與責任

- [x] **先以原型量成本。** 一個明確、預設關閉的可編輯錄影選項，擷取乾淨的螢幕影片、可選的獨立相機，以及獨立的系統與麥克風音軌，共用媒體時鐘，帶有 offset、暫停／停止規則與遺失 metadata，沿用引擎的編碼器與 muxer。建 UI 前先量測；除非預算與 D1 允許，否則不額外編一份扁平 MP4，因為下方的渲染匯出可依需求產生。*2026-10-24 完成，放在開發開關 `RECORDSTUFF_CAPTURE_EDITABLE=1` 後面（macOS）：一個 MP4，只有螢幕的畫面、各輸入的聲音與相機（1280×720）各自一軌，每種類型的第一軌預設播放；`pnpm bench:editable` 量到引擎多 3.33 個百分點，App 估算為直接模式 CPU 的 1.27 倍，常駐記憶體 +1.3 MiB，每分鐘磁碟用量 1.33 倍，都在提案的預算內。中斷照現在的方式回報（事件、log、session 紀錄），尚未寫進檔案；App 沒有暫停功能。已驗證與未驗證的項目見[紀錄](../docs/zh-TW/verification/history-2026-10.md#plan-087-第一步可編輯錄影的成本--2026-10-24)。*
- ~~**滑鼠事件，opt-in 且有上限。**~~ 已由 D1（2026-10-24）取消：不做自動縮放就不需要，游標維持在螢幕畫面裡。
- [ ] **可編輯選項。** 在「錄影」設定中加入一個選項，預設關閉，並在開啟處說明，取代第一步的開發開關：開啟時（macOS）錄影存成可編輯的格式，關閉時與現在相同。錄影卡片會標示它是可編輯的；這種檔案在匯出前，用任何播放器開啟都只顯示螢幕與系統聲音（第一步的軌道配置）。在 Windows 的引擎支援前，Windows 隱藏這個選項。
- [ ] **小型的純 Rust 畫面模型**（來自 086）：由編輯的 revision 與有理數媒體時間，回傳 render 參數，在本計畫中只有相機在螢幕畫面上的位置、大小與是否顯示。時間在到達平台邊界前都維持整數／有理數，絕不以 UI 的幀間隔推進；座標空間、取整、比例與裁切只定義一次；色彩為 BT.709，範圍一路保留。沿用 `camera_layout` 的數學而不是複製，不持有擷取時鐘或 OS handle，並以確定性 fixture 依正序、倒序與隨機順序重播檢查。
- ~~**在這個模型中做自動縮放。**~~ 已由 D1（2026-10-24）取消。
- [ ] **在 085 的編輯畫面中調整相機與音量。** 對可編輯的錄影：在預覽上像錄影工作室在錄影前那樣擺放相機小框並調整大小（整段錄影一個位置），可顯示或隱藏，並用工作室的音量推桿分別調整系統聲音與麥克風；每個變更都能在 085 有上限的編輯狀態中復原，並存進其有版本的紀錄。不做 keyframe 時間軸或分段擺放。
- [ ] **渲染預覽與匯出**（來自 086），在 085 的匯出 worker 中，使用已在 Metal 與 Direct3D 11 上執行的既有 WGSL compositor（plan 075）；只有需要 kernel 做不到的多 pass 渲染時，才在量測成本後重新考慮 wgpu。預覽：依需求以及播放時以 Studio 的預覽幀率渲染，透過既有的編碼預覽傳輸並套用 084 的上限送出，每次 seek 一個 generation。音訊：系統與麥克風音軌各自解碼，依 offset 放到共用媒體時鐘上（中斷是靜音，絕不是位移），依 085 精確到 sample 的規則剪開並在接點淡入淡出，用引擎既有的混音器，以編輯設定的各輸入音量混音（初始值為錄影時工作室的設定；plan 074 與 075），再編碼成一條 AAC 音軌；預覽播放同一份混音，所以編輯時聽到的就是匯出的內容，不依賴任何播放器去混合分開的音軌。匯出：硬體解碼 → 畫面渲染 → 硬體 H.264 編碼 → mux，每段都有有限的幀與 bytes 佇列及 backpressure；沒有硬體支援時以原因拒絕匯出。發布、取消、准入（錄影永遠優先）與退出沿用 085；一個工作綁定一個編輯 revision。
- [ ] **多軌復原。** 085 的編輯狀態與匯出 worker 擴充為多檔案的 session：單一 session owner、各軌大小與 backlog 上限、整體磁碟空間政策、manifest 最後 commit，以及漸進寫入的復原 metadata（絕不為每個事件重寫一個不斷增長的 JSON array）。worker 結束後保留可救回的螢幕片段，並標出缺少的相機、麥克風與時間缺口；磁碟用盡時依既有的 outcome 契約安全結束媒體。

## 門檻與驗證

實作前在參考機上依管線 baseline 固定上限。原型的暫定預算：相同相機與音訊輸入下，App 總 CPU 不超過直接模式的 1.5 倍，常駐記憶體增加不超過 256 MiB，佇列上限與錄影長度無關；磁碟放大量依音軌分開回報。這些是產品預算提案，不是證據。超過時就縮減音軌或解析度，或停在 D1；絕不放寬預設錄影的預算。

預設模式維持在 baseline 範圍內與其節奏、同步預算內。可編輯模式的每個啟用音軌都要符合既有的同步與節奏標準，因為多個時鐘可能漂移，所以要跑 `pnpm matrix -- long`。畫面參數在每種重播順序下都在明定的容差內一致，預覽與匯出在同一媒體時間渲染的畫面在測試前宣告的容差內一致（不用 UI pixel baseline）。固定的 1080p30 參考錄影的渲染匯出在參考 Mac 上至少達到即時速度，佇列記憶體與長度無關，取消的 p95 在 2 秒內；解碼、渲染、等待編碼器與寫入分開回報，速度提升不得來自降低畫質。在系統與麥克風音軌各放不同純音的 fixture 上，兩者在匯出中都聽得到，跨每個剪點都與畫面同步，包括麥克風中斷的情況。檢查每次 seek 時的相機位置、相機與麥克風中斷，以及程序結束後的復原，再做編輯 → 匯出 → 原生播放。權限依既有的 hands-on 邊界，絕不自動重設 TCC。

廣泛的擷取、儲存、UI 與生命週期整合需要 `pnpm check`、最後的 `pnpm acceptance:regression`、新簽章錄影的媒體驗證與播放、受影響的錄影設定、Studio 與生命週期案例、CPU 對照，以及包含 `long` 的相關 matrix。Windows CI 只檢查契約與建置；未測試的實機行為要列出。結案時完成復原、格式與隱私文件及雙語說明，保留失敗的實驗、移除探針，並更新耐久的決策。
