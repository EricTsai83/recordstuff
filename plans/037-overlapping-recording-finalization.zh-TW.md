## 價值與量測門檻

目標是連錄數段獨立影片時，縮短段落間等待：只有效益值得時，允許已停止的 A 發布穩定媒體檔期間開始 B。這與錯誤歷史非同步保存不同，會改變媒體生命週期入口。RecordStuff 本來逐段寫入，不一定有 Cap 昂貴的片段 remux 階段，不能用 Cap 的效益當成本專案的量測。

- [ ] 量測停止至允許下一次開始的時間，拆分 host 最後資料交付、待寫資料、flush／close、獨占發布／複製與 UI 回應。使用具代表性的短／長錄影及本機／隔離外接儲存，記錄大小、硬體、時間與媒體完整性，不填滿系統碟。人工延遲只能證明工作管理正確，不能當實際效能收益。
- [ ] 初定進入實作門檻：可重現的代表案例中 p95 停止至可開始超過 1 秒，且至少 0.5 秒屬於擷取／排空／flush／close 之後可安全分離的工作。列樣本數與分布，調整門檻須有書面證據。若沒有明顯可分離等待，記錄不實作建議並延期，不為了完成計畫而降低安全或增加複雜度；未實作功能不能默默標完成，與維護者記錄排程／結案決定。

## 通過量測門檻後的實作契約

- [ ] 延伸 025 操作 registry：正在擷取、已停止且封存檔案待發布、終止結果分別有每次錄影的擁有者。A 最後資料交付完成、全部寫入排空、暫存檔 flush 並關閉後，才釋放擷取資源並允許 B 與 A 發布重疊。A 保有獨占檔名／路徑；A 晚到事件不可停止 B、共用 B writer 或刪除已宣稱保留的部分檔案；每次錄影保有自己的 038 哨兵直到自己的終止結果。維持 024／026 完整位元組與空檔保證。
- [ ] 最多一段正在擷取，加一筆較舊媒體收尾；同一時間只有一個發布工作（main 內序列化的 promise 鏈，不是執行緒）。若 B 停止時 A 未完成，安全封存 B 並禁止開始 C，直到有空位；不丟 B、不無限排隊、不平行複製兩筆。所有封存／排隊檔案列入退出管理；若無法安全拆分，維持目前 stopping 禁止新開始的規則。
- [ ] 慢／滿／離線磁碟代表需要限制新工作，不是持續錄進 RAM 的理由；不重疊尚未 flush 的寫入積壓。量測 A 發布與 B 即時寫入競爭，在慢磁碟啟用前，以 038 的寫入積壓計數與磁碟餘裕防護加上實測寫入延遲，定義並測試保守的開始條件，不另建第二套積壓量測；不安全時明確顯示等待存檔。非同步不增加吞吐量，不自動降品質或丟媒體掩飾負載。
- [ ] 選單列仍只有一個圖示：B 的 REC 優先，選單／狀態另外標示 A 正在存檔；只剩收尾時不能暗示已完成。呈現封存／待處理工作及禁止新開始的原因。完成／失敗歸屬原錄影，必要時進失敗歷史，確認／定位不可跨 ID；A 發布成功前不宣稱存好、不提供不完整目的檔案。
- [ ] 保留錄影中抑制成功通知的既有政策，依錄影 ID 決定取消，不重播過期通知；不新增成功影片歷史庫。如需改通知政策，明列並驗證。每次錄影快照輸出／品質，B 設定不改 A 目的地。權限恢復／relaunch／退出檢查全部媒體操作及 036 metadata，媒體未完成時不得提供破壞性強制退出。
- [ ] 補齊雙語存檔／等待／錯誤 UI 與錄影／桌面設計，使用 [Codex 實作／Opus 5.5 review](../.agents/skills/codex-implement-with-opus-5-5-review/SKILL.md)；重用 025 協調器，不另建生命週期控制器。
