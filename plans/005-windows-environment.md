# 005 Windows 環境與驗收

狀態：待執行
前置：環境建置無前置；錄製驗收使用 007 的設定與 008 的工具（可與 003、004 平行）
後續：006 的 Windows 部分

## 問題

001 §4 要求在 Windows 10 20H2 以上錄 10 分鐘、檔案總管雙擊用媒體播放器能播；§17 第 3、4 題需要在 Windows 驗證。目前只有一台 Mac。

補驗 007 的 Windows 品質選項、實際擷取／成品參數及 60 fps 能力。Windows 60 fps 未驗證前保持停用；VM 結果不能代替 x86 實體機效能驗收。

## 做法

1. 環境：Parallels Desktop 或 UTM，安裝 Windows 11 ARM。Electron 有 win32-arm64 建置，pnpm、Node 24 都有 ARM 版。x64 的驗收（§4 提到近三年 x86 筆電）留到有實體機器再補，記為已知缺口。
2. 在 VM 內 clone、`pnpm install`、`pnpm dev`。確認：系統匣圖示、第一次啟動的「RecordStuff 在系統匣待命」通知、紅色錄製圖示、Windows 沒有任何權限提示。
3. 錄 60 秒有聲音，檔案總管雙擊用「媒體播放器」播。
4. §17 第 4 題的驗證：錄一段前十秒完全無聲、之後才有聲音的內容，確認音畫對齊、音軌長度等於影片長度。這是驗證 Chromium 的 keepalive 確實生效，預期通過。
5. §17 第 3 題：loopback 是否穩定拿到系統音；切換輸出裝置（耳機 ↔ 喇叭）時的行為。
6. 10 分鐘 1080p30 的 CPU 與檔案大小；工作管理員看 GPU 影片編碼是否有活動。
7. 儲存位置測試：改到一個之後拔掉的 USB 或網路磁碟，確認「儲存位置無法寫入」的通知與選單第一行。
8. `pnpm dist:win` 產出未簽章 NSIS 安裝檔，安裝、啟動、SmartScreen 警告的實際文字記進 README。

## 完成標準

- §17 第 3、4 題在 Windows 端有答案。
