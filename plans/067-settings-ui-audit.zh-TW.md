先用既有 preview 矩陣；只有缺少涵蓋才延伸共用情境準備或 Playwright。下列新增項目是規劃範圍，不是現有 CLI 參數。資料使用合成資料、隔離偏好；不刪除或改名維護者的錄影檔。

| 維度 | 必要範圍 |
| --- | --- |
| 頁面 | 四個頁籤、每個可捲動區的頂部及底部、每項設定／控制項、視窗外框／狀態／頁尾 |
| 語言及外觀 | 英文、繁中 × 淺色、深色；操作「跟隨系統」及選中狀態；四頁的基準完整交叉雙語、雙主題 |
| 尺寸 | 預設 960×640、窄版 440×760、最小 380×360；固定高度檢查 599/600/601px 與 419/420/421px 斷點；加一個大視窗檢查過量留白 |
| 縮放 | 雙語中資訊密集的錄影／一般頁，檢查 100%、125%、150%、200%；包含最小尺寸與放大的預設視窗。透過 App 的縮放路徑操作，記錄實際 zoom／邏輯 viewport，確認所有操作仍可到達 |
| 視窗／控制項 | 啟用／未啟用、待命／停用／儲存中、hover／focus／選中、成功／錯誤／重試；靠近邊界的 popover／選單；全鍵盤路徑 |
| 錄影檔 | 空白、載入、讀取失敗／重試、網格／列表、多檔案、無縮圖、長英文／中文檔名、改名有效／無效／等待、移到垃圾桶／復原及復原期限 |
| 設定及狀態 | 待命、開始、錄影、存檔、缺權限、儲存失敗、無效檔名模板、長路徑、快捷鍵聆聽／衝突／逾時／重試、更新等待／錯誤及清理本機資料確認 |
| 失敗與覆蓋層 | 空白／有紀錄、未讀／已讀、多列展開、恢復動作／技術細節；說明 popover、改名對話框、toast、縮放提示；內嵌播放／暫停、選單／slider，受影響時涵蓋全螢幕交接 |

四頁 × 雙語 × 雙主題 × 預設／窄版／最小尺寸，形成 48 張基準圖片；其他狀態依實際風險選代表組合。每項設定及每種暫時 UI 都要有案例；共用變更可能影響其他組合時追加。捲到底的內容另外截圖。不在沒有待解問題時把所有狀態與維度無限制相乘。

每項問題記錄：ID、頁／狀態／語言／主題／尺寸／縮放、截圖與原始碼位置、量測問題、使用者影響、嚴重度、修正方向、驗證案例及最終處置。P0 是無法操作或資料風險；P1 是控制項不可用、截斷、不可讀或互動故障；P2 是反覆出現的層級、功能可發現性、間距問題；P3 是外觀細修。區分已確認、候選與接受的取捨。完整盤點也可能發現某頁已良好，應寫明證據並保留。

各適用表面都評估以下面向：

1. 資訊架構：分組順序、清楚名稱、目前位置、設定與值的關係、主要／次要／破壞性動作及重複控制項。
2. 字體：實際 font size／line height／weight、中文字形、短標籤與長說明、數字對齊、root/rem、截斷及縮放。讀取 computed styles，不假設 Tailwind token 名稱等於像素。
3. 版面：間距節奏、列對齊、控制項寬度、卡片 padding、區段間距、側欄密度、有效內容寬度、捲動提示、可到達性、標題列避讓及頁尾。
4. 互動：窄版頁籤可發現性、說明入口、即時儲存回饋、等待／停用原因、鍵盤導覽、焦點返回、重試及復原；操作不可只有 hover 才能到達。
5. 外觀／可及性：雙主題對比、選中／停用／錯誤辨識、清楚 focus、可及名稱與描述、減少動態、高對比與選用螢幕閱讀器觀察。DOM 屬性不能代表 VoiceOver 通過。

產出：涵蓋整體 UI 的問題台帳、證據支持的優先順序及每頁結論。在這階段之前不宣稱介面整體好或不好。

## 3. 訂共用設計規則並實作已確認改善

以下為產品起始目標，需對照基準及原生桌面密度調整；字級與間距是設計選擇，不是 WCAG 強制要求：

| 項目 | 起始目標及驗收規則 |
| --- | --- |
| 字體層級 | 主要標籤／值約 13–14 CSS px，說明／metadata 至少 12px，頁標題約 22–24px；敘述行高約 1.4–1.5。必要文字低於 12px 須記錄例外；量最終 computed size，包含 rem utilities |
| 間距 | 以 4/8px 級距建立小型共用尺度；相關操作比不同區段更靠近；卡片／列 padding 一致。長內容可增高 |
| 控制項 | 主要高度約 28–32px；量真正 hit rectangle。小圖示操作目標至少 24×24 CSS px，或說明適用的間距／等價操作例外；放大點擊區不必放大圖案 |
| 對比 | 一般有意義文字 ≥4.5:1，大字 ≥3:1，必要控制項／狀態圖形與相鄰色 ≥3:1。用 computed／合成色量測；裝飾、停用有各自例外 |
| 響應式 | 不出現非預期外層水平溢出、標籤／控制項重疊、操作無法到達。長路徑／說明換行；有意省略檔名時提供取得完整名稱的方法。200% zoom 可捲動／重排，不隱藏必要操作 |
| 導覽與狀態 | 選中頁不只靠顏色；窄版其他頁能以滑鼠與鍵盤理解；錯誤／等待／停用資訊可發現；即時變更有回饋且不搶焦點 |

對比與點擊範圍依 W3C 的[文字對比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字對比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[操作目標尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。它們是選定的可及性檢查，不代表完整 WCAG 符合宣告。

- [ ] 先修 P0/P1，再改善密度／外觀、P2 及有理由的 P3。每項已確認問題都修正或明確說明延後理由；必要項目未解時不可無條件結案。
- [ ] 先調共用字級／間距／控制項 tokens，再調外框／導覽／響應式，最後逐頁、選單／對話框／說明及回饋。沿用 primitives／variants；只有設定頁需要的修改限定於該表面。
- [ ] 保留 committed value、焦點 ownership、快捷鍵擷取、鎖定及 IPC 契約。已確認 UX 問題需要改語意時，修改 controller/model 並加有意義回歸涵蓋，不用 CSS 遮掩。
- [ ] 改文案時同步雙語及 placeholder。說明幫助使用者做決定，避免把實作細節放入產品流程。
- [ ] 沿著共用 `ui.css`／primitives 查到倒數、內嵌及全螢幕播放器。即使沒改播放器檔案，root/rem/token 也可能影響它們；納入受影響截圖及必要行為檢查。
- [ ] 開發中的局部檢查只回答具體問題。對未定設計產生候選截圖，由 agent 判讀迭代，不把例行選擇交給使用者核准。

產出：對應台帳 ID 的修復，以及最終設計 token／互動理由。

## 5. 選定最終驗證 recipe 並執行一次

依[測試政策](../docs/zh-TW/testing.md)分類最終 diff 及 callers 後，在任務本地紀錄寫實際 recipe。合併所有適用列，包含測試／scripts 及共用 renderer 影響；同任務只重用輸入、產物、環境、案例仍有效的證據。

| 影響 | 目前政策的必要 recipe | 條件／排除 |
| --- | --- | --- |
| 只寫計畫文件 | 相對連結／anchor、package 指令名稱、雙語一致及 `git diff --check` | 本輪規劃不啟動／建置 App、不錄影、不開 caffeinate |
| 設定外觀／互動實作 | `pnpm acceptance:regression`，再用相同最終 `out/` 跑 `pnpm preview:ui` 並判讀；`git diff --check` | Regression 包含 `pnpm check`／build／Playwright，不另外重跑相同 check/build。066 後採其核准的當前等價流程，保留所有必要涵蓋 |
| 共用 player/video 呈現／互動，包含間接 token 影響 | 同一最終 `out/` 追加 `pnpm acceptance:player` | FFmpeg 產生合成片；只改外觀不需錄真實螢幕／系統音訊 |
| Window options、`window-controls.ts` 或左上角繪製 | 新 `pnpm start:app`，再 `pnpm acceptance:settings-shortcut -- --observe`，判讀 `settings-window.png` | 離屏圖不能判定原生視窗控制；結束這輪時可用既有 `--quit` 收尾選項，確認退出並保留 cleanup |
| 擷取設定／鎖定或其他 runtime 行為 | 追加受影響政策列，必要時做相關 signed-bundle 錄影 smoke | 鎖定的示意圖不證明真錄影行為。資料夾／品質持久化、快捷鍵送達、timer／CPU、權限如有修改，各需實際案例 |
| Preview／測試 runner 修改 | Typecheck、相關測試及修改路徑的實際執行，包含受影響失敗／cleanup 路徑 | 可由有涵蓋的組合檢查供應；保留錯誤分類及程序監督 |

所有 `out/`／`dist/` 建置及 runners 依序執行。目前 regression 含桌面設定／快捷鍵 fixture，交接前不可啟動該組合指令。066 後先確認替代流程確實只跑背景，再省略交接。離屏 preview 及背景 Playwright 不需交接。

每次桌面回合前列出確切案例、游標／按鍵／焦點／畫面／音訊影響，請使用者回「好了」，停止輸出並等待。一個回覆涵蓋所述連續回合及收尾。依 [native acceptance skill](../.agents/skills/native-acceptance/SKILL.md)：已有 runner 的操作由專案 runner 做，未涵蓋 UI 與截圖觀察由 Computer Use 做，不臨時寫 AppleScript/IPC 代替原生輸入。鎖定、缺權限／工具／簽章 identity 或干擾記 blocked；繼續獨立可做項目、保留證據，不改稱不適用。

每個完整 App 回合還原偏好、關閉測試 UI、正常退出受測 App、確認本體及 helpers 消失，保持關閉。播放器／fixture 依 runner 收尾，不關無關 App。失敗／中斷也記 cleanup；任務結束停掉自己的 caffeinate。必要檢查通過後才完成；後續修改只重跑失效檢查，必要範圍通過即停止。

純外觀變更排除錄影／音訊矩陣、長錄、CPU benchmark、安裝、通知送達及網站檢查；依行為／相依改變重新分類。螢幕／系統音訊擷取、主觀聽感、真實 VoiceOver、Windows 實機若未實際操作仍未驗證，不能由背景／fixture 通過推論。
