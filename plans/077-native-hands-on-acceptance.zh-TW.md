# 077 — 原生錄影引擎的動手驗收

[English](077-native-hands-on-acceptance.md) | [繁體中文](077-native-hands-on-acceptance.zh-TW.md)

狀態：已規劃；尚未開始。建立：2026-10-16，依維護者在 076 步驟 7 的要求（「記下來，之後做」）。優先順序：建議緊接在 076 之後，由維護者排序。硬性相依：076，這些案例驗收的是它的原生引擎。依[計畫索引](README.zh-TW.md)按順序執行。

## 目標與範圍

完成原生錄影引擎（076）在 macOS 上、runner 無法單獨布置的驗收案例：每一項都需要維護者動手，或需要 agent 不得進行的機器設定變更，包括讓 Mac 睡眠、拔掉螢幕、撤銷螢幕錄製權限，以及讓 Dock 顯示出來。成功的標準是：每個案例都以簽署 bundle、透過原生引擎執行，結果依 [recording](../docs/zh-TW/system-design/recording.md) 的承諾記錄（睡眠與移除螢幕時存下檔案並給出正確通知、權限被拒時顯示權限卡片、開啟 D6 時錄影中沒有 Dock），而且每項設定或權限的變更都還原。

不在範圍內：Windows（依 076 的 D8 只由 CI 驗證）、任何引擎修改（在此發現的缺陷另立 plan，或由維護者核准修正），以及 076 的 runner 已涵蓋的案例（錄影品質、CPU、選單列、生命週期 fixture，以及 076 會加進 `pnpm acceptance` 的錄影中退出與自己的視窗）。

## 目前狀態

- 076 已在 2026-10-15 與 2026-10-16 記錄原生引擎的錄影品質、CPU 基準與選單列案例（[076 步驟 7](076-native-capture.zh-TW.md#7-驗證工具與驗收)）；這四個案例依維護者指示留待之後。
- Chromium 路徑處理過睡眠（plan 050）、螢幕移除與權限被拒；原生引擎把失敗對應到相同的 `HostErrorCode`，但這四項都還沒在實機上經過原生引擎執行。
- 維護者的 Dock 似乎設定為自動隱藏，因此 076 的 D6 那一輪兩次錄影都沒有出現 Dock。

## 步驟

### 1. 錄影中睡眠

- [ ] 原生引擎錄影中，由維護者讓 Mac 睡眠（Apple 選單 → 睡眠，或在螢幕允許時闔上螢幕）。依 plan 050 預期：錄影在睡眠前停止並存檔，喚醒後出現已儲存通知，不留下 sentinel。記錄 log 的停止與存檔行，以及檔案完整性（`pnpm verify`）。

### 2. 錄影中移除螢幕

- [ ] 錄製外接螢幕時，由維護者拔掉該螢幕。預期：工作階段以 Chromium 路徑相同的螢幕失敗（`track_ended`）結束，partial 依 recording.md 的說明保留或存檔，下一次在剩下的螢幕上錄影正常。結束後重新接上。

### 3. 權限被拒

- [ ] 由維護者在「系統設定 → 隱私權與安全性 → 螢幕與系統錄音」關閉 RecordStuff，然後開始錄影。預期：不擷取、和現在一樣顯示權限卡片與通知、log 有 `permission_denied`、不留下空檔案。維護者再開回權限，確認下一次錄影正常（依 recording.md，可能需要重新啟動）。

### 4. Dock 顯示時的 D6

- [ ] 讓 Dock 顯示（維護者在這一輪關閉自動隱藏，或在會顯示 Dock 的機器上執行），分別在「隱藏選單列與 Dock」關閉與開啟時各錄一次。預期：第一次的影格中有 Dock，第二次沒有；維護者把 Dock 設定改回原狀。

### 5. 記錄

- [ ] 把結果寫入驗證紀錄與 076（或其後續）的結案紀錄，附上證據路徑、每個案例改了什麼設定以及如何還原；未執行的案例列為未驗證。

## 完成與驗證邊界

每個案例都在簽署 bundle 上執行完畢，或由維護者接受列為未驗證；結果與證據都已記錄；這一輪改過的設定與權限都已還原，即算完成。每個案例都是一輪桌面驗證，遵守[桌面交接](../docs/zh-TW/testing.md#測試前確認桌面交接)；實體與系統設定的操作由維護者執行，agent 從不更改 TCC 或系統設定。撰寫本 plan 只需檢查連結、中英文一致與 `git diff --check`。
