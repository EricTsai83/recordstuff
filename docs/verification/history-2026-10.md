## Plan 066 closure — 2026-10-06

Plan 066 moved routine renderer and Electron integration acceptance off the desktop at the maintainer's request: `pnpm acceptance:regression` is now `pnpm check` plus the background Playwright suite (`pnpm test:ui`), which shows no window, takes no focus, sends no OS input, registers no global shortcut, plays no sound, delivers no notification and captures nothing ([background UI suite](../system-design/tooling.md#background-ui-suite)). Every former case has a ledger ID and a destination ([migration ledger](playwright-migration-066.md)): of the settings fixture's 516 cases 513 moved and 3 stayed native, the shortcut fixture's 57 and the player's 19 moved with native counterparts where the OS is the claim, and none was removed. No application source changed (`out/` digest `a2965ca06e8e` before and after).

- **Hosts and boundary.** Three Electron hosts (production main, a view host over the real model and library, and the production countdown overlay) run behind a boundary that creates every window hidden, offscreen and muted and answers show, focus, minimize, restore and full screen from a virtual state; the tray, notifications, shortcuts, dialogs, shell, Dock, capture and power are recording adapters. Teardown audits the boundary, samples the window server on macOS, quits normally and confirms from the process table that every process the launch owns ended.
- **Findings along the way.** An offscreen window's native `isVisible()` turns true with its page, so the window server is the containment check; Playwright's CDP keys never reach Electron's `before-input-event`, so the keys main intercepts are sent with `sendInputEvent`; Playwright emulates a light colour scheme unless told not to, which had drawn the dark baselines light; and `BrowserWindow.getAllWindows()` recognises windows by constructor name.
- **Native counterparts.** `pnpm acceptance:settings-native`, `pnpm acceptance:shortcut-native` and the reduced `pnpm acceptance:player`, together as `pnpm acceptance:recipe -- native-ui`. The clips are checked in (tests/ui/media), so neither the suite nor the player runner needs FFmpeg.
- **Review.** Codex GPT-6.1 Sol reviewed two passes. Pass 1's eight findings (CI baselines under Playwright's default `updateSnapshots`, unreported supervision errors, a one-time process snapshot, folder-mention process adoption, unguarded real dialog/notification/activation/tray paths, unmute checked only at the end, violations lost on self-exit, a missing Electron runtime reported as a failure) and pass 2's three (the registration recipe without the native runner, real registration recovery dropped from the native fixture, no summary on a blocked run) were all fixed; drills D08–D10 cover the containment and ownership fixes.

## Plan 068 closure — 2026-10-06

Plan 068 finished the module-boundary work the maintainer asked for on 2026-10-06, after `src/main/` and `src/renderer/` were regrouped into module folders earlier that day ([module boundaries](../system-design/repository.md#module-boundaries)). The maintainer asked for it to be done at once rather than after 066 and 067. It started from a working tree that also held the uncommitted React/shadcn migration, so HEAD `bcf744af` alone does not identify its inputs.

- **Action handler.** The 29 cases of `handleAction` moved verbatim from a closure in `src/main/index.ts` into `src/main/actions/actions.ts` (`createActionHandler`), with the collaborators passed in. `index.ts` keeps a hoisted one-line delegate and went from 1,033 to 871 lines. `actions/` is a new area between `menus/` and `index.ts`: the handler needs the settings store, the settings window and the tray, which a structural interface in `app/` would have copied, about 40 members. No runner anchor moved, as `controlled-acceptance.test.ts` and `update-acceptance.test.ts` confirmed. New tests pin the quit gate, each preference's lock, a raced update click and a drag.
- **Settings page.** `settings-app.tsx`, about 1,800 lines, became the shell plus `tabs/library.tsx`, `tabs/preferences.tsx`, `tabs/shortcut-editor.tsx`, `tabs/failures.tsx` and `undo-toast.tsx`, line for line. The Recording and General tabs share one model-driven renderer, so there are three tab modules, not four. `settings-controller.ts` became one `export *` surface over `controller/` (core, shortcut, results, library, player, info and toast). A write across concerns became a small function of the module that owns the state (`dismissLibraryOverlays`, `forgetMissingItems`, `clearFeedback`, `forgetInfo`, `playerHidden`). The page tests drive the page through its entry, so they stayed beside it.
- **Developer tooling.** The 83 files of `scripts/lib/` were grouped into `runner/`, `acceptance/`, `verification/`, `audio/` and `release/`; entry points stayed at the top. `lineTime` moved to `runner/log-reader.mts` and `command` to `runner/processes.mts`, so `runner/` and `verification/` no longer import `acceptance/`. The website's imports and `website.yml`'s path filters followed `release/`. `pnpm audio:quality` reports now key their implementation hashes by the new paths (`./lib/audio/…`), so reports from before 2026-10-06 do not match them by key.
- **Boundaries.** `tests/source-boundaries.test.ts` now covers `scripts/` as well: nothing in `src/` imports `scripts/`, the `scripts/lib/` groups import one way and never an entry point, and fixtures import only `src/`, `scripts/lib/` and other fixtures. A planted violation in each tree failed it.
- **A defect the move introduced.** The path rewrite also changed the import text the update and controlled runners inject into a copy of `index.ts` (`../../scripts/fixtures/…`), as though it were the runners' own import. No unit test builds the patched copy, so only the similar string in `runtime-inputs.test.ts` failed. All three were restored before any runner ran, and both runners then built their patched copies and passed.

## Plan 065 closure — 2026-10-03

Plan 065 lets the recording shortcut and a left click on the status item cancel a start that has lasted a second, as the menu's Cancel recording already did. Claude implemented it, with Codex GPT-6.1 Sol review. Before it `Recorder.toggle()` ignored every press while starting: a start that waited 120 s on a pending capture request could be escaped only through the menu, the press left no log line, and a quit during it waited for the capture request (once 286 s). The durable rules are in [recording design](../system-design/recording.md#countdown), [desktop design](../system-design/desktop.md#recording-shortcut), [acceptance](../acceptance.md#additional-cases-by-impact) and [tooling](../system-design/tooling.md#tray-acceptance).

- **Measurement and decision.** The retained log of 2026-09-12 to 2026-10-02 held 739 starts: median 289 ms, 95th percentile 396 ms. All nine over 1 s waited in preparation (1.1–9.4 s for permission denials, a missing audio track and the earlier 8 s limit; 120 s four times while the capture request stayed pending, one of them held a quit for 286 s), none in opening the folder, one after `record` (2026-09-13). Of 917 logged shortcut presses, the human double presses under 1 s were 290, 365 and 393 ms apart; the ~600 ms pairs were runners cancelling countdowns; the only presses that landed in starting were plan 063's runner, 4–8 ms after the start. On 2026-10-03 the maintainer chose: (a) a 1 s grace; (b) the starting Cancel recording names the shortcut; (c) quit while opening or preparing cancels at once, brought into this plan. The plan's controlled reproduction of a long start became the native round below, since the log already attributed every long start to its phase.
- **Recorder.** While starting, a toggle at least `START_CANCEL_GRACE_MS` (1000 ms) after the session's request, on the monotonic clock, calls the Cancel recording path: opening or preparing is cancelled with no file, failure entry or notification, and after `record` it becomes stop-on-start. A press within the grace, and any press while stopping, is ignored and logged. `shutdown()` cancels an attempt still opening or preparing inside its deferred check, so no second quit attempt can start from the synchronous state change, and the mark stays as a fallback; sleep still only marks.
- **Tray.** The starting menu's Cancel recording carries the registered shortcut as its accelerator and its tooltip names it, in both languages, as the countdown's does.
- **Tooling.** The controlled build has a `prepare=hold` fault and `release prepare`, which hold the capture host's `prepared` reply in main. `pnpm acceptance:tray -- --long-start <run>` drives that build's real shortcut, status item and Quit; the command-channel client moved to `scripts/lib/acceptance/controlled-client.mts`.

## Plan 063 closure — 2026-10-02

Plan 063 made the native tray, Settings-entry and notification-text cases scriptable and stated when a runner or Computer Use applies. Claude implemented it, with Codex GPT-6.1 Sol review. Before it the acceptance skill sent every native operation to Computer Use, which cannot reach the tray-only process (`-10005 timeoutReached`), so tray cases waited for the maintainer or were blocked, and no document said when a script should be chosen instead. The durable rules are in the [selection rule](../testing.md#scripted-runner-or-computer-use), the [runner table](../acceptance.md#scripted-runner-or-computer-use), [scripted native acceptance](../system-design/tooling.md#scripted-native-acceptance) and [design decisions](../system-design/decisions.md).

- **Selection rule and decision.** Testing and acceptance now say: use a committed runner when one covers the operation, Computer Use to observe and for what no runner covers, the maintainer for subjective and password steps, and label scripted input, Computer Use observation and manual evidence apart. On 2026-10-02 the maintainer allowed committed runners to operate RecordStuff's own tray menu, Settings window and menu items under recorded limits (tested bundle by path and pid, a right-click rather than `AXPress` on the status item, no permission prompt, TCC or privacy list, no global kill or test hook).
- **App change.** The tray logs `tray: menu opened in <state>: <json>` with the menu Electron is given each time it pops up, so a runner can compare the NSMenu it reads with the production model. Nothing else in the app changed; `DEFERRAL_MESSAGE` is exported so a test ties the notification runner's expected text to it.
- **Runners.** A JavaScript for Automation helper reads Accessibility through the C API in about 0.1 s (System Events took 29 s for the same menu) and posts CoreGraphics events. `pnpm acceptance:tray` drives the real status item; `pnpm acceptance:settings-shortcut -- --observe` asserts the Settings window's activation, focus, Tab, minimize, restore, close and reopen; `pnpm acceptance:quit-dialog` gained a banner-text layer read from Notification Center. The acceptance skill now selects and runs these runners and keeps Computer Use for visual judgments of their screenshots and for operations without a runner. At closure the maintainer chose to make it executor-agnostic and renamed it from `astra-acceptance-with-computer-use` to [`native-acceptance`](../../.agents/skills/native-acceptance/SKILL.md): any agent that can run commands and see screenshots, as Claude did here, runs the runners and judges `screencapture` images itself, and Codex GPT-6 Astra is delegated only for live Computer Use operations.
- **Found on the real desktop.** On macOS 26 status items live in Control Center's windows. Once `REC` widened the item, the copy on the 1080 pt portrait display was crowded out by the front app's menus (its window off screen) while AX still reported its frame, so the first round's recording menu never opened and the recording ran about three minutes before it was stopped with the shortcut and saved. The driver now clicks the on-screen window named by the bundle identifier on the primary menu bar when the reported copy is hidden. Posting the click to the process (`CGEventPostToPid` to RecordStuff or Control Center, four variants) left the pointer alone but never opened the menu, so a click moves the real pointer and a round needs the desktop handoff. The second round exposed three runner bugs, fixed before the passing round: a nested menu case settled the countdown it was reading, a quit waited for a menu that could no longer be read, and the Traditional Chinese unread-failure line was matched only by its prefix. Keyboard navigation of the popped-up menu worked under CoreGraphics input, unlike 048's attempt.
