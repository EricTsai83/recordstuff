# 094 — 工作室的「相機」預覽來源

[English](094-studio-camera-view.md) | [繁體中文](094-studio-camera-view.zh-TW.md)

狀態：已規劃、尚未開始。建立：2026-10-23，依維護者要求，從 092 拆出（原本是 092 D3 的「相機」來源），因為它是那個計畫最大的一塊：兩個平台都要新增一組 compositor 參數，錄影前還要一條頁面端的路徑。硬性相依：092（它的 `view` 訊息與 Studio baseline）與 090（相機能穩定送出第一格）。佇列第五個，在 092 之後、084 之前，讓 084 在 port 上所有訊息都存在後再為它設上限。依[計畫索引](README.zh-TW.md)順序執行。本次只寫計畫，以下行為都尚未實作或驗證。

## 目標與現況

092 之後，Studio 的預覽可以顯示合成畫面或只有螢幕。使用者無法用夠大的尺寸檢查相機本身（構圖、光線、對焦）：在合成畫面中，泡泡只佔 391 × 220 預覽區的一小部分。「相機」來源只顯示相機、放大，且不改變錄出的內容。

## 決定（維護者，2026-10-23）

- **D1 — 「相機」來源**加入 092 的來源分段按鈕：**合成／螢幕／相機**。預覽區維持原大小與錄影的比例。「相機」只畫相機，放大到預覽區內最大、置中，長寬比與圓角和錄影裡合成的泡泡相同；外框隱藏。只改預覽：錄出來的永遠是合成畫面。

## 步驟與責任

- [ ] **引擎端。** `camera` 成為 092 `view` 訊息的一個值。在 `camera_layout.rs` 新增一組參數：泡泡裁切以預覽輸出中最大的尺寸置中、不畫螢幕、周圍用預覽區背景色；錄影的 `compose` 不動。相機從完整的 1280 × 720 畫面取樣，而不是從合成畫面裁切，所以放大後仍然清楚。切換來源時強制出 key frame，與 092 相同。兩個平台的 compositor 都有參數的 Rust 測試，包括錄影參數不隨來源改變。
- [ ] **頁面端。** 第三個分段、「相機」時隱藏外框，以及沒有畫面的情況：session 開始前，「相機」放大頁面自己的相機（`getUserMedia`，預覽開啟時 Studio 會為泡泡開啟），套同樣的比例與圓角，因此不會再開第二個相機擷取；相機中斷、尚未就緒（090）或被隱藏時顯示佔位畫面並說明原因。只用正式元件與 CSS，依 [UI 對齊規則](../docs/zh-TW/testing.md#測試-ui-與-app-保持一致)。
- [ ] **量測與文件。** 用 `measure:cpu` 量只是看著的 Studio，涵蓋「省電」與「標準」，在同一輪中以相同的相機與音訊輸入連續量「合成」與「相機」來源（差異很小，依[測試政策](../docs/zh-TW/testing.md#縮短錄影回合)；結論取決於這個差異時以 A、B、A 重複）：「相機」來源合成的東西比「合成」少，成本不得超過這個對照組的範圍。092 的 Studio 數據只作參考，因為它們是在沒有相機的情況下量的。錄一段有相機的影片並切入、切出「相機」，確認檔案是合成畫面。更新 [recording](../docs/zh-TW/system-design/recording.md) 中 Studio 的段落與翻譯。

## 門檻與完成條件

「相機」來源的比例與圓角在 session 前與 session 中都和合成的泡泡一致；切換來源從不改變錄出的檔案，也從不讓錄影卡住或失敗；同一幀率下的 CPU 在旁邊量的「合成」對照組範圍內。

## 驗證

focused 測試（`pnpm test:scope -- studio`、參數的 Rust 測試）；引擎變更跑 `pnpm check`。在新的簽章 bundle 上、經「好了」交接後做一輪桌面測試，經維護者同意才開相機：`pnpm acceptance:studio`、CPU 案例、一段以 `pnpm verify` 檢查的錄影，並以肉眼比對「相機」來源與合成泡泡的形狀。Windows 只經 CI。

## 執行與結案契約

依[計畫索引](README.zh-TW.md)處理順序、決定點、桌面交接與結案；保留 capture process 的故障隔離，以及預覽失敗不讓錄影失敗。開始執行時先看當時的程式碼與 090、092 的結案紀錄。
