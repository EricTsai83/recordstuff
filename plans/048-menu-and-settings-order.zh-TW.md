# 048 — 選單列選單與設定的順序

[English](048-menu-and-settings-order.md) | [繁體中文](048-menu-and-settings-order.zh-TW.md)

狀態：已規劃，尚未實作。建立日期：2026-09-27。排在 [047](047-failure-history-tab.zh-TW.md) 之後、[035](035-guided-native-acceptance.zh-TW.md) 之前，035 仍在最後。本計畫與 045–047 沒有硬性相依；047 也會改動設定分頁，046 會新增一個錄影群組，所以本計畫排序的是兩者完成後的結果。執行順序見[佇列](README.zh-TW.md#順序與狀態)。

## 目的與範圍

維護者於 2026-09-27 要求檢查 UI 呈現資訊的順序，尤其是右鍵選單的順序是否正常。本計畫檢查[選單列模型](../src/main/tray-model.ts)在每個狀態下的內容與[設定群組](../src/main/settings-model.ts)，提出一致的順序，並實作維護者核可的順序。

範圍內：選單列選單項目的順序與分組、少數影響瀏覽的選單慣例（省略號、選單中顯示的快捷鍵、「結束」的標籤）、一個「開始錄製」項目，以及設定群組的順序。範圍外：失敗紀錄本身（由 [047](047-failure-history-tab.zh-TW.md) 排序）、倒數（[045](045-countdown-digit-scaling.zh-TW.md)、[046](046-countdown-sound.zh-TW.md)）、此處列出的標籤以外的文字修改、通知與對話框（各只有一則訊息，沒有順序可調），以及左鍵行為。

## 目前的順序與發現

選單是每次按右鍵時依狀態重建的扁平清單（[桌面設計](../docs/zh-TW/system-design/desktop.md#tray-與通知)）。以下是目前兩種情況：失敗已確認後的待命狀態，以及有未讀失敗時的錄製中狀態：

```text
最近一次失敗：<原因>             （停用）
查看失敗紀錄…
────────────
待命 — <螢幕>                    （停用）
顯示最後一個錄影
────────────
儲存位置：~/Movies/RecordStuff
更改儲存位置
────────────
設定 (⌥⌘,)
顯示 log
結束
```

```text
尚未確認的錄影失敗：1 筆         （停用）
查看失敗紀錄…
────────────
錄製中                           （停用）
停止
────────────
儲存位置：~/Movies/RecordStuff   （停用）
更改儲存位置                     （停用）
────────────
設定 (⌥⌘,)
顯示 log
結束
```

1. **失敗排在狀態之前。**只要保有任何失敗紀錄，失敗相關的行就會出現在每個選單的最上方，排在狀態行與該狀態的主要動作之前。錄製中時，「停止」是第四行。
2. **已確認的失敗永遠不會離開頂端。**所有失敗都確認後，「最近一次失敗：<原因>」與「查看失敗紀錄…」仍排在最前面，直到紀錄清空為止；而已確認的紀錄最多保留 20 筆，所以一次很久以前的失敗可能長期佔據選單開頭。
3. **沒有「開始」項目。**錄製中有「停止」、倒數中有「取消倒數」，待命時卻沒有開始的方式；模型本身的註解也把開始／停止列為選單列指令。目前只有左鍵能開始。
4. **檔案相關項目被拆開。**「顯示最後一個錄影」放在狀態群組，與儲存位置項目分開。
5. **「結束」沒有獨立出來。**「設定」、「顯示 log」與「結束」同在一組。一般的選單以及 [Cap 的選單列](https://github.com/CapSoftware/Cap/blob/119edf04864b59abfc0d52f60bf77d7f33cfd2b8/apps/desktop/src-tauri/src/tray.rs#L577-L620)都把「結束」放在最後一組；Cap 的標籤是「Quit Cap」。
6. **慣例不一致。**「查看失敗紀錄…」有省略號，「設定」（開啟視窗）與「更改儲存位置」（開啟對話框）卻沒有。設定快捷鍵直接寫進標籤「設定 (⌥⌘,)」，錄影快捷鍵則只出現在「停止」與「取消倒數」的 tooltip，而不是像原生選單那樣靠右顯示。
7. **「一般」把維護項目排在日常偏好之前。**「一般」依序為快捷鍵、通知、更新、語言、外觀、關於，所以語言與外觀排在更新控制項下面。「錄影」依序為螢幕、倒數、影片品質、解析度上限、影格率，已經是「錄什麼、何時開始、錄成什麼樣」的順序。
8. **儲存位置是唯一不在設定中的已儲存偏好。**它只能從選單列查看與更改，但設定視窗其實已經能從失敗紀錄開啟選擇資料夾的對話框。

[Cap 的選單列](https://github.com/CapSoftware/Cap/blob/119edf04864b59abfc0d52f60bf77d7f33cfd2b8/apps/desktop/src-tauri/src/tray.rs#L471-L620)（固定 revision 的靜態檢視，未執行）依使用情境排序：先是動作（Open Main Window、Record Display…、Import Media…），再來是模式與最近的項目，接著是視窗（View all recordings、View all screenshots、Settings），最後是 Upload Logs、版本與 Quit Cap。

## 建議的順序

以下為初始提案，待下方的維護者檢視確認。每個狀態都使用同樣的群組、同樣的順序，沒有內容的群組就省略，所以同一個項目在不同狀態之間不會換位置：

1. **狀態：**狀態行，接著是該狀態的主要動作：「開始錄製」（待命）、「停止」（錄製中）、「取消倒數」（倒數中），或權限步驟（需要權限）。待命時的「上次螢幕錯誤」仍緊接在狀態行下方。
2. **未讀失敗：**只在有未讀時出現：「尚未確認的錄影失敗：n 筆」與「查看失敗紀錄…」。
3. **檔案：**「顯示最後一個錄影」、「儲存位置」、「更改儲存位置…」。
4. **視窗：**保有失敗紀錄但都已確認時的「查看失敗紀錄…」（不再顯示「最近一次失敗：<原因>」），接著是「設定…」；設定快捷鍵無法使用時，說明行放在它下方。
5. **App：**「顯示 log」、「結束 RecordStuff」。

```text
待命 — <螢幕>                    （停用）
開始錄製                    ⇧⌘1
────────────
尚未確認的錄影失敗：1 筆         （停用）
查看失敗紀錄…
────────────
顯示最後一個錄影
儲存位置：~/Movies/RecordStuff
更改儲存位置…
────────────
設定…                       ⌥⌘,
────────────
顯示 log
結束 RecordStuff
```

設定：「錄影」維持螢幕、倒數、倒數音效（046）、影片品質、解析度上限、影格率；若維護者接受下方第 6 項決定，儲存位置排在螢幕之後。「一般」改為快捷鍵、通知、語言、外觀、更新、關於，讓日常偏好在前、維護項目放在「關於」頁尾旁；Cap 也把版本與檢查更新放在設定側欄的底部。

## 實作約定

- [ ] **先由維護者檢視。**讓維護者看待命（沒有失敗、有未讀失敗、只有已確認的失敗）、需要權限、倒數中與錄製中的目前與建議選單，以及建議的設定順序，形式可以是像上方的文字示意或截圖。實作前把每項決定寫入本計畫：(1) 新增「開始錄製」；(2) 失敗群組依提案安排；(3)「結束 RecordStuff」／「Quit RecordStuff」；(4) 快捷鍵在選單中靠右顯示；(5)「一般」的順序；(6) 在「設定 → 錄影」新增儲存位置列，並保留選單列項目。被否決的項目從本約定中移除。
- [ ] **選單列順序。**[tray-model.ts](../src/main/tray-model.ts) 依序以五個群組組成每個狀態，不產生開頭、結尾或連續的分隔線，tooltip 維持不變。停用的項目維持停用而不隱藏，所以錄製中的選單仍保留灰色的儲存位置。
- [ ] **開始錄製。**新增 `start` 動作，只要左鍵點擊會開始錄影，待命狀態就顯示此項目，標籤為「開始錄製」／「Start recording」，與選單列既有的「錄製中」一致。它的行為與左鍵完全相同，包括倒數。因為 macOS 已開啟的選單無法更新（[桌面設計](../docs/zh-TW/system-design/desktop.md#tray-與通知)），選取時依當下狀態判斷：只在待命時開始，其他狀態不做任何事並寫 log，所以過時的「開始」永遠不會停止錄影或取消倒數。
- [ ] **選單慣例。**「設定…」與「更改儲存位置…」加上省略號。「開始錄製」、「停止」與「取消倒數」以靠右的原生快捷鍵顯示已註冊的錄影快捷鍵，「設定…」顯示已註冊的設定快捷鍵（`accelerator` 搭配 `registerAccelerator: false`），選單不會再註冊第二個全域快捷鍵。快捷鍵未註冊時不顯示，既有的 tooltip 保留。若原生檢查發現選單列的 `popUpContextMenu` 不會畫出這些快捷鍵，就保留目前的文字與 tooltip，並記錄原因。
- [ ] **設定順序。**[settings-model.ts](../src/main/settings-model.ts) 依提案排列「一般」；區段標題、鎖定註腳與「關於」頁尾跟著各自的群組移動。若接受第 6 項決定，「錄影」分頁在螢幕之後新增儲存位置列，顯示路徑並提供「更改…」與「在 Finder 中顯示」，沿用既有的 `changeOutputDir` 與 `openOutputDir` 處理及其鎖定；選單列項目保留。
- [ ] **翻譯與文件。**新增與修改的標籤提供英文與繁體中文。同步更新雙語的桌面設計選單列段落與狀態表、設定視窗段落、驗收指南的選單列列，以及英文網站「Right-click for Settings, your output folder and logs」一句（若其暗示的順序改變）。

## 驗證與排除

- [ ] 單元測試：每個狀態在沒有紀錄、有未讀失敗與只有已確認失敗時，兩種語言下的完整項目順序與分隔線；只有已確認失敗時，視窗群組中的項目且沒有「最近一次失敗」行；「開始錄製」恰好在左鍵會開始時啟用；待命以外的過時「開始」被忽略；只有已註冊的快捷鍵才顯示；說明行位於「設定…」下方；兩個分頁的設定群組順序，包括 046 的群組，以及（若接受）儲存位置列與其鎖定。
- [ ] `pnpm acceptance:regression`（設定順序有變更；已包含 `pnpm check`），並檢查兩種語言的設定畫面截圖。
- [ ] 以新的 `pnpm start:app` bundle，透過[原生驗收 skill](../.agents/skills/astra-acceptance-with-computer-use/SKILL.md)或對選單列項目執行 Accessibility 動作，在待命、倒數中與錄製中開啟選單並截圖，涵蓋兩種語言與淺色、深色：檢查順序、分隔線，以及靠右快捷鍵是否出現。從「開始錄製」開始一段短錄影並以「停止」結束，再驗證並播放檔案；這個新入口會走錄影開始路徑。若無法操作選單列（040 時 computer use 就遇到這個問題），記為 blocked 並移交 035。
- [ ] 若網站有變更：`pnpm site:check`，並檢查變更的頁面。
- [ ] 排除：擷取與編碼（「開始」呼叫既有的開始流程）、倒數、失敗紀錄（047）、通知與對話框，以及 Windows 外觀（選單列模型共用，但只驗證 macOS）。
