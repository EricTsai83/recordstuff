# 035 — 最後一輪：由維護者操作的原生驗收

[English](035-guided-native-acceptance.md) | [繁體中文](035-guided-native-acceptance.zh-TW.md)

狀態：已規劃，尚未執行。建立日期：2026-09-25。此計畫固定排在[佇列](README.zh-TW.md#順序與狀態)最後；目前為 033、034、037、040、042 與 043 之後。之後新增的實作／修復計畫也排在本項之前，不以編號大小改變此規則。這是清空計畫前的最後一項，不是現在開始操作。

## 目的與責任

補齊錄影失敗 UX 本次未經原生操作的全部項目，並在開始時彙整前序計畫新增、仍未驗證的必要原生案例。由 Codex 準備建置、可逆測試環境及逐步指引，**維護者親自操作每項原生案例至少一次**；Codex 記錄觀察、核對 log／產物及追蹤失敗。不能以 fixture、單元測試、腳本送鍵或代理代按取代使用者這一輪操作。

依[共用測試政策](../docs/zh-TW/testing.md)、[驗收指南](../docs/zh-TW/acceptance.md)與[原生驗收 skill](../.agents/skills/astra-acceptance-with-computer-use/SKILL.md)的產物、證據與清理規則執行。此處由維護者代替 agent 操作桌面，因此先前 computer-use 無 desktop/tray target 的限制不代表不能做人工驗收；若 agent 仍看不到畫面，以維護者回報標註「人工觀察」，不可偽稱工具已觀察。

背景：[本次驗證紀錄](../docs/zh-TW/verification/history-2026-09.md#錄影失敗結果--2026-09-25)。589 個單元測試、86 個設定 fixture 案例不能證明原生警告圖示、原生錯誤結果互動或錯誤通知點擊通過；這三組先前受阻，本計畫將其拆成下表的可操作案例。

## 執行前準備

- [ ] 等所有其他實作／修復計畫完成，再依最終原始碼、驗證歷史、前序計畫的 blocked／not run 清單，產生本輪最終案例清單。每項列來源、平台、觸發條件、預期結果及證據；舊的已明確豁免項不得默默改成通過，也不自動擴大成所有歷史未測項。前序計畫新增的必要原生缺口要納入本項，不能遺漏。
- [ ] 核對最新結果持久化實作與本表一致：各筆失敗及確認狀態跨重啟保留；pending 轉為無法確認、重新檢查檔案但不保證可播放。不額外掃描其他遺留檔案。
- [ ] Codex 先完成適用的自動檢查；記錄 source revision／dirty diff、App 版本、bundle 路徑與雜湊、OS、螢幕、音訊及原偏好。macOS 以 `pnpm start:app` 產生全新已簽章 bundle，Windows 使用 034 已確認的原生啟動方式，不拿 macOS runner 代替。
- [ ] 建立專用臨時輸出資料夾與有限容量測試磁碟映像；限制測試容量及時長，不填滿系統碟、不改使用者原輸出資料夾權限、不拔除含使用者資料的裝置。觸發故障前說明將發生什麼、只影響哪個測試資源與還原方式。
- [ ] Codex 先寫好每種故障的可重現操作配方，記錄會觸發哪個正式錯誤路徑。無法穩定觸發的 pending／unknown／重疊錯誤可另準備明確標識的開發測試 bundle；必須走正式結果處理與 UI，不能直接改 DOM。受控狀態只能證明原生 UI，不能冒充真實磁碟或捕捉故障。這類測試支援如需程式修改，先列修復／支援工作在本項之前，完成 review 與必要檢查後再請維護者操作。
- [ ] 每次只有一位桌面操作者；先詢問維護者是否準備好開始本輪，而非直接開始錄影。這是實際驗收時的協作安排，不是新增計畫時索取同意。

## 帶領方式

每次只給一個短步驟，使用使用者看得見的名稱；格式為「現在操作 → 應該看到 → 請回報看到什麼」。等回覆或實際觀察後才進下一步，不一次丟整張清單要求自行驗。相同動作可覆蓋多個案例，但每個案例分別記結果。需要截圖時再於正常對話請求；log 不能代替圖示、焦點、Finder 置前或橫幅的人工觀察。

每個狀態等候最多 30 秒。沒有看到、結果不同或無法執行即標 fail／blocked，記錄步驟、畫面與時間；不要無限重試。找到 bug 時先列明問題，再修復與重建，重驗受影響案例；此計畫繼續保持最後一項，不能先刪除它再留下後續修復。

## 倒數追加驗收（尚未操作）

來源：[040](040-recording-countdown.zh-TW.md)。依其最終時間與外觀數值準備操作步驟。

- [ ] N32：使用預設 3 秒，分別以點選單列圖示與 ⌘⇧1 各開始一次，並在淺色與深色選單列各試一次。觀察先出現忙碌圖示（沙漏），再出現不帶數字的碼錶，最後是實心圓加 REC；除了 REC 以外，項目寬度不變。判斷右上角不帶方框的數字在白色文件、深色 App 與亮色照片上是否夠透明又看得清楚，並播放每個檔案確認影片中從未出現該數字。
- [ ] N33：分別以第二次點擊、快捷鍵、選單的「取消倒數」與結束 App 取消倒數。每種方式都回到 idle 並保留「顯示上一段錄影」，不留下檔案、失敗紀錄或通知；結束 App 能正常退出。
- [ ] N34：倒數期間持續在文字編輯器打字（按鍵留在該 App，RecordStuff 未被啟用），並點擊穿過數字。再分別於全螢幕 App 上、選擇副螢幕時（數字出現在該螢幕）、開啟「減少動態效果」與「減少透明度」時，以及上一次的儲存通知仍在右上角時各試一次。記錄 VoiceOver 實際朗讀的內容（若有）；此項不是通過門檻。
- [ ] N35：選擇關閉（錄影開始時不出現數字），再試 5 秒與 10 秒（兩位數放得下）；確認倒數與錄影期間此群組被鎖定，以及沒有此欄位的既有設定檔在更新後以 3 秒開始。
