# 045 — 倒數數字依螢幕大小縮放

[English](045-countdown-digit-scaling.md) | [繁體中文](045-countdown-digit-scaling.zh-TW.md)

狀態：已規劃，尚未實作。建立日期：2026-09-27。排在 [035](035-guided-native-acceptance.zh-TW.md) 之前，035 仍在最後。執行順序見[佇列](README.zh-TW.md#順序與狀態)。

## 目的與範圍

倒數數字（[桌面設計](../docs/zh-TW/system-design/desktop.md#倒數-overlay)）在每個螢幕上都一樣：88 × 88 pt 視窗內的 SF Pro Rounded 56 pt。維護者的主螢幕是 27 吋 1920 × 1080、短邊 1080 pt 的面板（[040 結案](../docs/zh-TW/verification/history-2026-09.md#plan-040-結案--2026-09-26)），字級約為螢幕高度的 5%；維護者於 2026-09-27 回報數字太小，應依螢幕大小調整。本計畫讓數字大小成為被錄螢幕的固定比例，使筆電、大型外接螢幕與直立螢幕上看起來一致。

040 的其他選擇全部保留：右上角位置與邊距、28% 白色且沒有方框、背景、邊框、圓環或模糊、字型與字重、減少動態效果與減少透明度的變化、所有時間數值（包括擷取前 300 ms 的提前量）、取消方式、選單列與設定。不在設定中新增大小選項，數字也不移到螢幕中央。

縮放依螢幕的邏輯尺寸（pt），不依實體尺寸：Electron 的 `Display` 提供 pt 與縮放倍率，但沒有實體尺寸；而且螢幕越大通常觀看距離越遠，同樣的螢幕比例在各螢幕上讀起來相近。

## 縮放規則

以下為初始目標，由下方第一步的維護者選擇取代：

- **基準長度：**被錄螢幕 `bounds` 的短邊。不使用工作區，因為 Dock 的位置與自動隱藏會改變數字大小。取短邊讓直立螢幕與同一面板橫放時的數字相同。
- **字級：**基準長度的 10%，限制在 56–216 pt。下限就是目前的大小，任何螢幕上的數字都不會變小；上限在 1× 的 4K 螢幕（2160 pt）才會達到，只用來約束異常大的虛擬螢幕。
- **視窗：**邊長為字級 × 88 / 56 的正方形，四捨五入到整數 pt，維持 040 的數字與視窗比例，讓「10」仍放得下。頁面由視窗推得字級，實際字級為視窗邊長 × 56 / 88。
- **邊距：**維持距工作區右緣 16 pt、頂端下方 12 pt。視窗內的透明邊界會一起變大，因此數字變大時會稍微遠離角落。
- **外框與陰影：**與字級成比例，因此在 56 pt 時與 040 的數值完全相同，包括減少透明度時的外框。

| 短邊（範例） | 字級 | 視窗 |
| --- | --- | --- |
| 768 pt（1366 × 768） | 77 pt | 121 pt |
| 982 pt（14 吋 MacBook Pro 預設） | 98 pt | 154 pt |
| 1080 pt（維護者的 1920 × 1080 主螢幕與 1080 × 1920 直立螢幕） | 108 pt | 170 pt |
| 1440 pt（27 吋 5K 預設，2560 × 1440） | 144 pt | 226 pt |
| 2160 pt 以上 | 216 pt（上限） | 339 pt |

## 實作約定

- [ ] **先由維護者選擇。**修改原始碼前，讓維護者看短邊 8、10、12 與 14% 的數字（在 1080 pt 主螢幕上為 86、108、130 與 151 pt），畫在實際位置、使用實際的顏色、外框與陰影，分別疊在深色 App、白色文件與亮色照片上。在該螢幕全螢幕開啟的靜態 HTML 草稿即可；草稿不是 repo 內的檔案。實作前把選定的比例，以及維護者要求的上下限或邊距變更寫入本計畫；若維持 10%，也要寫明。
- [ ] **共用數值。**在 [shared/countdown.ts](../src/shared/countdown.ts) 以縮放常數（比例、字級上下限、數字與視窗比例）取代固定的 `sizePt` 與 `font.sizePt`，每個都註明是初始目標或維護者的選擇，模組仍不 import Electron 或 DOM。`overlayBounds` 接收螢幕的 bounds 與工作區，以整數 pt 回傳縮放後、邊距不變的正方形。
- [ ] **Overlay 頁面。**[renderer/countdown.ts](../src/renderer/countdown.ts) 與 [countdown.css](../src/renderer/countdown.css) 以 viewport 單位（`vmin`）依視窗決定數字大小，外框寬度與陰影的位移和模糊改用 `em`。視窗 bounds 成為唯一承載大小的來源：preload、數值 channel，以及「頁面只呈現 main 傳來的內容」的規則都不變，不新增 IPC。custom property 仍透過 CSSOM 設定，頁面的 CSP 允許這種寫法。
- [ ] **Overlay 視窗。**[countdown-overlay.ts](../src/main/countdown-overlay.ts) 以主螢幕縮放後的 bounds 建立視窗，並在 `show` 中、送出第一個數值前設定被錄螢幕縮放後的 bounds，就像現在設定位置一樣。位置 log 行維持 [countdown-evidence](../scripts/lib/countdown-evidence.mts) 解析的格式，改為回報縮放後的大小。視窗以不透明度 0 顯示並在 120 ms 內淡入，所以在大小不同的螢幕之間調整尺寸時，不應出現舊尺寸的畫格；若下方的原生檢查看到了，就在 main 中修正，不讓頁面取得回傳管道。視窗選項、層級、焦點與點擊穿透都不變。
- [ ] **證據工具。**`digitRegion` 已能把任何記錄下來的視窗換算到錄影畫格；在其測試中加入縮放後的視窗（例如 1920 × 1080 螢幕上的 170 × 170 pt）。預期不需修改 runner；若較大的裁切區域暴露出區域或閃光畫格邏輯的問題，就在該處修正。
- [ ] **文件。**同步更新雙語文件：桌面設計的倒數 overlay 段落（以規則與範例取代 88 × 88 pt 與 56 pt）、[函式參考](../docs/zh-TW/system-design/functions.md)中 `overlayBounds` 的說明、[設計決策](../docs/zh-TW/system-design/decisions.md)的倒數列（數字隨被錄螢幕縮放），以及[驗收指南](../docs/zh-TW/acceptance.md)的倒數列（數字大小適合每個螢幕）。網站文案寫的是「a faint 3, 2, 1」，仍然正確；把首頁場景（1600 × 900 的場景）中的數字與選定比例比較，只有在已不能代表 App 時才調整大小。

## 驗證與排除

- [ ] 單元測試：`overlayBounds` 在橫放螢幕、短邊相同的直立螢幕（大小相同，位於該螢幕右上角）、被限制到下限的小螢幕（88 pt，即目前的視窗）、被限制到上限的大螢幕、四捨五入，以及原點為負值的副螢幕。以假視窗測試 overlay：以主螢幕縮放後的 bounds 建立、在第一個數值前以被錄螢幕縮放後的 bounds 呼叫 `setBounds`，以及帶縮放後大小的 log 行。頁面：`overlayStyle` 以 `vmin` 設定數字大小、以 `em` 設定外框與陰影，且在 88 pt 視窗下換算成 040 的 56 px 字級、1 px 與 1.5 px 外框及原本的陰影數值。證據解析與區域換算在縮放後視窗下的結果。
- [ ] `pnpm check`。設定面板、文字與 IPC 都沒變，因此不需要 `pnpm acceptance:settings` 與 `pnpm acceptance:regression`。
- [ ] 以新的 `pnpm start:app` bundle、預設 3 秒跑一輪 `pnpm acceptance -- --skip-cancel`：log 為被錄螢幕放置預期大小的視窗，檔案通過媒體驗證，且變大後的數字區域在前 15 個畫格的裁切，與 2 秒後相同閃光相位的畫格差異在門檻 3 以內，證明變大的數字仍不會出現在錄影中。取消與退出路徑都沒有變更，所以略過取消案例。
- [ ] 代理透過[原生驗收 skill](../.agents/skills/astra-acceptance-with-computer-use/SKILL.md) 或截圖做原生觀察，以快捷鍵開始（040 時 computer use 無法點擊選單列）：1080 pt 主螢幕上倒數中的數字；選擇直立副螢幕後的數字（大小相同，位於該螢幕右上角）；以及 10 秒倒數中的兩位數「10」，之後取消（確認放得進視窗；不需要錄影）。若有短邊不同的螢幕可用（例如內建螢幕），也在該螢幕擷取一次倒數，並觀察第一個數字是否有尺寸跳動；否則把該案例記為 not run。
- [ ] 若調整了首頁場景：`pnpm site:check`，並檢查場景暫停時的畫格。
- [ ] 排除：品質與音訊矩陣、長時間錄影、權限、選單列，以及取消與退出路徑（擷取、編碼、開始流程與倒數時間都不變）；鍵盤焦點與點擊穿透（視窗選項不變；仍由 035 的 N34 涵蓋）；Windows 外觀（只驗證 macOS；規則與平台無關，但不宣稱 Windows 外觀）。選定的大小在白色文件、深色 App 與亮色照片上是否合適，由維護者判斷，屬於 035 的 N32。

- [ ] 分列檢查／結果、範圍排除與必要但未驗項目；mock 邊界不是原生證據。缺少前提屬 blocked。實作執行 `git diff --check`。
- [ ] 同步更新雙語的 035：N32 除了透明度也判斷數字大小，N34 的副螢幕案例檢查大小是否跟隨螢幕；並在 035 的核對說明中加入 045。
- [ ] 耐久結論放入雙語設計／驗證文件，更新兩份索引；全部完成後才刪除此計畫與翻譯。不自行 commit、push 或發布。

本次僅規劃，檢查相對連結／anchor、命令名稱、雙語覆蓋與 `git diff --check`；不因寫計畫而 build、跑 App 測試、launch 或錄影。
