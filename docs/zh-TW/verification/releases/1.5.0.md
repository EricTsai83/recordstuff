## 打 tag 前的本機驗收

2026-10-04 由 Claude 在維護者回覆「好了」後執行，原始碼為乾淨的 `c1ec7d1`（macOS 26.6.2、Apple M1 Pro、arm64），當時尚未推送到 main；`node scripts/release.mts preflight v1.5.0` 與 `pnpm check` 均已通過。自 1.4.0 起的 App 變更是系統匣模板圖中較大的待命圓環與錄影圓點；打包設定（electron-builder 檔案、`build/`、App 圖示、DMG 版面）沒有變更，因此未執行 `pnpm dist:mac`，DMG 結構由 CI 驗證。開始前先以正常方式結束了另一個 checkout 正在執行的開發版。

**系統匣。** `pnpm start:app` 建置、簽署（`01B373511530BBF287CA35E54C10A5F017AAD637`）、驗證 9 個 bundle 身分並開啟 `dist/mac-arm64/RecordStuff.app`，其版本為已記錄的 1.4.0；CI 依 tag 蓋上 1.5.0。`pnpm acceptance:tray` 依序以 zh-TW、en 執行：14 通過、1 失敗、1 未執行。待命、倒數與錄影中選單在兩種語言都與 model 相符；從選單開始與停止都已存檔，鍵盤路徑能開啟並關閉 RecordStuff，再點一次與「取消錄影」都能取消，倒數中與待命選單的「結束」都讓所有程序結束。`show-last` 失敗一次：log 指出在 Recordings 開啟了最新錄影，但 RecordStuff 不在最前面、也沒有焦點，因此未送出 ⌘W。以 `--languages en` 重跑時通過（10 通過、1 未執行）：Recordings 開啟且最新錄影的播放鈕有焦點、RecordStuff 在最前面，⌘W 也關閉了視窗。此案例為間歇性，且該功能在 1.4.0 發布時沒有發布回合，不是本版的退化。兩輪的 `stale-start` 都未執行（macOS 先處理了選單的 Start，再處理排隊的快捷鍵）。Claude 判讀了 runner 的選單截圖（分組、分隔線、靠右的快捷鍵、兩種語言的可讀性）以及以 `screencapture` 擷取的選單列：待命圓環清楚，大小與旁邊的圖示相當。

**錄影 smoke。** `pnpm acceptance` 透過 System Events 以快捷鍵在 3 秒倒數（音效開啟）後開始並停止錄影：標準品質、原始解析度上限、60 fps、1920×1080、10.3 秒、40.2 MB、48 kHz 雙聲道 −42.8／−42.8 dBFS，音訊與影片長度差 1 ms、容器起始偏移 0 ms，完整逐幀解碼無錯誤；10 次閃光與 10 個音，所有完整性檢查通過，倒數數字未進入畫面（最差平均差 1.15，門檻 3），兩個倒數音都未進入錄到的音訊，倒數中再按一次即取消，沒有檔案、失敗或通知。`pnpm acceptance:playback` 以 QuickTime 開啟影片，長度 10.29 秒、1920×1080，即時播放，三次跳轉都在 0.25 秒內且畫面跟著變化，並播放到結尾。既有擷取權限正常；系統匣 runner 已還原儲存的語言與圖示點擊設定；素材、QuickTime 與 RecordStuff 都已關閉，沒有殘留程序。回合中執行 caffeinate，結束後已停止。僅存於本機的證據：[系統匣報告](../../../verification/measurements/2026-10-04T13-42-14-847Z-tray-acceptance-hBllWs/report.md)、[系統匣重跑](../../../verification/measurements/2026-10-04T13-45-16-119Z-tray-acceptance-snA4gg/report.md)、[快捷鍵報告](../../../verification/measurements/2026-10-04T13-43-55-338Z-hotkey-acceptance/report.md)、[播放證據](../../../verification/measurements/2026-10-04T13-44-33.025Z-playback-mdThAL/)。保留的影片：`2026-10-04 21-42-26.mp4`、`2026-10-04 21-43-00.mp4`（系統匣，錄的是當下畫面、沒有素材）與 `2026-10-04 21-44-01.mp4`（快捷鍵），以及重跑時的錄影。
