## 現在的問題

錄影離開 RecordStuff 的每條路都交出**原始檔**：從錄影分頁把卡片拖出去（[main](../src/main/index.ts) 的 `startDrag`）、「在 Finder 中顯示」，以及存檔通知（點了會在錄影分頁打開這段錄影，再從那裡拖出去）。沒剪過的一般錄影這樣是對的；其他情況都沒有任何提醒，使用者不知道自己給出去的是什麼：

| 分享的是 | 對方拿到的 | 風險 |
| --- | --- | --- |
| 剪過的一般錄影（085） | 全部片段，包括移除的：剪輯存在 `userData` 的剪輯紀錄，從不寫進檔案 | **高**：隱私，使用者以為已經刪掉 |
| 編輯過的可編輯錄影 | 錄影當時的樣子：移除的片段、靜音的區段、隱藏的相機都還在 | **高**：隱私 |
| 沒編輯的可編輯錄影 | 沒有相機泡泡的螢幕畫面（相機是停用的軌） | 高：不是使用者想給的 |
| 任何可編輯錄影 | 用 VLC 或 ffmpeg 就能抽出麥克風與完整相機畫面 | 中 |
| 任何可編輯錄影 | 一般錄影的兩倍大；剪輯不會跟著過去 | 低，但令人意外 |

這些情況下，匯出檔 `<name> (edited).mp4` 才是對的檔案，但它是「獨立的一段錄影，沒有連回來源」（[剪輯](../docs/zh-TW/system-design/editing.md)）：使用者得知道要選另一張卡片，而它也可能比最新的剪輯舊。

## 一段錄影是什麼（本計畫採用的模型）

一段錄影只有三樣東西，其中只有兩樣是檔案：

| | 是什麼 | 檔案 |
| --- | --- | --- |
| **原始檔** | 錄影當時的樣子，從不寫入（085 的規則） | 一個 |
| **編輯** | 一種狀態：剪輯紀錄（剪掉哪裡、泡泡位置、音量、時段）。app 顯示的「編輯後」是照它即時播放出來的 | 沒有 |
| **儲存的副本** | 使用者要求時，照原始檔＋編輯、以選定的形式算出的檔案 | 零到多個 |

使用者拖出或分享的是一個**版本**：在那一刻從原始檔＋編輯產生的東西。版本不是 app 保存、管理的檔案，而是在離開時才在 app 自己的快取裡做成檔案。所以版本不需要和原始檔保持連結，也不會過期，使用者從來不用管理它。儲存的副本不一樣：那是使用者要求、自己放好的檔案，由使用者保留、改名或刪除，app 只讀取它的來源（見[管理離開的東西](#管理離開的東西)）。

兩種錄影存放輸入的方式不同，所以版本也不同：

| | 一般錄影 | 可編輯錄影 |
| --- | --- | --- |
| 相機 | 錄影當下合成進螢幕畫面，之後拿不出來 | 另存一條軌；螢幕畫面裡沒有泡泡 |
| 麥克風 | 錄影當下和系統聲音混成一條 | 兩者的混音（自 098 起，就是播放器播放的那條），另外每個輸入各一條 |
| 一般播放器看到的 | 有泡泡的螢幕、兩個聲音 | 沒有泡泡的螢幕、兩個聲音 |

## 業界的做法

沒有單一標準，但大家熟悉的 app 收斂成五種模式，本計畫照著做。

1. **非破壞性編輯：原始檔加一份做法，輸出時才算繪。** 「照片」保留原始檔，編輯存成修改紀錄；看到的是修改後的版本，「匯出未修改的原始檔」才給匯入時的檔案（[Macworld](https://www.macworld.com/article/232763/how-to-get-the-best-image-export-from-photos-in-macos.html)）。Screen Studio、Camtasia 與 Final Cut 也都保留錄影或專案，匯出時再算繪（[Screen Studio，匯出](https://www.screen.studio/guide/exporting-the-video)）。
2. **分享預設給你看到的；原始檔是刻意的第二選擇。** 「照片」的「匯出 N 張照片」會套用編輯，未修改的原始檔是另一個指令。
3. **擷取後立刻出現的快速操作區**，不用打開任何東西就能拖、拷貝或儲存：macOS 的截圖縮圖、CleanShot X 的 Quick Access Overlay（可儲存、拷貝或把擷取拖進其他 app，[CleanShot](https://cleanshot.com/features)），以及 Screen Studio 錄完後的 Quick Share widget（分享、儲存、拷貝、編輯，[Screen Studio，Quick Share](https://www.screen.studio/guide/quick-share-widget-)）。本計畫採用這個目的，但不多開視窗：錄影可以分享時才送出存檔通知，點了就到它的卡片，所有動作都已經在那裡（D6）。
4. **輸出依用途命名，而不是技術選項。** Screen Studio 的「匯出成檔案」與「拷貝到剪貼簿」及其 preset，Final Cut 的分享目的地；技術設定放在下一層。
5. **來源和成品分得出來。** 專案型 app 讓來源有自己的文件類型（Screen Studio 專案、Camtasia 的 `.tscproj`），不會被誤當成要寄的東西。RecordStuff 的可編輯原始檔仍是任何播放器都能開的 MP4，這是它們都沒有的優點，所以這裡用檔名來區分（D3）。

## 設計原則

1. **預設離開的，就是使用者在 app 裡看到的。** 剪輯已套用、相機已合成、聲音已混好。
2. **剪掉的東西，沒要求就不會離開。** 隱私是預設。
3. **版本依用途命名。** 介面不出現「音軌」、「alternate」、「stem」，這些字留給文件。
4. **原始檔與素材只差一個刻意的步驟**，從不阻擋。
5. **沒剪過的一般錄影，行為和現在完全一樣。**
6. **每個拖曳都有點擊與鍵盤的替代方式**，並有 VoiceOver 名稱。
7. **使用者管理的是錄影，不是衍生檔案。** 衍生檔案在離開時產生，由 app 清理。

## 版本

| 版本 | 內容 | 提供給 | 離開時的檔名 |
| --- | --- | --- | --- |
| **影片**（預設，標示建議） | app 顯示的樣子：套用剪輯、相機在顯示的地方合成、一條畫面一條聲音 | 所有錄影 | `會議.mp4`（沒剪過的一般錄影就是原始檔本身） |
| **只有聲音** | 影片的聲音，已混好 | 所有錄影 | `會議（聲音）.m4a` |
| **原始檔** | 錄影當時的檔案，含所有軌 | 編輯過或可編輯的錄影 | 可編輯：`會議.recordstuff.mp4`（D3）；一般：`會議（原始）.mp4` |
| **不含相機的影片**（放在「更多」） | 影片，但不放相機 | 有相機的可編輯錄影 | `會議（僅螢幕）.mp4` |
| **素材**（放在「更多」） | 每條軌各自一個檔案，不重新編碼，給 Premiere、Final Cut、DaVinci | 可編輯錄影 | 拖曳或存到：資料夾 `會議 素材/`，內含 `會議 - 螢幕.mp4`、`- 相機.mp4`、`- 系統聲音.m4a`、`- 麥克風.m4a`（只有錄影實際有的）。拷貝：同樣的檔案，不包資料夾（D7） |

剪過的一般錄影，它的影片叫 `會議（剪輯版）.mp4`（D9）。

**只有原始檔做標記；離開的東西都以成品命名。** 專案型的錄影與剪輯軟體都這樣命名：Screen Studio 與 Camtasia 讓來源有自己的文件類型，匯出檔以專案命名；Shotcut 等開源剪輯軟體也以專案名稱匯出（[Shotcut 論壇](https://forum.shotcut.org/t/batch-export-multiple-projects-automatically/11740)）；「照片」匯出編輯後的照片時用原本的名稱，未修改的原始檔是另一個指令。收到的人在乎檔案裝什麼，不在乎有沒有剪過，「已編輯」反而讓人問改了什麼。所以：

- 版本以錄影命名，跟隨 app 的語言（英文為 `Meeting.mp4`），只有和預設形式不同時才加內容標示：`（僅螢幕）`、`（聲音）`、`（剪輯版）`、`（原始）`。macOS 預設隱藏副檔名，所以光靠 `.m4a` 與 `.mp4` 看不出差別，內容要寫在檔名裡，一眼就看得出是什麼（維護者，檢視計畫時）。
- 可編輯原始檔叫 `會議.recordstuff.mp4`，從存檔起就是這個名稱，離開時也一樣（D3）。剪過的一般錄影，刻意交出原始檔時叫 `會議（原始）.mp4`；它在磁碟上的名稱不變。
- **儲存在自己來源旁邊**的副本會和來源同名。只有這時才標示「剪輯版」，就像 iPhone 把編輯過的照片和原始檔一起傳出時命名為 `IMG_E…`（[MacRumors](https://forums.macrumors.com/threads/question-on-iphone-16-pro-max-camera-image-files.2478196/)）：存進一般錄影 `會議.mp4` 所在資料夾的副本叫 `會議（剪輯版）.mp4`，卡片也依檔案內的來源資訊顯示「從『會議』儲存」（D8）。可編輯錄影不會遇到這種情況，因為它的來源是 `會議.recordstuff.mp4`。
- **一般錄影在磁碟上的名稱永遠不變**，剪過也一樣：`（原始）`只是它的原始檔離開時取的名字。所以剪過的一般錄影，它的影片離開時會和來源完全同名，都叫 `會議.mp4`，拖進錄影資料夾時 Finder 會問要不要取代原始檔。D9 把 D8 從副本擴大到所有離開的東西：會和自己來源同名的版本叫 `會議（剪輯版）.mp4`，實際上就是剪過的一般錄影，它的影片一律這樣命名。
- 落點已有其他同名檔案時加數字（`會議 2.mp4`）。不使用 V1、V2 這類版本號：收到 V2 的人會問 V1 在哪、差在哪。在 app 裡，錄影改以時間與形式列出它的副本（D4）。

使用者只需要記住一條規則：**有標記的是原始檔，其他都可以直接給人。**

「不含相機的影片」只出現在可編輯錄影，因為只有它的相機能拿掉；一般錄影的相機已經是畫面的一部分。

## 畫面上怎麼分享

### 1. 拖卡片（大多數人走的路）

**拖出去的是「影片」：卡片播放的樣子就是離開的樣子。** 按住 ⌥ 拖曳則是「原始檔」。沒剪過的一般錄影，影片就是原始檔，所以什麼都沒變。

拖曳開始的那一刻檔案就必須存在（macOS 的限制），而編輯過或可編輯錄影的影片必須算繪（參考機約即時的 6.3 倍：10 分鐘的錄影約 1.5 分鐘）。所以影片要**事先準備**進快取（D2）：剪輯畫面關閉時，以及可編輯錄影存檔時。還沒好之前，卡片畫面上顯示「正在準備影片… 40%」，拖曳不會開始，並說明原因及按住 ⌥ 可拖原始檔（D1）。macOS 原生的 file promise（先開始拖，放下時才寫檔）可以省掉等待，但需要原生模組，而瀏覽器裡的 Slack、Gmail 等網頁 app 不接受；它是之後的選項，不在本計畫內。

**拖曳一律是拷貝，不會搬移。** 「照片」、「音樂」與 Lightroom 都一樣：從資料庫拖出去的是拷貝，資料庫保留自己的檔案。拖「影片」給的是快取裡算好的檔案，不可能搬走錄影；拖「原始檔」（或沒剪過的一般錄影的影片）給的是錄影本身的檔案，而 macOS 在同一顆磁碟內拖曳預設是搬移，除非來源只允許拷貝。步驟 0 檢查 Electron 的 `startDrag` 允許什麼；如果允許搬移，本計畫就限制為只能拷貝。app 內不提供把錄影搬出去的方式：和那些 app 一樣，「在 Finder 中顯示」就是那條路，錄影搬出資料夾後就從分頁消失。

### 2. 分享…（刻意選擇任何版本）

「**分享…**」是卡片 ⋮ 選單的第一項，在「在 Finder 中顯示」、「打開」、「重新命名…」、「編輯…」與「移到」之上，也是卡片的滑過動作之一。按下後，一層 overlay 覆蓋整張卡片（畫面加標題列），上面每個方塊是上表的一個版本（維護者的方向），方塊可以用到卡片的全部高度；overlay 頂端寫出錄影名稱，分頁其他地方不變。

- **最多三個方塊加「更多」**：影片（標示建議）、只有聲音、原始檔；「更多」裡是不含相機的影片與素材。錄影提供的版本較少時就顯示較少：沒剪過的一般錄影只有影片與只有聲音，因為它的原始檔就是影片。格狀版面的卡片至少 272 px 寬、連標題列約 200 px 高，放得下三個方塊加「更多」。清單版面的一列太矮，同樣的方塊改為從卡片彈出的 popover。
- 每個方塊顯示版本名稱與將產生的檔名；**拖出去**就是給那個檔案，**點擊**則有兩個動作：「**拷貝**」與「**存到…**」。不提供分享選單（AirDrop、訊息、郵件）：拖曳和拷貝就能送到同樣的地方，少一層選單，overlay 更單純（維護者，檢視計畫時）。
- 「**拷貝**」和 Finder 的 ⌘C 一樣把檔案放到剪貼簿，所以在 Finder 視窗、郵件、訊息或 Slack app 裡按 ⌘V，貼上的就是檔案本身；瀏覽器裡的網頁通常只收到檔名或圖示，那裡要用拖的。**不打開 overlay 也能用 ⌘C**：選中卡片按 ⌘C 拷貝影片（和拖曳給的一樣），在方塊上按 ⌘C 拷貝那個版本。「**存到…**」用系統的儲存面板選資料夾，以送出的檔名把檔案寫進去，等於用點的方式拖進 Finder 視窗。還沒好的版本，等好了再拷貝或儲存：「拷貝」會在方塊上顯示進度，完成後才放進剪貼簿。
- **原始檔方塊用一行字說明內容**，避免私密內容在沒看到的情況下離開：編輯過的錄影寫「錄到的全部，包括剪掉的部分」，可編輯錄影寫「相機與每個聲音分開保存」。
- 還沒好的方塊顯示進度；打開「分享」是明確的意圖，所以會開始準備所有還沒好的版本。
- **一次多個，照 macOS 的方式**：⌘＋點擊選取方塊（方塊上出現勾選），再拖任何一個選中的方塊，就一起給出所有選中的檔案（`startDrag` 支援 `files`），和 Finder 一樣。涵蓋「成品＋原始檔或素材一起給」。這是給熟悉的人的捷徑，基本流程不需要它，每個檔案也都能單獨拖。
- Esc、✕ 或點外面關閉。Tab 在方塊間移動，空白鍵選取，Return 開啟方塊的動作，⌘C 拷貝目前的方塊。

### 3. 錄完之後：存檔通知（D6）

錄完後不多開任何視窗。**錄影可以分享時才送出存檔通知**，點了和現在一樣在錄影分頁打開這段錄影：它的卡片就在那裡，可以播放、拖曳、拷貝或「分享…」。一般錄影存好就可以分享，所以通知和現在一樣立刻出現。可編輯錄影的通知等它的影片準備好（D2）才出現：參考機上 1 分鐘的錄影約 10 秒、10 分鐘約 1.5 分鐘；這段期間有人打開分頁，卡片上已經顯示「正在準備影片… 40%」。準備失敗時，通知說錄影已存好，卡片說影片無法產生。關掉通知不影響其他事：卡片完全一樣。

### 4. 剪輯畫面

工具列的「**匯出**」改為「**儲存副本…**」，詢問位置與形式：畫面（螢幕＋相機、只有螢幕、不要畫面）與聲音（混音），命名同上；預設存進錄影資料夾，成為自己的一張卡片，顯示「從『會議』儲存」。選擇只影響新檔案：副本不放相機，不會刪掉原始檔的任何東西，原始檔的相機軌仍在，下一份副本還能用。剪輯畫面沒有「分享…」：分享屬於卡片，關閉剪輯畫面就會開始為它準備影片（D2）。

### 5. 卡片說明它是什麼

- 「**可編輯**」標記保留，tooltip 用白話：「畫面、相機和聲音分開保存，之後還能調整。要寄給別人，直接拖或用『分享』。」
- 「**已編輯**」標記保留。
- 影片準備中：畫面上的進度。拖曳給的是對的檔案時，不跳任何警告。

## 管理離開的東西

- **版本不需要管理。** 它們以「錄影、剪輯 revision、版本」為 key 做進快取，剪輯沒變就重複使用；剪輯改了，下次就重做。拖出的檔案是快取檔案在同一個資料夾內的硬連結，換上要送出的檔名，不用複製。
- **快取放在哪裡：** macOS 是 `~/Library/Caches/RecordStuff/Versions/`，Windows 是 `%LOCALAPPDATA%\RecordStuff\Cache\Versions\`（Windows 也有剪過的一般錄影），也就是系統放「可以重新產生的檔案」的地方：Time Machine 不備份，裡面也沒有任何東西是唯一的一份。
- **怎麼清理：** 最多到 D5 的上限，先清最舊的。交出去的檔案（拖曳或拷貝）至少保留 24 小時，還在剪貼簿上時也一直保留，即使超過上限也一樣，因為瀏覽器裡的 Slack、Gmail 等網頁在放下之後可能還在讀檔；最差的情況是快取超出上限，多出的量是一天內交出去的檔案。刪除錄影或把它搬出資料夾時，它的快取立刻刪掉，不論是否在保留期：使用者刪掉的錄影不能還留在隱藏的資料夾裡，即使正在進行的上傳因此失敗。錄影再次編輯後，舊的快取在保留期過後刪除。
- **儲存的副本是使用者放的普通檔案。** RecordStuff 在每份副本中寫入它的來源（來源名稱與剪輯 revision，放在 `udta`，就像 `rsed` 描述可編輯檔），所以副本存進錄影資料夾時，即使在 Finder 改了名，錄影分頁仍能顯示「從『會議』儲存」。檔案以外不存任何連結，所以沒有要同步的東西。
- **錄影列出它在錄影資料夾中的副本**（D4）：錄影分頁依每個檔案內的來源資訊找到它們，錄影的選單依時間與形式列出，並提供「在 Finder 中顯示」。移出 RecordStuff 監看的資料夾或被刪掉的副本就不列出；不另外保存紀錄。
- **可編輯原始檔用檔名區分**：`會議.recordstuff.mp4`（D3），仍是任何播放器都能開的 MP4，但不會被當成要寄的影片。這是雙副檔名的慣例（`.tar.gz`、`.min.js`、`.d.ts`）：最後一個副檔名說明怎麼打開，前一個說明是哪種檔案。這個名稱只是給人看的：
  - app 判斷可編輯錄影靠檔案裡的 `rsed` 描述，從不看檔名，所以在 Finder 改名後仍可編輯，而一般檔案取名為 `.recordstuff.mp4` 也不會變成可編輯錄影；
  - 卡片標題不顯示 `.recordstuff`（「可編輯」標記已經說明），在分頁裡「重新命名…」會保留它；
  - 檔名格式設定（[錄影設定](../src/main/settings/model/recording.ts)）套用在標記之前：`<格式>.recordstuff.mp4`；
  - 本計畫之前錄的可編輯錄影不改名，照舊運作，只是沒有標記。
- **本計畫之前匯出的檔案**（`會議（已編輯）.mp4`）沒有來源資訊，仍是各自獨立的卡片。

- **不需要算繪的影片就不算繪。** 沒有編輯、也沒顯示相機的可編輯錄影，本來就有正確的畫面與混好的聲音（098）；它的影片只要把這兩條軌不重新編碼地複製到新檔案，幾秒就好，相機與分開的聲音也就不會帶出去。只有剪輯、顯示相機、改過音量或隱藏的時段才需要算繪器。
- **快取看得到也能清除**，就像 Final Cut Pro 的「刪除產生的檔案」、Lightroom 的清除快取與 Premiere 的媒體快取設定：「設定 → 一般」顯示快取大小與「清除」按鈕，只保留還在保留期內的檔案。

### 和錄影同時準備

準備（D2）在使用者繼續工作時進行，也可能在他再次錄影時進行。它絕不能讓那段錄影掉任何一格。

**錄影為什麼會掉格。** 錄影是即時的：每張畫面都要在自己的時間內完成擷取、在 GPU 上合成（Metal）、由硬體影片引擎編碼（VideoToolbox），30 fps 時是 33 ms。下一張到了，上一張還在等，就會被跳過，pacer 改用前一張補上（[錄影](../docs/zh-TW/system-design/recording.md)）。算繪用的是同一個影片引擎（解碼與編碼）、同一個 GPU、記憶體頻寬與磁碟；錄影需要時這些被算繪佔著，錄影的畫面就會晚到。基本款 M 系列晶片只有一個影片編碼引擎，Pro 與 Max 有兩個，所以風險因機器而異。聲音只佔一點 CPU，不會這樣受影響。

**其他 app 怎麼做。** Final Cut Pro 只在使用者閒置幾秒後才在背景算繪，使用者一動就立刻停。OBS 除了即時編碼不跑任何重的工作，畫面被跳過時顯示「編碼超載」。macOS 把可延後的工作（照片的分析、Spotlight、Time Machine）放在背景優先順序：系統會限制它的 CPU、磁碟與網路，讓它留在節能核心，過熱或低耗電模式時延後。共同的原則是：即時的工作優先，背景工作一看到它吃緊就讓開，而且要量測。

**設計分五層：**

1. **自己的程序、背景優先順序。** 準備在匯出 worker 裡執行，它本來就是獨立的程序（[剪輯](../docs/zh-TW/system-design/editing.md)），並套用 Darwin 的背景策略，所以 macOS 只給它剩下的 CPU、限制它的磁碟 I/O，並讓它留在節能核心。它當掉也碰不到錄影。
2. **編碼器知道哪個工作是即時的。** 錄影的 VideoToolbox session 和現在一樣是即時的；算繪的不是（現在就不是），錄影進行時同時最多只處理一張畫面，而不是八張。
3. **依錄影健康狀況調節的調節器。** capture 程序本來就在量關鍵數字：畫面時間戳比主機時鐘超前多少、跳過幾張畫面、編碼器積了多少（它的結束報告）。錄影期間它每秒送一筆小取樣給 main。只要有一筆顯示有畫面晚到或被跳過，或編碼器積了超過一張，main 就讓準備在下一張畫面暫停；連續 10 秒都正常才恢復，避免忽停忽走。暫停不花成本：算繪器本來就每張畫面檢查一次取消。不論取樣如何，錄影一結束就不再暫停。
4. **系統狀況。** 過熱達「嚴重」或「危急」、低耗電模式時暫停；即時預覽時也暫停，因為使用者正在看那些畫面。
5. **開啟前先通過量測門檻。** 在支援的最慢機型（基本款 M1）上，30 與 60 fps、有無相機的錄影，同時準備一段 10 分鐘的影片：晚到與跳過的畫面要和單獨錄同一段相同（目前 30 fps 是 0.00%），`verify --sync` 不變，錄影的 CPU 在 087 的預算內。沒通過的機型，調節器在那裡的策略就是整段錄影都暫停，也就是這個設計退回的單純暫停。

錄影被刪除或再次編輯時，它正在準備的版本會取消；app 結束時捨棄（刪掉做到一半的檔案，下次需要時再做）。一次只準備一個版本。準備期間匯出 worker 會為它留著，閒置規則（[設計總覽](../docs/zh-TW/system-design/design-overview.md)）與 `measure:cpu` 都要納入：閒置在準備完成後才量，準備本身的成本也要量。

**要做多少事：** 健康取樣（capture 程序已經有這些數字）、main 裡的調節器（小型狀態機，以取樣序列做單元測試，包括忽停忽走、暫停中錄影結束）、程序的優先順序，以及門檻的量測。要防的錯誤是忽停忽走（10 秒的緩衝）、停了就不再恢復（錄影結束時清除）、長時間錄影讓準備一直等（錄完後就會做完，卡片顯示進度）。

## 不採用的做法

- **每次拖曳編輯過的錄影就跳警告：** 使用者會習慣按掉，而且會打斷拖曳。
- **把副本以儲存的連結歸在錄影卡片底下：** 每次改名、搬移、刪除都要同步，在 Finder 改名就斷掉。把來源寫在檔案裡就能有同樣的「從…儲存」，而沒有這些問題。
- **可編輯原始檔改用 `.recordstuff` 套件格式：** 放棄 087「任何播放器都能打開」。
- **檔名用版本號（V1、V2）：** 對收到的人說明不了內容。
- **每個離開的版本都加「已編輯」：** 標記的是成品而不是來源；收到的人不需要，還會引起疑問。只保留在副本和自己的來源放在一起時。
- **讓可編輯檔啟用的畫面改成合成畫面：** 錄影時要多一個編碼器，而且仍然沒有套用剪輯。
- **把剪輯寫回原始檔：** 違反 085 不寫入來源的規則。
- **每次錄完出現快速縮圖**（macOS 截圖縮圖、CleanShot 的 overlay）：多一個視窗，而且影片還在產生時就跳出來打擾；影片好了才送出通知、帶到卡片，用現有的東西就能做到同樣的事（維護者，檢視計畫時）。
- **拷貝素材時自動壓成 zip：** 使用者沒選過的檔案格式，收到的人還得解壓；四個名稱一致的檔案本身就能送進任何接受檔案的聊天或郵件。

## 決定（維護者 2026-10-28 回答）

- **D1 — 影片還沒好時拖卡片：等待。** 拖曳給的是「影片」，也就是卡片播放的樣子：沒剪過的一般錄影立刻給原始檔；剪過的一般錄影的剪輯結果，以及任何可編輯錄影套用剪輯與音量、合成相機的畫面，要算繪完成後才給。完成前不開始拖曳，卡片顯示進度，並說明按住 ⌥ 可拖原始檔。
- **D2 — 在剪輯畫面關閉時與可編輯錄影存檔時準備影片。** 使用者再次錄影時也可以繼續準備，由[和錄影同時準備](#和錄影同時準備)裡的調節器控制，絕不讓錄影因此掉任何一格（維護者在檢視計畫時的方向）。
- **D3 — 可編輯原始檔在存檔時命名為 `<name>.recordstuff.mp4`。** 用全名而不用 `rs`：多數人看不懂 `.rs`，開發者還會當成 Rust 程式檔，而 `recordstuff` 說明了用哪個 app 能再打開；副檔名仍是 `.mp4`，任何播放器都能開。
- **D4 — 錄影列出它在錄影資料夾中的副本**，依每個檔案內的來源資訊找到。移出監看資料夾或被刪掉的副本不列出；不另外保存紀錄。副本是「儲存副本…」（即現在的「匯出」）產生的檔案；編輯本身不產生檔案。
- **D5 — 快取最多佔 10 GB 與可用空間 10% 取較小者。**
- **D6 — 不做快速縮圖；錄影可以分享時才送出存檔通知**（2026-10-28 檢視計畫時修訂；原本回答為預設開啟的縮圖）。一般錄影和現在一樣立刻送出；可編輯錄影等影片準備好才送出。點了在錄影分頁打開這段錄影。
- **D7 — 拖曳或存到時，素材是一個資料夾，音軌不重新編碼**（聲音為 AAC 的 `.m4a`）；拷貝時給同樣的檔案、不包資料夾，因為大多數聊天與郵件 app 不接受資料夾（2026-10-28 檢視計畫時細化）。
- **D8 — 存在一般錄影來源旁的副本叫 `<name>（剪輯版）.mp4`**，即上面的命名規則。
- **D9 — 會和自己來源同名的版本叫 `<name>（剪輯版）.mp4`；「只有聲音」叫 `<name>（聲音）.m4a`**（2026-10-29 由 AI 暫定，維護者之後會調整）。把 D8 從副本擴大到拖曳，剪過的一般錄影，它的影片就不會以 `會議.mp4` 離開，也不會在 Finder 裡取代原始檔；用「剪輯版」而不用「已編輯」，因為它說的是這個檔案是什麼，而不是發生過什麼。

## 步驟

- [ ] **0. 開始。** 檢查目前的程式、085 的發布與命名、087 與 098 的音軌、錄影分頁的卡片、拖曳、選單與通知，以及剪輯紀錄。檢查 `startDrag` 是否讓放下的動作搬走錄影（拖到同一顆磁碟的 Finder 視窗）；如果會，限制為只能拷貝屬於步驟 2。D1–D8 已於 2026-10-28 回答，D9 於 2026-10-29 暫定。第一個桌面回合前依 [AGENTS.md](../AGENTS.md) 啟動 `caffeinate -d -i -t 5400`。
- [ ] **1. 版本與快取。** 把版本做成 shared 的模型（每段錄影提供哪些、兩種語言的檔名、撞名）；以錄影、剪輯 revision 與版本為 key 的快取，它的位置、上限、24 小時保留與清理；背景準備，一次一個，背景優先順序，不需要算繪時直接複製軌，依上面的規則取消與捨棄；設定裡的快取大小與「清除」；經由匯出 worker 算繪版本但不發布在錄影旁；以硬連結換上送出的檔名。在儲存的副本中寫入來源。每種錄影與剪輯狀態、檔名、快取的重用、過期與上限都有單元測試。
- [ ] **2. 卡片。** 拖曳給影片、⌥ 拖曳給原始檔、只能拷貝、準備中的狀態（D1、D2）、tooltip；D3 對新可編輯錄影的命名，標題不顯示標記，「重新命名…」保留標記。背景 UI 測試涵蓋各狀態、兩種語言與主題，只斷言行為與無障礙。
- [ ] **3. 分享…。** **先選設計：** 檢視計畫時的示意圖只是擺出元件位置，不是設計。動工前，先提出幾個明顯不同的視覺設計，涵蓋 overlay、方塊、方塊的動作與準備中的狀態（至少三個，用 app 自己的元件、字型與 design token 做，包含兩種主題、兩種語言，以及格狀卡片與清單 popover），做維護者選中的那一個；這是會暫停計畫的決定點。接著：選單項目與滑過動作；Overlay（格狀）與 popover（清單）、最多三個方塊加「更多」、原始檔方塊的說明、方塊的名稱與檔名、拷貝與存到…（拷貝時素材給檔案，D7）、卡片與方塊上的 ⌘C、⌘＋點擊選取與一次多個檔案、準備與取消、鍵盤與 VoiceOver。剪輯畫面以附形式選擇的「儲存副本…」取代「匯出」；錄影的副本列表（D4）。
- [ ] **4. 和錄影同時準備，以及存檔通知。** capture 程序的健康取樣、調節器與它的暫停和恢復、過熱與低耗電模式的條件、匯出 worker 的優先順序；在支援的最慢機型上量測門檻，並依結果設定各機型的策略。存檔通知（D6）：錄影可以分享時才送出，可編輯錄影在影片準備好之後，以及準備失敗時說什麼。為背景準備更新 `measure:cpu` 與閒置規則，並量測它的成本。
- [ ] **5. 桌面回合。** 收到「好了」後，在全新的簽章 bundle 上：把每個版本拖到 Finder 視窗以及郵件草稿或聊天中，檢查收到的檔案（影片一條畫面一條聲音、套用剪輯、相機在顯示的地方；只有聲音能解碼；原始檔逐位元組相同；素材和錄影的軌一致）；各狀態下拖卡片與 ⌥ 拖曳；「拷貝」與 ⌘C 貼到 Finder、郵件與 Slack app，以及瀏覽器網頁收到什麼；通知的時機；1、10、30 分鐘錄影的準備時間；在準備影片的同時錄影，把跳過的畫面與同步和單獨錄同一段比較，並在 log 中看調節器何時暫停；拖到同一顆磁碟後錄影仍留在原處；快取上限與保留期。還原設定、關閉 app 並確認程序已結束。
- [ ] **6. 易用性檢查。** 以[剪輯畫面易用性 skill](../.agents/skills/edit-view-usability/SKILL.md) 的方法套用到分享：請第一次使用的人把錄影寄給同事，再把素材交給剪輯師，以 Computer Use 觀察；發現的問題修正或記錄。
- [ ] **7. 文件與結案。** [剪輯](../docs/zh-TW/system-design/editing.md)（版本、快取、來源）、[桌面](../docs/zh-TW/system-design/desktop.md)（卡片、分享…、通知）、[設計總覽](../docs/zh-TW/system-design/design-overview.md)的閒置規則、[設計決策](../docs/zh-TW/system-design/decisions.md)（模型、拖曳規則、命名、不採用的做法）、README 對分享的說明、驗證紀錄、翻譯、移除本計畫並更新索引。

## 驗證

- 步驟 1–4：開發時以 `pnpm test:scope` 跑 library 與 editing 範圍；步驟 5 之前跑 `pnpm check`，因為匯出 worker、錄影分頁與 main 的發布都會改變。
- 步驟 5–6：以[原生驗收 skill](../.agents/skills/native-acceptance/SKILL.md) 跑桌面回合；拖曳會移動真正的游標，每輪都需要交接。共用 `out/` 與 `dist/` 的工作要排隊。
- 分開回報：自動化結果、拖了什麼到哪裡、收到什麼檔案、易用性回合看到什麼，以及沒驗證到的部分（Windows 沒有可編輯錄影，一般錄影的分享只由 CI 檢查，也不提供拷貝檔案，只有拖曳與存到…；回合中沒有實際拖入的服務）。
