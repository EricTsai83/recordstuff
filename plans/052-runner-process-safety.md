# 052 — Runner process and environment safety

[English](052-runner-process-safety.md) | [繁體中文](052-runner-process-safety.zh-TW.md)

Status: planned. Created: 2026-09-29. First in the queue, before 053. Execution order: see [queue](README.md#order-and-status).

## Purpose and boundary

The second audit on 2026-09-29, run on `2088633` after 051 closed, fixed 20 app, release and website defects in `ea86b99`…`7f1f3a8` on main. It also found that several desktop runners bypass the shared process and environment helpers. The maintainer moved that group here, because changing runner orchestration needs the affected runners exercised for real and could not share that round. Every item below was confirmed by reading the code at `2088633`; none was reproduced.

- **Unescaped Electron path in `pgrep`/`pkill` patterns.** [run-matrix.mts](../scripts/run-matrix.mts) (`electronPids`, `electronMainPid`, the SIGTERM sweep and the final `pkill`), [measure-finalization.mts](../scripts/measure-finalization.mts) and [diagnose-frame-cadence.mts](../scripts/diagnose-frame-cadence.mts) put the real `Electron.app` path straight into an extended regular expression. Their local `pgrep` helpers ignore the exit status. The only trigger is a checkout path with regular-expression metacharacters, such as `~/Code (2026)/recordstuff`. The parentheses then never match themselves, or an invalid pattern exits 2 with empty output. Either way the "already running" guard passes, `stopApp()` finds nothing and the runner reports "every owned process exited" while Electron keeps running. [processes.mts](../scripts/lib/processes.mts) already provides `escapeRegExp` and a status-checking `recordStuffPids`.
- **Inherited Electron variables reach the development app.** `run-matrix` and `measure-finalization` only delete `ELECTRON_RUN_AS_NODE` before launching `Electron.app` with `RECORDSTUFF_AUTORECORD`. [runner-env.mts](../scripts/lib/runner-env.mts) `scrubbedEnv()` also removes `ELECTRON_RENDERER_URL`, `RECORDSTUFF_AUTORECORD` and `NODE_OPTIONS`. The unpackaged app honours an inherited `ELECTRON_RENDERER_URL`, and Electron honours `NODE_OPTIONS`; a VS Code JavaScript Debug Terminal sets the latter. [acceptance-controlled.mts](../scripts/acceptance-controlled.mts) keeps a hand-copied key list without `NODE_OPTIONS`. [acceptance-updates.mts](../scripts/acceptance-updates.mts), [acceptance-runtime.mts](../scripts/lib/acceptance-runtime.mts), [audio-quality-tools.mts](../scripts/lib/audio-quality-tools.mts) and [cpu-sampler.mts](../scripts/lib/cpu-sampler.mts) delete only `ELECTRON_RUN_AS_NODE`.
- **The shared RecordStuff pattern is spelled out again.** `processes.mts` says every runner goes through it, but `recordStuffPids` has no caller. `acceptance-controlled`, `acceptance-updates`, `acceptance-hotkey` and `measure-cpu` repeat the pattern inline; the last two lack the `(^|/)` anchor, and `measure-cpu` ignores a `pgrep` failure. `diagnose-frame-cadence` and `measure-finalization` use the looser `RecordStuff.app/Contents/MacOS/` with an unescaped dot. [controlled-acceptance.mts](../scripts/lib/controlled-acceptance.mts) `bundleProcessPattern` duplicates `recordStuffPattern(bundleDir)` without its `^` anchor.
- **A build interrupted in `measure:finalization` exits 1.** The runner installs its SIGINT/SIGTERM handlers and then builds with a blocking `spawnSync`. Ctrl-C kills pnpm, `status` is null and `process.exit(built.status ?? 1)` runs before the queued handler. That contradicts the documented 130/143, and a SIGTERM to the runner alone cannot stop the build. `run-matrix` already builds asynchronously in its own process group and stops it on a signal.
- **Fixed material profiles.** `run-matrix` and `measure-finalization` share `$TMPDIR/recordstuff-material-profile`, and `diagnose-frame-cadence` uses `recordstuff-cadence-material-profile`. None is removed; the shared one is reused across rounds and held 39 entries on 2026-09-29. `measure-cpu`, `acceptance-hotkey` and `acceptance-updates` already create a unique profile with `mkdtemp` and delete it, as the [acceptance helper](../scripts/lib/acceptance.mts) comment ("callers own the profile") expects.

Out of scope: app, release-tool and website code; new runner features; the other audit leftovers the maintainer did not queue (`compareVersions` pre-release ordering, the duplicate `PermissionStatus` type, an `isCaptureControl` helper, website font preload and colour tokens).

## Implementation contract

- [ ] **One process module.** Move Electron-path matching into `processes.mts`: an `electronPattern(appPath, part)` built with `escapeRegExp`, and a `pgrepPids(pattern)` that throws on a spawn error or any status other than 0 and 1 (1 means none). `recordStuffPids` uses the same helper. Route every runner named above through these; delete the local `pgrep` helpers and `bundleProcessPattern`, whose callers use `recordStuffPattern(bundleDir)`. `pkill` uses the same escaped pattern. A `pgrep` failure now fails the runner's preflight or cleanup visibly instead of reading as "nothing is running".
- [ ] **One launch environment.** Every runner that launches Electron or the app starts from `scrubbedEnv()` and then adds what it owns (`RECORDSTUFF_AUTORECORD`, fault points). No runner keeps its own key list.
- [ ] **Interruptible finalization build.** `measure:finalization` builds with the asynchronous, process-group build that `run-matrix` uses and stops it from the signal handlers, so Ctrl-C or SIGTERM during the build exits 130/143 after cleanup.
- [ ] **Owned material profiles.** `run-matrix`, `measure-finalization` and `diagnose-frame-cadence` create their Chrome profile with `mkdtemp` and remove it during cleanup. Cleanup still waits for the material browser to exit before judging "every owned process exited".
- [ ] **Documentation.** In both languages, [tooling](../docs/system-design/tooling.md) (acceptance cleanup and the runner list) states that process matching and the launch environment are shared, that a `pgrep` failure blocks the round, and the finalization runner's interrupt behaviour.

## Verification and exclusions

- [ ] Unit tests: `electronPattern` and `recordStuffPattern` match a path containing `( ) [ ] + . $` literally and reject a sibling path; `pgrepPids` returns `[]` for status 1 and throws for status 2 and for a spawn error; `scrubbedEnv` is the only source of each runner's launch environment (a test that fails if a runner file deletes a key itself); the finalization runner's interrupt maps a signal during the build to 130/143 with cleanup run.
- [ ] `pnpm check`.
- [ ] Runner orchestration changed, so exercise each affected runner once on the reference Mac, in one desktop round after the [readiness handoff](../docs/testing.md#confirm-desktop-handoff-before-testing): `pnpm matrix -- quick`, `pnpm measure:finalization -- --dir <tmp> --repeat 1`, `pnpm diagnose:cadence -- --runs 1`, `pnpm measure:cpu`, `pnpm acceptance` and `pnpm acceptance:updates -- --logic-only`. For `pnpm acceptance:controlled`, one `pnpm acceptance:controlled -- selftest` round suffices. Each must still find, launch and stop its own process, and leave no material profile behind. Run `measure:finalization` from a VS Code Debug Terminal or with a harmless `NODE_OPTIONS` value and show that the launched app does not inherit it. Interrupt `measure:finalization` once during its build and once during a take, and record the exit codes.
- [ ] Run one runner from a temporary clone whose path contains `(` and `)`, and show that its preflight sees an already-running Electron from that clone and its cleanup stops it.
- [ ] Exclusions: the full capture matrix, long recordings and audio fidelity. Capture and encoding are unchanged, so the recordings above answer only whether the runners still drive them.
