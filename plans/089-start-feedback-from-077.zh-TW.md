# 089 — 及時的權限拒絕與闔蓋時的麥克風

[English](089-start-feedback-from-077.md) | [繁體中文](089-start-feedback-from-077.zh-TW.md)

狀態：已規劃、尚未開始。建立：2026-10-22，依維護者要求，來自 077 實機回合的兩項觀察。優先順序：建議下一個做、排在 083 之前；由維護者決定。硬性相依：無。依[計畫索引](README.zh-TW.md)依序執行各步驟。

## 目標與範圍

開始錄影或錄影中有兩種情況沒有及時告訴使用者，都在 [077 的回合](../docs/zh-TW/verification/history-2026-10.md#plan-077-結案--2026-10-22)於實機上看到：

1. **權限拒絕晚了 9.3 秒。**關閉螢幕權限並對執行中的 App 選「稍後」後，開始錄影在 `starting` 停了 9.3 s 才得到 `permission_denied`。[`display-source.ts`](../src/main/display/display-source.ts) 最多列舉三次擷取來源、每次間隔 150 ms，要到第三次仍是空的（有螢幕、沒有來源、macOS）才判定授權被撤銷；每次 `desktopCapturer.getSources` 看來都等了約 3 s。成功條件：撤銷的授權在本計畫依量測訂出的時限內被拒絕（目標是第一次空的列舉後 ≤ 1 s），仍是同樣的 `permission_denied`、權限卡與通知，而且不會誤拒重試原本要處理的真正拓樸變化。
2. **闔蓋時的內建麥克風只錄到靜音。**MacBook 闔上蓋子時，內建麥克風仍列出、能開啟，但只送出數位零；077 一段錄影中有 13 s 是靜音，而使用者沒被告知，因為遺失是以沒有緩衝判定，不看內容。成功條件：使用者在錄影前或錄影中得知所選輸入聽不到聲音，方式由維護者在 D2 決定。

不在範圍：CI 以外的 Windows；一般安靜或靜音麥克風的處理方式（安靜的房間不是故障）；引擎內的 shareable-content 路徑；077 的其他觀察（被移除螢幕的最後一格到 main 發現之間的 1.4 s 已照文件接受）。

## 步驟

### 1. 量測拒絕

- [ ] 在 log 記錄每次 `getSources` 與整個解析的耗時，分別量授權被撤銷時的開始（由維護者撤銷；agent 一律不改 TCC）與一般開始；記錄授權正常時是否也會在有螢幕時得到空的列表（螢幕喚醒、拓樸變化）。為耗時那行加單元測試。

### 2. D1 — 何時判定授權已撤銷（維護者）

- [ ] 建議：macOS 上，有螢幕卻列出空的來源，而 `PermissionWatcher` 已懷疑授權（或引擎自己的 probe 這麼說）時立即拒絕；否則維持三次嘗試。替代：第一次空的回答一律拒絕；或同時問引擎的 `probe`，取先回答者。依選擇實作並為各分支加測試，`topology_changed` 與 `no_display` 維持不變。

### 3. 偵測聽不到的麥克風

- [ ] 找出 macOS 對闔蓋提供什麼資訊（IOKit `AppleClamshellState`、內建裝置的 data source，或 `kAudioDevicePropertyDeviceIsAlive`／`IsRunningSomewhere`），以及當時 HAL 列出內建輸入是否不同；並用 077 的檔案與新錄的檔案量測「連續 N 秒每個樣本都剛好是零」能否在 BenQ、內建與藍牙輸入上與安靜的房間區分。

### 4. D2 — 使用者看到什麼（維護者）

- [ ] 建議：闔蓋時在裝置清單標示內建輸入（「蓋子已闔上」），錄影中持續 2 s 的完全數位靜音透過既有的 `microphoneLost` 路徑判定為麥克風中斷，讓已承諾的通知、紀錄與 log 適用。替代：闔蓋時隱藏該輸入；或只在設定中警告。以引擎 core 測試與 Recorder 測試實作。

### 5. 驗證與紀錄

- [ ] 改動模組的 focused 測試；因擷取與引擎有變更，跑 `pnpm check`；簽章 bundle 回合：撤銷授權（維護者）、闔蓋與開蓋各用內建麥克風錄一段；還原所有設定與權限。更新[錄影](../docs/zh-TW/system-design/recording.md)、[桌面](../docs/zh-TW/system-design/desktop.md)與英文版，再依計畫索引結案。

## 完成條件

D1、D2 已決定並實作，兩種情況都在簽章 bundle 上跑過或經維護者接受為未驗證，且文件與結案紀錄寫入結果時完成。
