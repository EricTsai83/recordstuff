## Purpose and boundary

RecordStuff detects a dead capture renderer through heartbeats and learns about a full disk only when a write fails. Four conditions still go unobserved until data is lost: the output volume runs out of space mid-recording, the encoder stops delivering chunks while the renderer still answers pings, the writer backlog grows without bound on slow storage, and the process is terminated while recording so the temporary file is never reported. This plan adds one small guard for each, routed through the existing stop and failure paths. It adds no state-machine states, no recovery or remux, no health UI beyond the existing saved notification and failure history, and no scan of unrelated files in the output folder.

Owners: [Recorder](../src/main/recorder.ts), [FileWriter](../src/main/file-writer.ts), [history coordinator](../src/main/recording-result.ts), [app lifecycle](../src/main/index.ts), [translations](../src/shared/i18n.ts) and their tests. Keep every threshold in one place with a stated initial target; tune only with written evidence.

## Cap reference

At pinned revision `26e1a6d882f311d10b5317e9e0d29babe4f6737e`, Cap [polls free space every two seconds during a recording](https://github.com/CapSoftware/Cap/blob/26e1a6d882f311d10b5317e9e0d29babe4f6737e/crates/recording/src/output_pipeline/core.rs#L532-L615) and emits [low/exhausted health events](https://github.com/CapSoftware/Cap/blob/26e1a6d882f311d10b5317e9e0d29babe4f6737e/crates/recording/src/output_pipeline/core.rs#L391-L421) against [fixed byte thresholds](https://github.com/CapSoftware/Cap/blob/26e1a6d882f311d10b5317e9e0d29babe4f6737e/crates/utils/src/disk_space.rs#L5-L8); its muxer keeps [a byte-bounded packet queue](https://github.com/CapSoftware/Cap/blob/26e1a6d882f311d10b5317e9e0d29babe4f6737e/crates/cap-muxer/src/main.rs#L92); a [crash sentinel](https://github.com/CapSoftware/Cap/blob/26e1a6d882f311d10b5317e9e0d29babe4f6737e/apps/desktop/src-tauri/src/crash_sentinel.rs#L1-L9) written at launch and cleared on clean exit detects sessions that died without shutting down; a [power observer](https://github.com/CapSoftware/Cap/blob/26e1a6d882f311d10b5317e9e0d29babe4f6737e/apps/desktop/src-tauri/src/power_observer.rs#L22-L33) logs sleep and wake. These are source-level references from a native pipeline that can retime frames and rebuild fragments. RecordStuff receives opaque MediaRecorder bytes, so only the observe-and-stop shape transfers, not the recovery machinery.

## Implementation contract

- [ ] **Disk headroom.** While a session is in flight, poll free space of the output directory with `fs.statfs` on one timer (initial target every 5 seconds; a failed poll logs once and never stops the recording). Below a warning threshold (initial target 1 GiB) log once per session. Below a stop threshold (initial target 200 MiB) request the normal stop once, so the file is drained, synced and published while space remains. The saved notification and log state that the recording stopped early because the disk is almost full; carry that reason as an optional field on the existing `saved` event, not through a second event or a global flag. Success stays success and does not enter failure history. If publication still fails, the existing failure path and partial preservation apply unchanged. Do not reserve space, switch folders or downgrade quality.
- [ ] **Stalled capture.** After `started`, arm one inter-chunk timer that every accepted chunk resets; disarm it when `stopped` arrives or the session finalizes, so a normal drain never reads as a stall. Log a warning once at the first bound (initial target 10 seconds without a chunk) and fail at the second (initial target 30 seconds) through the existing terminal failure path with `capture_failed` and a distinct detail, preserving the partial file. Heartbeats stay unchanged; a responsive renderer that delivers no media becomes a failure instead of a silent hang. The existing first-chunk deadline remains the guard before the first chunk.
- [ ] **Bounded writer backlog.** FileWriter counts bytes accepted but not yet confirmed written. When an append would exceed the bound (initial target 64 MiB), reject it and fail the session through `output_write_failed` with a backlog detail, retaining the first error as today. No pause, drop or retry: MediaRecorder cannot be throttled, and the bound exists so slow or offline storage ends the recording with a preserved partial instead of unbounded memory. Expose the current backlog for logging and for 037's admission measurement.
- [ ] **Interruption evidence.** Before a session creates its temporary file, write one sentinel file per session in a dedicated userData directory (file name is the session id; content is session id, start time and temporary path) with the existing atomic writer, so a crash can never leave a temporary file that no sentinel names. A failed sentinel write logs once and does not block the recording. Remove the session's own sentinel on every terminal outcome, including failures. One file per session means 037's concurrent finalization adds and removes sentinels without a shared read-modify-write. On launch, before history restore, each remaining sentinel becomes one failure-history entry whose text says the app did not exit normally while recording and the file may be incomplete; then remove that sentinel. Reuse the existing restore recheck: the path is a lookup hint that becomes partial only while the file exists, otherwise unknown. Prefer a distinct detail on an existing code; add a new code only if the user-visible text cannot otherwise be honest, and then update the shared validator, translations and every consumer together. This is neither orphan-file scanning nor crash recovery; the single-instance lock guarantees remaining sentinels belong to dead processes.
- [ ] **Sleep and wake.** Log `powerMonitor` suspend and resume with the in-flight session id, so a failure after sleep reads as sleep rather than unexplained track loss. Do not stop on suspend in this plan; record the native outcome of sleeping during a recording in 035 so a later decision has evidence.
- [ ] Bilingual messages for the early-stop reason and the interruption entry. Update recording design (deadlines and supervision table, file completion and failure) and desktop design (recording failure results) in both languages, including the statement that no recovery or repair is performed.

## Verification and exclusions

- [ ] Deterministic tests with injected clock and stat: warning then stop across the thresholds, stop requested once, poll failure ignored; stall warning and failure with real Recorder events and a preserved nonempty temporary file; backlog rejection with a real FileWriter against a slow write stub; sentinel written before the temporary file exists and removed on saved and on each failure code; a failed sentinel write does not block the start; two sentinels at launch produce two entries, with the file present and missing; no sentinel after a normal exit. Assert real temporary-file contents and emitted events, not only call counts.
- [ ] `pnpm check`, then a fresh `pnpm start:app` recording smoke with media verification and playback. Exercise the disk guard against a bounded disk image, never the system disk; exercise interruption by force-quitting the labeled bundle during a recording on an isolated output folder and relaunching. Both are guided native cases in 035 (N30, N31); tests do not prove their notification or history presentation.
- [ ] Exclude quality/audio matrices, permission flows and publication: this plan changes no encoding, source selection or state machine.
