# 095 — 工作室的 stage 依視窗盡量放大

[English](095-studio-stage-size.md) | [繁體中文](095-studio-stage-size.zh-TW.md)

狀態：已規劃，尚未開始。建立：2026-10-23，依維護者在 092 改動後回合期間的要求。硬性相依：092（它的「預覽」面板，以及所有工作室數字所比較的工作室列）。排在 092 之後、094 之前，讓 094 的「相機」畫面畫在最終的 stage 上。依[計畫索引](README.zh-TW.md)的順序執行。本次只撰寫計畫；下列行為都尚未實作或驗證。

## 目標與現況

錄影工作室的 stage 是錄影要擷取的螢幕的預覽，以該螢幕的比例畫在一個灰色框（`.camera-preview`，在 `--muted` 上留 14 × 16 px 的 padding）中，最高 `max(200px, 100dvh − 420px)`（`.studio-stage .camera-preview-stage`，[ui.css](../src/renderer/ui.css)）。在 1043 × 758 的視窗、橫式螢幕上約為 391 × 220 CSS 像素，左右上下都是灰底：視窗大部分寬度沒用到，下方的面板（預覽、相機、音訊）卻固定佔去一部分高度。維護者要畫面在自身比例下盡量大。

## 需求（維護者，2026-10-23）

- **R1 — 同比例下最大的畫面（contain）。** 在任何視窗大小與縮放下，stage 依錄影螢幕的長寬比盡量放大，但寬與高都不超出容器：寬度先取容器寬度，若這樣會比容器高，就改以容器高度為高、依比例算出寬度。橫式與直式螢幕都適用同一規則；哪一邊先碰到容器，取決於容器與螢幕兩者的形狀，而不是只看螢幕是橫是直（維護者，2026-10-23）。灰框只留在比例讓出的另一個方向的空間；不能成為包住一個本可更大的畫面的邊距。
- **R2 — 畫面上不放東西**，依 2026-10-23 對即時預覽、相機狀態與 092 的「關閉」覆蓋層的決定：stage 只有畫面與可拖曳的泡泡外框。
- **R3 — 泡泡位置維持精確。** 任何 stage 大小下，拖曳與方向鍵都把泡泡放在錄影合成它的位置（同樣的 `bubbleRect` 與 `positionFromRect`），24 px 的拖曳範圍與 plan 067 的可讀性下限不變。

## 實作前要做的決定

- **D1 — 高度怎麼分。** stage 取得視窗高度扣掉控制列與面板後剩下的空間，低於某個下限時頁面捲動；或在寬視窗中把面板移到 stage 旁邊。選項在背景 gallery（`pnpm preview:ui`）以預設、窄、最小與大尺寸畫出，由維護者選一個。
- **D2 — 依使用頻率安排工作室版面**，2026-10-23 提出、尚未選定：錄影中要一直看得到的（開始或停止與經過時間、錄影與相機的狀態、表示有聲音進來的小指示）、常按的（靜音、隱藏相機、即時預覽、畫面）、偶爾調整的（推桿、相機開關）、設一次的（泡泡大小、圓角、鏡像、預覽速率）。若採用，控制列放常用操作與每個輸入的小音量指示，stage 下方的面板放設一次或偶爾調整的設定。由維護者決定它屬於本計畫或之後的計畫。
- **D3 — 預覽的解析度。** 092 維持 640 像素寬的串流，因為 stage 只有約 391 像素。在 Retina 螢幕上寬兩、三倍的 stage 會把 640 像素放大顯示。決定前先量：`PREVIEW_WIDTH` 為 640 與較大寬度（例如 960）時，工作室在「省電」與「標準」下的 S，並在簽章 bundle 上比較兩者畫面；只有維護者看得出差別並接受它相對 092 各列的實測成本時才採用較大的串流，否則維持寬度並記錄結論。

## 步驟

- [ ] **改動前的 baseline。** 在目前 HEAD 的簽章 bundle 上執行 `pnpm measure:cpu -- --skip-settings --skip-playback --studio --studio-rate power --fps 60 --repeat 3 --diagnostics`（以及「標準」），同一輪包含 R：較大的 canvas 可能讓頁面繪製更耗 CPU，所以 stage 大小同時是 CPU 問題與版面問題。
- [ ] **在 gallery 中呈現 D1 的選項**（若 D2 屬於本計畫也一併呈現），只用正式頁面與 CSS，依 [UI 對齊規則](../docs/zh-TW/testing.md#測試-ui-與-app-保持一致)；由維護者選擇。
- [ ] **Stage。** 在 [studio.tsx](../src/renderer/settings/tabs/studio.tsx)、[camera-preview.tsx](../src/renderer/settings/tabs/camera-preview.tsx) 與 [ui.css](../src/renderer/ui.css) 實作選定的版面：stage 依給它的空間與螢幕比例決定大小（container query 或量測尺寸），灰底只作為比例的留邊。背景 UI 案例斷言行為與不依設計值的不變量：每個尺寸與縮放下 stage 維持螢幕比例、在一個方向碰到容器且另一個方向不超出、沒有溢出，泡泡拖到同樣的位置。
- [ ] **D3** 如上，附量測與維護者的目視判斷。
- [ ] **改動後量測並寫入文件。** 在新的簽章 bundle 上連續量 baseline 的案例；更新 [desktop](../docs/zh-TW/system-design/desktop.md#錄影工作室) 的工作室章節與工具指南的[管線 baseline](../docs/zh-TW/system-design/tooling.md#管線-baseline)，含英文版。

## 門檻與完成條件

在每個 gallery 尺寸下，stage 都是在容器內、依螢幕比例能放下的最大矩形（一個方向碰到容器，另一個方向不超出），橫式與直式皆然，上面不放任何東西；每個尺寸下泡泡都放在錄影合成它的位置。工作室在「省電」與「標準」下的 CPU 維持在 092 各列的誤差範圍內，或較大的成本是維護者依 D3 實測後的選擇。錄影行為不變。

## 驗證

`pnpm test:scope -- studio layout`（工作室案例與視覺矩陣），並檢視 gallery 的圖；若 D3 改變引擎的寬度則加 `pnpm check`。在「好了」交接後，於新的簽章 bundle 上進行桌面回合：`pnpm acceptance:studio` 與上述 CPU 案例，並在橫式與直式螢幕上以截圖觀察。Windows 只靠 CI。

順序、決定點、桌面交接與結案依[計畫索引](README.zh-TW.md)。開始執行時檢查目前的程式樹與 092 的結案紀錄。
