### 共通要求

1. **保留已驗證邊界。** Electron／React、媒體處理不進 main／sandbox renderer、每次 capture 故障隔離、直接 MP4 預設與既有 Metal／D3D11 shader 路徑都保留，除非量測支持局部替換。080 已證共享 texture 沒有 CPU 收益；081 已做 10／5 fps。實作前讀[設計決策](../docs/zh-TW/system-design/decisions.md)；條件未改、沒有新可量問題不重開被否決的傳輸工作。
2. **收益量測、功能成本設限。** 083 固定負載／指標。效能優化過改善／不退步門檻；robustness 用有界資源與故障復原證明。編輯可增加成本，須明訂 CPU／memory／I/O 預算及 opt-in admission，不宣稱全面變快。計畫無法保證未來收益；gate 失敗刪實驗或停在具體範圍決定，不暗降畫質或放寬錄影預算。
3. **ownership 小而明確。** 優先沿用模組、validator、timer、supervision、runner。queue、cache、GPU resource、檔案、callback 都有 owner、容量與 session-end cleanup。先定義取消、generation／revision、防未來版本與 failure outcome。沒有實證需求不造通用 framework、schema 相依、plugin、第二套動畫或永久平行 backend。採相依需記平台、license／notice 及 rollback 成本。
4. **依行為選驗證。** 依[測試政策](../docs/zh-TW/testing.md)選一次驗一次，分報通過、排除、必需但未驗證。pure module 先 focused；capture／protocol／encoding／檔案生命週期需 `pnpm check` 與新簽章錄影／媒體／播放，依受影響邊界加 CPU、相關 matrix（改 drift 要 long）、lifecycle、UI、package。最終 UI 依 regression 規則。合成媒體可驗 render 語義，UI 測試不得固定設計值／pixel baseline，須用 production UI。新 runner 參數實作並記錄前不可當現有命令。
5. **桌面與證據。** 每輪須明確「好了」交接並用[原生驗收 skill](../.agents/skills/native-acceptance/SKILL.md)；需要桌面回合的實作在第一個 edit 前背景啟動 `caffeinate -d -i -t 5400`，最終清理後停止。序列化 `out/`／`dist/` consumer，桌面／音訊一個 owner。即使失敗也恢復設定、關測試 UI、正常退出並確認程序消失。lock／干擾與自動／原生觀察／人工證據分列。Windows CI 不等於硬體 capture／texture／camera；已結案的 077（[紀錄](../docs/zh-TW/verification/history-2026-10.md#plan-077-結案--2026-10-22)）列出仍未觀察的 hands-on 案例。
6. **耐久結案。** 同步 system-design／翻譯、verification／證據限制及雙語索引。決策／契約留下、後續連結轉指耐久紀錄後才移除已完成計畫對。原型被拒須保留結果、明確暫緩或重訂後續範圍，不能宣稱功能已完成。本次不含 commit、PR、release、publish。
