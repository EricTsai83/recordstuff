# 037 — Measured, bounded overlap of recording finalization

[English](037-overlapping-recording-finalization.md) | [繁體中文](037-overlapping-recording-finalization.zh-TW.md)

Status: planned, not implemented. Created: 2026-09-25. After 025, 026, 029, 030, [036](036-async-failure-history.md) and [038](038-recording-health-guards.md); default queue after 034, before final [035](035-guided-native-acceptance.md). Those plans supply terminal ownership, empty-file validation, stable event identity, media evidence, nonblocking history/exit coordination and the writer backlog bound.

## Value and measurement gate

Target: record several separate takes with less waiting between them. Allow capture B while completed capture A is publishing its stable media file, where measured benefit justifies the complexity. Async history saving is unrelated; this plan changes media lifecycle admission. RecordStuff writes media incrementally and does not necessarily have Cap's expensive fragment-remux stage, so Cap's benefit is not evidence of ours.

- [ ] Measure stop-to-next-start-admitted time and its phases: final host handoff, queued writes, flush/close, exclusive final publication/copy and UI response. Use representative short/long recordings on local and isolated external storage; record file size, hardware, timings and media integrity. Do not fill the system disk. Synthetic delay proves ownership only, not user-visible performance benefit.
- [ ] Initial go criterion: a repeatable representative case has p95 stop-to-ready above 1 second, and at least 0.5 seconds belongs to work safely separable after capture/drain/flush/close. Record sample count and distribution; tune thresholds only with written evidence. If no meaningful separable wait exists, document a no-go recommendation and defer overlap rather than weaken safety or implement complexity to satisfy a plan. Do not silently mark an unimplemented feature complete; record the scheduling/completion decision with the maintainer.

This is a source-level reference, not native acceptance or a claim about every Cap mode/platform. Adopt separate ownership and outcome tracking; do not add remuxing, cloud uploads or simultaneous capture sessions.

## Implementation contract after a go decision

- [ ] Extend 025's operation registry: active capture, stopped sealed file awaiting publication, and terminal result have distinct per-attempt ownership. Release A's capture resources only after final data handoff is complete, all writes are drained, and its temporary file is flushed and closed. Only then may B start while A's publication continues. A retains exclusive naming/path ownership; late A events cannot stop B, reuse B's writer or delete an advertised partial. Each attempt keeps its own 038 sentinel until its own terminal outcome. Preserve 024/026 byte and empty-file guarantees.
- [ ] Bound overlap to one active capture plus at most one older media finalization, with one publication task at a time (a serialized promise chain in main, not a thread). If A still finalizes when B stops, seal B safely and block capture C until a slot is free; never discard B, start an unbounded queue or run two publication copies. Include every sealed/queued file in quit ownership. If a safe bounded split cannot be made, retain existing stopping admission.
- [ ] Treat slow/full/offline storage as backpressure, not a reason to record indefinitely into RAM. Do not overlap unflushed write backlog. Measure contention between A's publication and B's live writes; define and test a conservative admission rule from 038's writer backlog counter and disk headroom guard plus measured write latency before enabling overlap on slow storage. Do not add a second backlog measure. When unsafe, visibly wait for pending saves. Async scheduling cannot increase device throughput; no automatic quality downgrade or dropped media to hide overload.
- [ ] Tray remains one icon: B's REC wins, while menu/status separately names A as saving; idle with only finalization must not imply completion. Display queued/sealed work and why a next start is disabled. Completion/failure belongs to its original recording and appears in failure history if needed; acknowledgement/reveal cannot cross IDs. Never announce A saved until publication succeeds or expose its incomplete destination.
- [ ] Preserve the documented saved-notification suppression while another recording is active, with deterministic per-attempt cancellation and no stale replay. Do not invent a success-history library. If notification policy must change, document and test it explicitly. Output/quality selections are snapshotted per attempt; changing B's settings cannot redirect A. Permission recovery/relaunch/quit consult every owned media operation plus 036 metadata; no destructive force-exit path while media remains pending.
- [ ] Add bilingual saving/waiting/error feedback and update recording/desktop architecture. Use [Codex implementation / Opus 5.5 review](../.agents/skills/codex-implement-with-opus-5-5-review/SKILL.md), reusing 025's coordinator rather than a second lifecycle controller.
