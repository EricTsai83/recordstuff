# 101 — 和麥克風、相機並列的「系統聲音」開關

[English](101-system-audio-switch.md) | [繁體中文](101-system-audio-switch.zh-TW.md)

狀態：已規劃，尚未開始；D1–D6 為提案，需維護者在步驟 1 之前回答。建立：2026-10-29，維護者的要求，起因是「每次錄影時怎麼快速選擇要錄哪些東西」。硬性依賴：無未完成項目。建立在已結案的 074（麥克風開關與 Tray 的輸入項目）、075（相機開關、單次錄影靜音與音量推桿）、087 與 098（可編輯錄影與其音軌）以及 097（Tray 中輸入的名稱與問題）之上。依[計畫索引](README.zh-TW.md)的順序執行。本任務只撰寫計畫，以下內容皆尚未實作或驗證。

## 目前的問題

錄影一定會擷取系統聲音。錄影前能選擇的項目與位置：

| 選擇 | Tray（錄影時包含） | 錄影工作室 | 錄影設定 |
| --- | --- | --- | --- |
| 麥克風開或關 | ✓ | ✓ | ✓ |
| 相機開或關 | ✓（有相機時） | ✓ | ✓ |
| 系統聲音開或關 | — | 只在 session 進行中：「不錄」，只影響那一次 | — |

所以「螢幕加系統聲音」、「兩種聲音都錄」、「加上相機」都只要在 Tray 勾一下，但**只錄麥克風**（講解操作時不要錄到通知聲、音樂或視訊會議的聲音）沒有錄影前的選項。現有的繞法都不好：把系統聲音音量調到 0%，這是會一直保留的設定，不調回來之後每次都沒聲音；或在 session 開始後於錄影工作室選「不錄」，但從 Tray 或快捷鍵開始的錄影來不及選。

目標：一個「系統聲音」開關，凡是有麥克風、相機開關的地方都有它，讓三個輸入的任意組合都用同一種方式在錄影前選好。

## 引擎已經做到的

- 引擎在兩個平台都有 `SystemAudio::Off`（[core](../native/capture/src/core/mod.rs)）：macOS 不建立音訊篩選，core 少一個輸入（[session.rs](../native/capture/src/mac/session.rs)）；Windows 不開啟 process loopback（[win/session.rs](../native/capture/src/win/session.rs)）。macOS 的 live test 有 `microphone-only` 案例。
- 完全沒有聲音輸入的錄影會有一條和影片等長的靜音音軌（core 測試 `a_recording_without_any_sound_gets_a_silent_track_as_long_as_its_video`），播放器和剪輯畫面仍看得到音軌。
- 可編輯錄影的描述會列出它的聲音（`system`、`microphone`、`silent`；[editable.ts](../src/shared/editable.ts)），所以沒有系統音軌的檔案已經能被描述。
- 目前 main 不會要求 `off`，只有開發用開關 `RECORDSTUFF_CAPTURE_AUDIO=off` 會（[native-host-process.ts](../src/main/recording/native-host-process.ts)）。

因此工作主要在 main、設定與介面；引擎路徑需要確認，不需要新建。

## 業界做法

Loom、CleanShot X、Cap 與 Camtasia 都讓使用者在錄影前，於開始錄影的地方分別勾選是否錄系統聲音和麥克風；OBS 則是用場景裡的來源。沒有一個把這個選擇藏在音量裡。這是 agent 對這些產品的認識，2026-10-29 沒有再對照它們目前的文件；若設計依賴某個細節，步驟 0 會補上來源。這和 Tray 已列出麥克風與相機的「錄影時包含」一致。

## 設計（提案）

- **一個開關 `systemAudio`，預設開啟**，以布林值存在設定中。沒有這個欄位的檔案讀成開啟、不警告，所以既有使用者錄影結果不變；設定版本不變（和 099 新增欄位的做法相同）。
- **凡是有麥克風的地方都有系統聲音，並排在第一個**：Tray 的「錄影時包含」（系統聲音、麥克風、相機）、錄影工作室的輸入，以及錄影設定。倒數或錄影中鎖定，和麥克風相同。
- **關閉就是不擷取**，不是擷取後靜音：`start` 帶 `systemAudio: false`，擷取程序向引擎要求 `SystemAudio::Off`。不涉及權限提示：系統聲音除了螢幕錄影權限外不需要其他權限。
- **錄影工作室跟著它。** 開關關閉時，session 開始前和進行中都不顯示系統聲音那一列與音量推桿，和麥克風關閉時不顯示麥克風列相同；開關改變時，已準備的即時預覽會重新準備，和麥克風相同。「不錄」仍是對有擷取的輸入、只影響那一次錄影的選擇。
- **沒有系統聲音的可編輯錄影**只有麥克風的音軌，兩者都關時是一條靜音音軌；剪輯畫面只顯示檔案裡有的輸入。

## 不採用的做法

- **切換輸入的全域快捷鍵。** 全域快捷鍵能用的組合很少、容易和其他 App 衝突，而且盲按看不到結果：錄完才發現相機沒開。OBS 的場景快捷鍵可行，是因為它的預覽一直看得到；RecordStuff 錄影前除了 Tray 選單沒有可見的狀態。若使用者要求，再考慮做成預設不綁定、可自行指定的快捷鍵。
- **錄影模式**（「螢幕加相機」、「只有螢幕」⋯⋯）。三個獨立開關本身就是選擇；再加一層模式會和開關重複，還要規定兩者不一致時以誰為準。
- **用系統聲音 0% 代替不錄。** 那是持續的設定，不是每次錄影的選擇，而且聲音仍被擷取。

## 決策（agent 於 2026-10-29 提案，待維護者回答）

- **D1 — 位置：** Tray 的「錄影時包含」、錄影工作室與錄影設定，系統聲音排第一。替代方案：只放 Tray 與錄影工作室。
- **D2 — 預設開啟**，既有使用者也一樣，在有人關掉之前什麼都不變。
- **D3 — 錄影中鎖定**，和麥克風相同；錄影工作室的「不錄」仍處理進行中的錄影。
- **D4 — 允許兩種聲音都不錄**，不顯示警告：檔案保留一條靜音音軌。替代方案：在「錄影時包含」下方加一行說明這次錄影沒有聲音。
- **D5 — Windows 也做**，和所有 Windows 變更一樣只由 CI 檢查。
- **D6 — 不新增快捷鍵，也不做模式**（見上方不採用的做法）。

## 步驟

0. **先確認引擎路徑**，再動介面：在 macOS 以 `RECORDSTUFF_CAPTURE_AUDIO=off` 錄一般與可編輯錄影，各有、無麥克風；用 `ffprobe` 檢查音軌，檢查剪輯畫面的列與可編輯錄影的匯出，以及即時預覽。任何路徑失敗就停下回報。
1. **設定與協定：** `systemAudio` 欄位與 `setSystemAudio` 動作（儲存、錄影中鎖定、不支援時忽略）；`NativeStart.systemAudio`；擷取程序把它對應成 `off`，開發用開關仍優先。
2. **各介面：** Tray 項目與其問題列規則、錄影設定的一列、錄影工作室的輸入（列、推桿、即時預覽的輸入），英文與繁體中文字串、圖示。
3. **可編輯錄影與剪輯畫面**，依步驟 0 的發現處理。
4. **文件：** README（兩種語言）、網站的設定表、[錄影](../docs/zh-TW/system-design/recording.md#音訊)、[桌面](../docs/zh-TW/system-design/desktop.md)與[決策](../docs/zh-TW/system-design/decisions.md)，兩種語言。
5. **桌面測試**，在維護者回覆「好了」後進行，只錄案例需要的東西（[測試指南](../docs/zh-TW/testing.md#環境與共用機器)）：Tray 的開關與鎖定；系統聲音關、麥克風開（喇叭播放一個音，量測一般錄影的音軌中沒有它、人聲仍在）；兩者都關（和影片等長的靜音音軌）；沒有系統音軌的可編輯錄影在剪輯畫面打開並匯出。
6. **結案**，依計畫索引。
