# 017 螢幕擷取停止後的儲存通知時序

[English](017-saved-notification-timing.md) | [繁體中文](017-saved-notification-timing.zh-TW.md)

狀態：已規劃；系統紀錄支持問題診斷，尚未實作修復。更新：2026-09-20。

## 問題與證據

部分儲存通知雖被 macOS 接受，卻沒有出現橫幅。2026-09-20 的 NotificationCenter 紀錄對 `com.ericts.record` 明確回報 `resolutionReason: display shared` 與 `muted by DND suppression: silence`。其中 03:29:24 的對應案例被收進通知歷史，且 `canDisplayWhileCenterIsClosed: false`，因此測試沒有可見通知可點擊。Electron 的 `show` 事件本身不能證明橫幅出現。

本機診斷產物位於 `docs/verification/measurements/2026-09-20-notification-diagnostics/`，擷取的系統紀錄為 `/tmp/recordstuff-notification-system.log`。這些是本機證據，不是儲存庫的永久依賴；實作時應將相關且已過濾私人資訊的摘錄及案例對照保存在驗證紀錄。沒有對應證據前，不把所有缺少通知都歸為同一原因。使用者操作桌面干擾了另一筆 Chrome 前景結果，不能用來解釋系統抑制，也不能據此解決 [014](014-finder-notification-focus.zh-TW.md) 較早的點擊未送達失敗。

目前 capture host 已先停止媒體 tracks，再送出 `stopped`；主程序接著完成檔案寫入並發出 `saved`。待驗證的假設是：擷取資源釋放後，macOS 的通知抑制狀態仍需非同步更新。目前沒有證據證明程式漏掉停止 tracks。

## 目標與範圍

在一般允許橫幅的通知設定下，錄影完成後應於擷取結束後出現一次可點擊的儲存通知，使用者點擊前不啟動 Finder。檔案保存與回到 idle 不依賴通知呈現。尊重使用者刻意設定的專注模式與螢幕分享通知抑制，不修改系統設定或繞過限制。

本計畫涵蓋通知時序與驗證所需的最少診斷；Finder 置前仍由 014 處理。不建立通知服務、持久佇列、私有 macOS API、額外產品權限或隱含的雙語測試矩陣。實作本計畫不代表授權提交、發布或推送 tag。

## 工作順序

1. **建立時序證據。** 對照成功與缺少橫幅案例的 tracks 釋放、host `stopped`、檔案完成、通知請求、系統螢幕分享狀態、抑制決策與 Accessibility 可見狀態。只補調查所缺的時間戳，記錄 macOS／Electron 版本與相關通知設定；無法對應的案例保留未解狀態。
2. **選擇最小且受支援的修正。** 查核是否有可確認就緒的生命週期／API 訊號；不可假定 JS tracks 停止回覆代表 OS 已就緒。有證據證明順序錯誤才修正順序。若無適合訊號，評估只對 macOS 儲存通知加入一次有上限的延遲，以實測時序與前後對照決定，記錄選定時間及限制，不宣稱固定延遲可保證送達。不加入重試迴圈、重複通知、不延遲寫檔／idle，也不靠延長橫幅搜尋掩蓋抑制問題。明確定義開始下一次錄影與退出 App 時待送通知的處理，清理必須有界，避免舊 timer 在新錄影中送通知。
3. **維持精簡且有意義的診斷。** 分開記錄通知請求、Electron show callback、看見橫幅、click callback 與 Finder 結果。沿用有界的 Accessibility 快照；失敗時若可取得系統紀錄，只保留相關證據，不把讀取系統紀錄變成產品需求。未知原因維持未知；即使腳本達到覆蓋門檻並回傳成功，缺少橫幅仍須明列於結果。
4. **驗證選定行為。** 針對實際排程／順序修改補精準測試，涵蓋只送一次、退出／新錄影處理，以及通知失敗不影響檔案。執行 `pnpm check`。依原生驗收 skill，以 `pnpm start:app` 建置簽章版；退出或重建前先確認沒有使用者的錄影。
5. **原生驗收並保存結果。** 暫停桌面操作，在本機簽章版連續執行兩輪 `pnpm acceptance:notification -- --install --full`（每輪 15 個英文案例：Finder 關閉、背景、最小化），設定維持與重現問題時一致。檢查錄影停止、保存與播放，記錄實際驗證到的畫面／音訊行為。在通知待送期間測一次中斷，確認有界退出、沒有遺留錄影，並還原測試建立的視窗、設定及 App 安裝。保留耗時、判定與清理證據，不自動重跑失敗直到變綠。另明確測試新錄影重疊情境；語言驗證獨立處理，只有通知文字／比對方式改動時才需要擴充。

## 完成條件

- 有可對照的修正前後證據，記錄實作選擇及 OS 限制；不以 `shown` 單獨判定通知可見。
- 兩輪完整測試各 15 個橫幅都可見、可點擊，選取正確檔案且 Finder 在前景，沒有重複或未解缺漏。只有 exit code 為零但仍有 skipped／not-run 不算完成；外部操作干擾須另列，並在受控情境重測。
- 保存正常、背景完成不搶焦點，重疊／退出行為已驗證，中斷及清理在現有文件的上限內完成。
- 若仍被抑制，保留本計畫、證據及未解結果，不宣稱修好。使用者刻意設定的 OS 抑制記錄為限制，不繞過。
- 同步雙語桌面設計、驗證紀錄；指令或診斷改動時同步工具文件。依[計畫完成規則](README.zh-TW.md#完成計畫)保存永久結論，再移除本計畫及翻譯。公開發布仍屬 014 的獨立工作，需使用者明確指示。
