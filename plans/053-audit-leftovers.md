## Purpose and boundary

The third audit on 2026-09-29, run on `09bb4c3`, fixed 20 recording, desktop, settings, tooling and documentation defects in `ba8b651`…`4740520` on main. It also found the six items below and left them out of that round, because each needs evidence the round could not produce (a native keyboard check, a measurement baseline decision, a GitHub run, a second-launch check or notification delivery) or changes a log contract. Every item was confirmed by reading the code at `4740520`; none was reproduced.

- **Keyboard focus drops when an action button runs.** [settings.ts](../src/renderer/settings.ts) disables every choice of a group while it saves (`setDisabled(el, !group.enabled || !choice.enabled, Boolean(saving))`, line 202), including the button just activated, and [settings-model.ts](../src/main/settings-model.ts) keeps Check for updates… disabled for the whole check (`enabled: state.kind !== "checking"`, line 239). `choose()` restores focus only for `-retry` and `-recovery` controls (line 793, `a69ddff`). So activating Check for updates…, Retry shortcut registration or Open notification settings… from the keyboard leaves focus on the page, and the next Tab starts again at the tab strip. The repository's own premise ([desktop](../docs/system-design/desktop.md), "a disabled element cannot hold keyboard focus") says this happens in Chromium; happy-dom does not model it, so it is unverified.
- **Frame cadence reports its own percentiles.** [frame-cadence.mts](../scripts/lib/frame-cadence.mts) computes p05 and p95 with a private linear-interpolation `quantile` (line 32), while [stats.mts](../scripts/lib/stats.mts) says every measurement tool shares nearest-rank percentiles so that "p95" means the same thing in every report. `diagnose:cadence` p95 therefore differs from `measure:cpu` and `measure:finalization` p95; the median agrees. Switching changes reported numbers, so it needs a decision about comparability with earlier cadence reports.
- **A website-only pull request runs no CI.** [check.yml](../.github/workflows/check.yml) ignores `website/**` on push and pull request, and [website.yml](../.github/workflows/website.yml) has no `pull_request` trigger. Website tests, `astro check` and the build first run inside Vercel's production build after merging to main; the same holds for the website tests of `scripts/lib/release-manifest*.mts`. [CONTRIBUTING.md](../CONTRIBUTING.md) says every pull request runs `pnpm check`, which is true but reads as full coverage.
- **A second launch shows nothing.** [index.ts](../src/main/index.ts) has no `second-instance` handler, and the macOS `activate` listener in [permission.ts](../src/main/permission.ts) (line 140) only polls permission. Opening the app again while it runs, as a user whose menu bar icon is hidden behind the notch or a crowded menu bar would, gives no visible response; the Settings shortcut is the only other way in.
- **Capture-start notifications may be muted.** The resolution-cap warning and the frame-rate downgrade are shown on `captureStarted` ([index.ts](../src/main/index.ts), lines 617 and 623), while the display is being shared. The [saved-notification timing record](../docs/verification/history-2026-09.md#saved-notification-timing--2026-09-20) shows macOS deciding `resolutionReason: display shared`, `muted by DND suppression` during capture, which is why saved notifications wait until capture ends. The resolution-cap warning also persists in Settings; the frame-rate downgrade has no surface other than the log. [tray.ts](../src/main/tray.ts) `notifyCaptureWarning` (line 260) also spells the title `"RecordStuff"` instead of using `APP_NAME`.
- **The finalize timing line leaves out the sentinel checkpoint.** In [recorder.ts](../src/main/recorder.ts) `finalize`, `sentinels.complete` (line 938) reads the sentinel and rewrites it atomically with fsync after `writer.finish()` and before `saved`, but `logFinalizeTiming` has no field for it, so a slow `userData` volume lengthens Saving… without a trace and [finalization-timing.mts](../scripts/lib/finalization-timing.mts) (`TIMING`, line 37) parses a breakdown that cannot add up to stop-to-ready. The log line is a script contract, so the recorder and the parser change together.

Out of scope: the runner items of [052](052-runner-process-safety.md); the leftovers the maintainer did not queue after the second audit (`compareVersions` pre-release ordering, the duplicate `PermissionStatus` type, an `isCaptureControl` helper, website font preload and colour tokens); new features.

## Implementation contract

- [ ] **Focus stays on a running action.** A busy action button stays focusable: it keeps `aria-disabled="true"` and the `saving-disabled` look and ignores activation while its request runs or a check is in progress, as the failure-row actions already do, and a truly unavailable choice is still `disabled`. After the request settles, focus is where the user left it. Apply the same rule to every action group, not only Updates.
- [ ] **One percentile definition, or a stated exception.** Either `cadenceStats` uses `percentileSorted` and `medianSorted` from `stats.mts`, and the tooling docs note the date from which cadence p05/p95 are nearest-rank, or `stats.mts` and tooling state that cadence percentiles interpolate and why. Pick one with the maintainer before changing numbers.
- [ ] **Website pull requests are checked.** A path-filtered job (in check.yml or website.yml) runs on pull requests touching `website/**`, `scripts/lib/release-manifest*.mts`, `src/shared/version.ts` or the workflow: install with the frozen lockfile, website tests, `astro check`, the offline build and the offline link check. It needs no secrets. CONTRIBUTING (both languages) says which workflow covers the website.
- [ ] **A second launch opens Settings.** Handle `second-instance` (and, on macOS, a reopen from Finder or the Dock through `activate`) by opening Settings through `handleAction("openSettings")`, so the same quit gate and window reuse apply. A notification click or permission poll must not open Settings; confirm which events macOS delivers before choosing the listener.
- [ ] **Capture-start notices reach the user.** Hold the frame-rate downgrade and the resolution-cap notification until capture ends, as `SavedNotification` does, or show the downgrade in Settings beside the existing capture warning; do not show a notification while the display is shared. `notifyCaptureWarning` uses `APP_NAME`.
- [ ] **The checkpoint is timed.** `finalize` measures `sentinels.complete` and the timing line gains `checkpoint N ms`; `finalization-timing.mts` parses it, still accepts lines without it, and its tests cover both. Decide whether a session whose sentinel write already failed skips `complete` (it then fails with ENOENT and logs "completion checkpoint failed" on every save); if it does, the flag must reflect the latest write, not any earlier attempt.
- [ ] **Documentation.** In both languages: desktop (focus rule, second launch, capture-start notices), tooling (cadence percentiles, finalize timing field) and CONTRIBUTING (website CI).

- [ ] `pnpm check`; `pnpm site:check` if the website workflow or its inputs change.

Each desktop round follows the [readiness handoff](../docs/testing.md#confirm-desktop-handoff-before-testing).
