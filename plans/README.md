# Remaining Work

[English](README.md) | [繁體中文](README.zh-TW.md)

Updated: 2026-10-27. This index lists unfinished plans, their order and their hard dependencies. A completed plan is removed; its closure record stays in [verification](../docs/verification/README.md) and its durable conclusions in [system design](../docs/system-design/README.md). Adopted decisions that bound the queue, such as no updater, no uninstaller on macOS, no native rewrite for size alone, and hardware verification on macOS only while the Windows x64 installer is published checked by CI alone, are recorded in [design decisions](../docs/system-design/decisions.md) rather than repeated here. The Windows tray acceptance that the closed 034 carried into 035's N17 stays open: without a Windows machine, the closed 064 left it open, and every release record lists it as untested. Releases follow [release automation](../docs/system-design/releases.md): the tag is the version and CI records each release back on main.

### Shared requirements

1. **Preserve proven boundaries.** Keep Electron/React, native media processing outside main and the sandboxed renderer, per-attempt capture fault isolation, current direct-MP4 defaults, and the current Metal/D3D11 shader path unless measurements justify a scoped replacement. Closed 080 showed no shared-texture CPU gain; 081 already paces Studio at 10/5 fps. Read [design decisions](../docs/system-design/decisions.md) before implementation; do not reopen rejected transport work without changed conditions and a new measurable question.
2. **Measure benefit; bound feature cost.** 083 freezes workloads and metrics. Performance optimizations must clear its improvement/no-regression gate; robustness changes must show bounded resources and fault recovery. New editing features can cost more: they need explicit CPU/memory/I/O budgets and opt-in admission, not a claim of universal speedup. No architecture can guarantee future gains from a plan alone. Gate failure removes the experiment or pauses for a concrete scope decision; it does not silently lower quality or loosen recording budgets.
3. **Keep ownership small.** Prefer existing modules, protocol validators, timers, supervision and runner infrastructure. Every queue, cache, GPU resource, file and callback has an owner, finite capacity and end-of-session cleanup. Define cancellation, generation/revision checks, unsupported-version behavior and failure outcomes before implementation. Avoid a general framework, schema dependency, plugin system, second animation model or permanent parallel backend without demonstrated need. Document each adopted dependency, supported platforms, license/notice obligations and rollback cost.
4. **Select verification by behavior.** Use the [testing policy](../docs/testing.md), select once/validate once, and report passed, excluded and required-but-unverified cases separately. New pure modules begin with focused tests. Changed capture/protocol/encoding/file lifecycle needs `pnpm check` and fresh signed recording/media/playback; add CPU, relevant matrix (long when drift changes), lifecycle, UI or package checks only for affected boundaries. Final UI integration follows the policy's regression rule. Synthetic media tests may check rendered media semantics; UI tests must not encode design values/pixel baselines and must use production UI. Proposed new runner flags are not runnable commands until implemented and documented.
5. **Desktop and evidence.** Each desktop round needs the explicit “好了” handoff and [native acceptance skill](../.agents/skills/native-acceptance/SKILL.md); before its first implementation edit start background `caffeinate -d -i -t 5400`, stop it after final cleanup. Serialize `out/`/`dist/` consumers and grant one desktop/audio owner. Restore settings, close owned UI, quit normally and confirm process exit even on failure. Keep lock/interference and automated/native/manual evidence distinct. Windows CI is not hardware capture/texture/camera evidence; the closed 077 ([record](../docs/verification/history-2026-10.md#plan-077-closure--2026-10-22)) lists the hands-on cases still unobserved.
6. **Close durably.** Update system-design documents and translations, verification results and evidence limits, this index and its translation. Remove completed plan pairs only after their decisions/contracts are retained and successor links are repointed to durable records. If a prototype is rejected, preserve that result and explicitly defer/re-scope dependents. Do not close a feature as implemented on a prototype rejection. No commit, PR, release or publish is included in this request.

Each is written in Traditional Chinese with the [`to-html` skill](../.agents/skills/to-html/SKILL.md), checked with its highlight and validate scripts and added to the learning index. An article is written once every plan it draws from has closed, so it teaches what was built and measured, not what was planned; the plan that closes last writes it as part of its documentation step. At the maintainer's request on 2026-10-16, each article centres on the trade-offs of the architecture and technology choices, not on RecordStuff's design: the conditions a choice depends on, the credible alternatives and what each costs, how other products chose, and the changed conditions that would reverse the choice; RecordStuff's choice is the worked example. All seven are written: four at 076's and 074's documentation, the last three, on screen capture, media permissions and the camera overlay, at 075's closure on 2026-10-18.
